# DEV-001 — Codex 저장소 및 문서 체계 초기화 작업 지시서

- 작업 ID: DEV-001
- 발주: HQ(PM)
- 수행: Development (Codex)
- 상태: **지시서 DRAFT / Owner 배포·실행 승인 대기**
- 우선순위: High
- 작업 유형: 기반 환경 초기화 (게임 기능 구현 아님)

## 1. 배경 및 목적

이 프로젝트는 Windows PC용 2D 픽셀 아트 경영 시뮬레이션입니다. HQ, Planning, Design은 별도 ChatGPT 채팅이며 Development는 Codex 작업 스레드입니다. Git이 승인된 산출물의 단일 공식 원본입니다.

**목표:** 기존 자산을 보존하면서 Git/Godot 프로젝트 상태를 확인하고, 문서·작업 티켓·AI 지침을 수용할 최소 저장소 구조를 준비합니다.

## 2. 작업 전 준수 규칙

1. **먼저 기존 파일과 Git 상태를 조사**하고 결과를 보고하십시오. 기존 저장소가 있다면 중복으로 초기화하지 마십시오.
2. Owner가 제공한 7개 PM-001 정책과 GOV-001 직무 경계를 준수하십시오.
3. 승인된 기획·디자인 명세가 없는 게임 기능, 경제 규칙, UI, 그래픽은 임의로 구현하지 마십시오.
4. 기존 파일·설정·브랜치를 삭제하거나 강제로 덮어쓰지 마십시오.
5. 원격 저장소 생성, 네트워크 푸시, 자동 커밋, main 병합, 릴리스는 **명시적 추가 승인 없이 금지**합니다.
6. 완료되지 않은 테스트를 성공했다고 보고하지 마십시오.

## 3. 작업 입력

Owner가 전달한 다음 파일들을 읽고 역할별 참고 문서로 준비하십시오.

- `governance/HQ_OPERATING_RULES.md`
- `templates/PLANNING_HANDOFF.md`
- `templates/DESIGN_HANDOFF.md`
- `templates/DEVELOPMENT_HANDOFF.md`
- `templates/RFC_AND_DECISION.md`
- `README.md` (패키지 사용 지침)

패키지 문서는 현재 DRAFT입니다. 파일을 저장소에 포함하더라도 승인 상태를 임의로 APPROVED로 바꾸지 마십시오.

## 4. 작업 순서

### A. 현황 조사

- 프로젝트 디렉터리 확인, 기존 `project.godot` 유무, Git 저장소 유무·상태, 현재 브랜치 및 원격 설정 확인.
- 설치된 Godot 실행 파일과 버전 확인(가능한 경우).
- 기존 사용자 작업물이 있다면 덮어쓰지 않고 차이와 충돌 위험부터 보고.

### B. 최소 저장소 구조 준비

기존 구조가 없다면 아래를 기본안으로 삼되, 현재 프로젝트 구조와 충돌하면 변경 제안을 먼저 제출하십시오.

```text
<repository-root>/
  project.godot                 # Godot 프로젝트가 이미 있으면 보존
  AGENTS.md
  README.md
  docs/
    governance/
      HQ_OPERATING_RULES.md
    templates/
      PLANNING_HANDOFF.md
      DESIGN_HANDOFF.md
      DEVELOPMENT_HANDOFF.md
      RFC_AND_DECISION.md
    planning/
    design/
    engineering/
  tasks/
    DEV-001_REPOSITORY_INITIALIZATION.md
  scenes/
  scripts/
  assets/
  tests/
```

- 빈 디렉터리는 반드시 생성할 필요가 없습니다. 필요한 경우 적절한 플레이스홀더를 사용하십시오.
- Git 저장소가 없다면 로컬 Git만 초기화하고 현재 브랜치를 보고하십시오.
- 기본 `.gitignore`에 Godot 생성 캐시(`.godot/`)와 개인/임시 파일, 로컬 빌드 출력 등을 제외하는 규칙을 구성하십시오. 기존 중요한 자료를 무시하거나 삭제하지 마십시오.
- `AGENTS.md`에는 **승인 명세 우선, 담당 범위 준수, 변경 전 현황 조사, 경계 변경은 RFC, 테스트 증거 기록, Owner 승인 없는 push/merge/release 금지** 정도의 최소 지침만 작성하십시오.
- Godot 프로젝트가 없다면 안정 버전 기준으로 게임 로직 없이 초기 프로젝트를 준비하십시오. 사용한 엔진 버전과 설정을 보고하십시오. 설치 불가·버전 불일치 시 임의 업그레이드하지 말고 이슈로 보고하십시오.

### C. 제공 문서 배치

- 위 패키지 문서를 안내된 저장소 경로에 배치하십시오.
- 문서의 버전·상태·승인자 표시를 보존하십시오.
- 불필요한 중복 사본은 만들지 마십시오.
- `README.md`에 부서별 문서 위치, 승인/커밋 절차, 프로젝트 소스는 자동 동기화되지 않는다는 점을 짧게 안내하십시오.

### D. 검증

- 문서 파일이 지정 위치에 존재하는지 확인하십시오.
- Git status에서 변경 파일을 확인하고 의도치 않은 무시/추적 누락이 없는지 검토하십시오.
- Godot가 설치되어 있다면 프로젝트 열기/파싱 검증을 수행하고 사용한 명령 및 결과를 기록하십시오. 실행하지 못한 경우 NOT_RUN으로 기재하십시오.
- **게임 플레이·기능 구현·Windows 빌드는 이번 작업 범위가 아닙니다.**

## 5. 이번 작업 범위에서 제외

- 재고·경제·고객 시스템 구현
- 게임 디자인 또는 아트 콘셉트 확정
- 별도 프레임워크·DB·배포 파이프라인 도입
- Codex 멀티에이전트 상시 실행
- 원격 저장소 생성, 푸시, PR 생성, 자동 커밋
- Owner 최종 승인이 필요한 주요 정책 변경

## 6. 완료 기준 (Acceptance Criteria)

- AC-01: 기존 Git/Godot 상태와 보존 조치가 보고됨.
- AC-02: 문서가 합의된 경로에 DRAFT 상태로 존재함.
- AC-03: Git 무시 규칙과 `AGENTS.md`가 준비됨.
- AC-04: Godot 설치·프로젝트 점검 결과가 PASS/FAIL/NOT_RUN으로 보고됨.
- AC-05: 변경 파일 목록과 Git status가 제출됨.
- AC-06: 원격 푸시·병합·릴리스·자동 커밋이 수행되지 않음.

## 7. 완료 보고 형식

다음 항목을 기재한 `DEV-001_RESULT.md`를 작성하여 Owner와 HQ 검수 대상으로 제출하십시오.

- 수행 환경/확인된 버전
- 기존 저장소 상태와 발견된 리스크
- 생성·수정·보존 파일 목록
- AC-01~AC-06 충족 여부 및 증거
- 테스트 및 검증에 사용한 명령·결과
- 미해결 질문/RFC 필요 사항
- Git status 및 Owner가 검토해야 할 사항

**작업을 끝내더라도 Owner의 커밋·승인 전에는 프로젝트가 공식 적용 완료된 것으로 표시하지 마십시오.**

## 8. Codex에 전달할 실행 지시 문구

> 이 저장소의 DEV-001 작업 지시서를 읽고 범위 내에서만 작업해 주십시오. 먼저 기존 Git 및 Godot 상태를 조사한 뒤, 충돌이 없는 최소 초기화 및 문서 배치를 수행해 주십시오. 변경된 파일, 검증 증거, 미해결 사항을 DEV-001_RESULT.md에 정리해 주시고, 커밋·푸시·병합·릴리스는 실행하지 마십시오.
