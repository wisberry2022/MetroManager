- 공개 등급: OWNER_RESTRICTED 기본. 공개용은 비공개 링크·대화·세션 정보를 제거한 별도 요약
- Handoff ID: HOF-YYYYMMDD-ROLE-OLD-NEW / 역할·담당 범위:
- 현직 작성자·작성 시각: / 후임 인수 확인 시각:

통상 인계는 아래 본문만 작성한다. INF·HQ·Owner의 별도 승인란이나 시험 답안은 필요하지 않다. Owner의 최초 지시가 준비만 허용했는지 실제 업무 전환까지 승인했는지는 반드시 구분한다. 빈칸을 승인으로 간주하지 않는다.

## 2. 역할과 작업별 권한

- R&R·타 부서 경계·금지:
- Owner가 최초 지시에서 승인한 승계 여부: 아래 각 행에 신규 부여/동일 범위 이전/권한 없음 구분.
- 본인 담당 부서의 필수 지침·검사·Owner 병합 규칙은 유지한다.

| 티켓 | 저장소·경로·브랜치 | 허용 동작(Commit/Push/PR 등 각각) | 기존 승인 근거·이전 지시 | 기간·종료 조건·금지 |
|---|---|---|---|---|
| | | | | |

열거한 유효 권한의 이전이 명시되어 있으면 같은 권한을 다시 요청하지 않는다. 인계 문서만으로 권한을 만들지 않는다. main 병합·릴리스는 해당 승인 또는 명시 위임이 있을 때만 가능하다. 후임은 새 ID를 사용하고 전임의 ID나 과거 author를 바꾸지 않는다.

## 4. 후임의 짧은 인수 확인

다음 내용을 자신의 말로 한 번 회신하고 지정 시각부터 허용된 업무를 시작한다. 회신에 대한 별도 합격·승인 응답을 기다리지 않는다.

- 내 신규 ID·역할·전환 효력 / 실제 인수 확인·업무 개시 시각:
- 직접 확인한 최신 main 전체 SHA와 현재 티켓·권한:
- 첫 행동:
- UNKNOWN/NOT_VERIFIED 및 해당 작업에만 필요한 보완:
- 후속 등록 상태·추적 참조:

등록부 미반영을 등록 완료로 주장하지 않는다. 실제 수행하지 않은 시험은 PASS가 아니다. 전임 종료 이후의 복귀는 자동 허용되지 않는다.

## 선택 부록 — 요청된 경우에만 상세 검증

통상 인계에서는 이 부록을 작성·제출하지 않는다. Owner 요청 또는 구체적인 충돌·누락의 보완에 한해 범위·검증자·해제 조건을 먼저 기록하고 관련 항목만 사용한다. 독립 평가의 대상자는 자신을 독립 검증하지 않는다.

| 질문 | 확인할 내용 |
|---|---|
| T1~T5 (CRITICAL) | 역할·결정 경계 / 승인과 초안 / 최신 업무·SHA / 유효 권한 이전 근거 / 첫 행동·차단·복구 |
| T6~T10 (NORMAL) | 미결 결정 / 부서 의존성 / PASS와 NOT_RUN / 경로·브랜치·승인 / 비상 복구 원본 |

전체 T1~T10 시험을 명시 요청한 경우에만 CRITICAL 5/5·NORMAL 4/5 이상 기준으로 판정한다. 증거 부족은 NOT_VERIFIED, 미실행은 NOT_RUN이다. 부분 확인을 전체 시험 합격으로 확대하지 않는다.
