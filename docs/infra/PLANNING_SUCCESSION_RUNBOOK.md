## 1. Owner 지시

Owner가 인계서 작성과 후임 업무 승계를 함께 지시한다. 기존/신규 ID·세대·효력 시각·이어받을 티켓·권한을 확정한다. 준비만 요청한 경우에는 기존 담당이 업무를 유지하며 전환 승인으로 확대하지 않는다. 교체 시점은 Owner가 정하며 컨텍스트 소진 판정이나 ACHC 점수를 필수로 요구하지 않는다.

## 2. 현직의 인계서

[간이 인계 양식](AGENT_HANDOFF_TEMPLATE.md)에 역할·승인 원본·현재 업무·추가 이력을 작성한다. 문서 원문은 Owner 제한 전달하며 공개 PR에 자동 게시하지 않는다.

- 최신 원격 main 전체 SHA·조회 시각과 Planning README·실행 티켓을 확인한다.
- Gate 2 최종 승인과 현재 개정본을 직접 대조한다. 과거 Gate 3 요청 초안·MVP 제외 기능·실제 승인된 후속 티켓을 구분한다.
- 진행 Issue/PR·미결·타 부서 인터페이스·다음 행동·유효한 Git 권한 이전 근거를 남긴다.
- 로컬 변경·접근 불가 자료는 UNKNOWN, 실제 구현·GUI를 실행하지 않았다면 NOT_RUN이다.

의미 경계 예시: B>0의 신규 탑승 제한과 미지급 6개월 신규 사업 계약 제재를 혼동하지 않는다. 후자는 기존 MVP 제외 결정이며 잔여 승객 도착만으로 추가 운영비를 부과하지 않는 CLOSE-01과도 구별한다. 실제 작업에서는 최신 승인 명세를 다시 읽는다.

## 3. 후임 확인과 업무 개시

후임은 인계서·최신 승인 Git·티켓을 직접 읽고 새 ID·역할·현재 업무·첫 행동·미확인 사항을 짧게 회신한다. 지정 시각부터 승인 범위에서 실행하며 INF 시험·HQ 전환 확인·Owner 재승인을 기다리지 않는다. 전임은 종료 시각 이후 해당 업무 신규 쓰기를 중단하고 자료를 보존한다.

권한 이전이 최초 지시에 명시된 티켓은 동일 범위의 Commit/Push/PR 권한을 다시 요청하지 않는다. 미승인 작업·새 범위·main 병합·릴리스는 해당 권한 근거를 별도로 확인한다. 후임은 새 ID를 사용한다.

## 5. 후속 기록과 예외

INF는 등록부 반영·감사 이력을 후속 관리하고 HQ는 담당·의존성을 갱신한다. 등록부 미반영 여부를 업무상 전환과 분리한다. ID 충돌·불명확한 권한·중대한 인계 누락은 영향을 받는 작업만 보류하고 필요한 내용을 확인한다. 상세 시험은 구체적인 요청이 있을 때만 수행한다. 현직 접근 불가 시 공식 Git·Issue·PR에서 복구하고 미기록 내용을 추측하지 않는다.
