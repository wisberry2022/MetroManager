# Planning Agent — 예방적 후임 인계 실행 가이드

- ID: INF-001-PLN-RUNBOOK / v1.0 / 2026-11-01
- 상태: GUIDANCE / 실제 후임 발령·Owner 교체 승인 `NOT_RUN`
- 역할 소유: Planning / 세션 수용 검증: INF / 업무 전환 시점: PM / 최종 결정: Owner

## 1. 언제 시작하는가
기획 규칙의 상당 부분이 Gate 2에서 확정되었고 Gate 3 분석으로 넘어가는 경계는 **사전 인수인계 문서를 준비하기에 좋은 후보 시점**이다. 이는 현직 기획자의 실제 컨텍스트 소진이나 즉시 교체 판정과 별개이다. 준비 단계에서는 현직 세션을 계속 사용한다.

## 2. Owner의 준비 지시 → 현직의 스냅샷
현직 Planning 세션에 다음을 요청한다(현재 권한 범위 내 읽기·문서만).
- 정식 역할·금지 및 가장 최근 유효한 업무별 Git 쓰기 승인.
- 최신 `main` 기준 승인 명세: Gate 1 `PLN-001-A/B v0.3`, Gate 2 `PLN-001-C v0.6`, `PLN-001-D v0.9`, `PLN-001_GATE2_DATA_v1_DRAFT.md`의 **본문 상태 v1.3 OWNER_APPROVED**. 시작 시 원격 최신 상태 재확인.
- Gate 2 최종 승인 원문 `docs/planning/PLN-001_GATE2_FINAL_APPROVAL.md`; 세부 결정·SEM-01~03·CLOSE-01~03·APP-01 및 Idea Library의 MVP 제외 기능.
- 요청 문서 `docs/hq/requests/PM-008-PLN.md`의 `REQUEST_DRAFT`와 정식 PLN 실행 티켓 존재 여부 재확인.
- 현재 미결·타 부서 의존성·다음 안전한 행동·소스 SHA 및 `NOT_RUN`.

**중요 예시:** `B>0`은 신규 **탑승** 제한이지 미지급 6개월 신규 **사업 계약 제재**가 아니다. 해당 제재는 현 MVP 제외로 결정됐다. 잔여 승객 도착만을 이유로 추가 운영비를 부과하지 않는다(CLOSE-01). 과거 논의와 현행 승인 정책을 반드시 분리한다.

## 3. INF 인계 완성도 사전검사
- 승인 명세 4계층(역할·원본·업무·추가 참조)에 누락이 없는가?
- 현직이 확인하지 못한 로컬 변경/세션 전용 결정은 `UNKNOWN`인가?
- 미결 결정·실제 구현 검증 의무를 DONE으로 주장하지 않았는가?
- 문서가 너무 길면 상세 이력은 Git 링크로 축소하고 신규 세션 필독량을 줄인다.
- Owner의 명시적 세대교체 결정 전에는 새 담당에게 쓰기 권한을 부여하지 않는다.

## 4. Owner가 교체를 승인했을 때
1. Owner가 새로운 Planning 채팅을 만들고 **Planning R&R·승인된 역할 범위**를 우선 전달한다.
2. `AGENT_HANDOFF_TEMPLATE.md`에 맞춘 최종 인계 자료(Owner 제한 사본), 최신 Git SHA, 현행 요청/작업 티켓을 제공한다.
3. 후임에게 처음에는 **읽기·수용시험만** 지시하고 과거 전체 대화 기록을 주입하지 않는다.
4. 후임이 Git 공식 원본을 직접 조회하여 T1~T10을 답한다. INF가 근거를 대조한다.
5. 수용 통과 후 PM이 기존 진행 작업/타 부서 의존성과 전환 가능 시점을 확인한다.
6. Owner가 최종 담당 전환과 **새 티켓별 Git 권한**을 승인해야 후임이 실행에 착수한다.
7. 현직 채팅은 감사·참조용으로 보존하고 임의 삭제하지 않는다.

## 5. 후임에게 전달할 첫 메시지 예문(상세 자료는 첨부)
'당신은 MetroManager의 차기 Game Designer(Planning)입니다. 승인된 R&R을 준수하고, 제공된 인계 문서 및 Git 최신 `main`에서 승인 결정·작업 상태를 직접 확인하세요. 지금은 **인수 수용 검증 단계**입니다. 기획 변경 확정, Issue·Commit·Push·PR, 타 부서 업무 수행을 하지 마세요. 먼저 현재 승인 범위, MVP 제외 기능, 미결 문제, 진행 티켓, 첫 안전한 행동을 각 근거 SHA와 함께 보고하세요. 기존 세션의 작업별 권한은 자동 승계되지 않습니다.'

## 6. 실패 대응
중대 질문 오답 또는 현행과 과거 결정 혼동 시 사용 개시 중단 → 인계 자료 교정 → 재시험. 접근 불가 시 승인된 Git 원본으로 복구하며 미기록 내용은 추측으로 확정하지 않는다.
