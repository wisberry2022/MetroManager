## 1. 목표와 계측 한계
오래된 채팅의 컨텍스트 초과를 추측하는 대신, **승인 결정의 정확성·현재 업무의 연속성·권한 및 검증 경계·반복 오류**로 업무 지속 가능성을 판단한다. ChatGPT 웹 채팅/Codex의 실제 남은 컨텍스트 토큰, 내부 압축 상태, 전체 숨은 컨텍스트는 GitHub 이력으로 직접 측정할 수 없다. 메시지 수·PR 수·경과일만으로 과부하를 판정하지 않는다.

증거: (a) Owner 승인 기록과 Git 버전/SHA (b) 현직 자기보고 (c) Issue·PR·티켓 상태 (d) 검증된 오류·교정 이력 (e) 필요한 경우 독립 재진술·후임 수용 시험. 현직 자기평가를 그대로 INF 확정 점수로 채택하지 않는다.

## 2. 직무 분리
| 주체 | 책임 |
|---|---|
| INF | 인계 양식·등록 정합성·예외 복구 관리. 등록 실행은 위임받은 범위에서 수행하며 Owner 직접 등록 시 요청 지원; 통상 교체의 사전 승인자가 아님 |
| 현직 부서 | 근거 있는 업무 스냅샷, 오답/정정 사실, 인계 패키지 작성 |
| 후임 | 최신 승인 원본·인계서 확인, 짧은 인수 확인, 지정 시각부터 허용된 업무 실행 |
| PM | Stage·의존성·진행 PR/티켓의 담당 정보 갱신·충돌 조정; 통상 교체에 별도 전환 승인 불필요 |
| Owner | 최초 지시로 후임·업무·효력 시각·권한 이전 확정. 후속 등록 직접 수행 또는 담당 지정. main 병합·릴리스는 해당 승인 범위 유지 |

부서 전문 경계는 기존 규정 그대로다. INF가 다른 부서의 임시 승인, Git 권한 이전, 업무 완료 판정을 자동 생성하지 않는다.

## 3. 점검 주기 및 트리거
- 최초 도입 4부서 기준선: 각 현직의 보고 수집 → INF 독립 교차 검증.
- 정기: PM의 주간 점검 또는 Stage 시작·종료 시점에 연계한 **경량 확인**. 매번 전체 4개 영역을 재채점할 의무는 없으며 변경·위험이 있으면 정밀 진단.
- 수시: 공식 결정 반복 오인, 허가 없는 변경, 현재 티켓/PR 추적 상실, 동일 완료 업무 반복, 중요한 보고의 검증 범위 과장, 장기 차단, Owner/PM/현직 요청.
- 긴급: 승인 없는 고위험 쓰기, 자료 파괴 가능성 또는 세션 접근 불가 발생 → 관련 쓰기 중단 권고, Git 최신 승인 원본 재확인, Owner 보고.

이 정책만으로 예약 검사·자동 모니터링·다른 채팅으로 직접 메시지 발송이 시작되지는 않는다.

## 4. ACHC 평가
ACHC는 요청된 건강 진단에 사용한다. 통상적인 예방적 교체에서는 자기보고·채점·독립 평가를 필수로 요구하지 않는다. 생략한 평가는 NOT_ASSESSED이며 낮은 건강 상태나 평가 PASS를 뜻하지 않는다.

4영역 각각 0~4점. 0=중대 불일치, 1=반복 불일치, 2=일부 누락, 3=대체로 근거 일치, 4=충분한 근거와 재현 확인. 확인할 수 없는 항목은 **N/A**로 기록하고 0점 처리하지 않는다.

| 영역 | 가중치 | 검증 질문 |
|---|---:|---|
| A 공식 맥락 정확성 | 35 | 현재 승인 상태·버전·결정·제외 범위를 정확히 재구성하는가 |
| B 작업 연속성 | 30 | 티켓/Issue/PR·미결·차단·다음 작업을 근거로 추적하는가 |
| C 일관성 및 권한 | 25 | R&R·Owner 승인·미검증/실행 결과를 구분하는가 |
| D 부담 위험(역점수) | 10 | 지속적인 맥락 누락·불필요한 반복 오류의 검증 증거가 없는가 |

D의 **4점은 낮은 부담 위험**, 0점은 높은 부담 위험. 단순한 최신 원본 재열람이나 정상적인 정책 수정에 따른 재검토는 오류가 아니다.

점수 = `100 × Σ((영역점수 / 4) × 가중치) / Σ(평가 가능 영역 가중치)`.
A·B·C 중 하나라도 N/A면 총점 `NOT_ASSESSED`. D만 N/A일 때는 A/B/C의 가중치 합 90으로 정규화하고 평가 제외를 표시한다. 숫자는 **관찰 근거의 적합성 지표**이지 실제 남은 토큰 비율이 아니다.

시범 참고 구간(절대 자동 판정 아님): 85~100=유지, 70~85 미만=주의, 50~70 미만=인계 준비 검토, 0~50 미만=교체 권고 검토. 낮은 점수라도 즉시 자동 교체하지 않고, 높은 점수라도 마일스톤 경계에서 예방적 인계 준비를 할 수 있다. 점수 구간과 최종 권고가 다르면 사유를 명시한다.

**점수보다 우선하는 중대 검토 조건:** DRAFT를 승인으로 오인, 필수 승인 없이 main/merge/릴리스 진행, 실행하지 않은 게임 테스트를 PASS로 선언, 타 부서 결정 무단 확정, 중요한 자료 파괴 위험. 사고 사실·영향·재발 여부를 확인하고 Owner 판단을 요청하며, 단일 오류의 원인을 무조건 컨텍스트 소진으로 단정하지 않는다.

## 5. 요청된 진단 절차
`REQUESTED → SELF_REPORTED → CROSS_CHECKED → INF_RECOMMENDATION → OWNER_DECISION`.
1. Owner/PM/INF가 대상 세션, 기준 시각, 이유와 범위를 정한다.
2. 현직은 `AGENT_HEALTH_REPORT_TEMPLATE.md`에 따라 자기보고. 측정 불가를 임의 점수로 채우지 않는다.
3. INF는 최신 승인 원본과 Issue/PR/티켓을 별도로 조회해 대조한다. 과거 시점에 맞았던 기록의 노후화와 실제 기억 착오를 구별한다.
4. INF는 `AGENT_ASSESSMENT_TEMPLATE.md`에 A/B/C/D, 관찰 사실·한계·최종 권고를 작성한다. 보안상 상세 평가문은 Owner 제한 전달.
5. PM은 필요한 업무 영향을 검토하고 Owner가 교체 여부를 결정한다. 진단 자체는 기존 권한을 정지하거나 새 세션을 생성하지 않으며, 아래 통상 인계의 필수 선행 단계가 아니다. INF 자체의 독립 진단이 필요하면 Owner 지정 검증자가 수행한다.

## 6. 통상 인계 — 최초 지시와 인수 확인

Owner 교체 지시 → 현직 인계서 작성·전달 → 후임 원본 확인·업무 시작.

1. Owner가 컨텍스트 관리에 필요한 시점에 원격 [인계 양식](AGENT_HANDOFF_TEMPLATE.md)의 작성을 지시한다. 최초 지시에 기존/신규 ID·세대·역할, 이전 종료/후임 시작 효력 시각, 승계 업무와 권한을 포함한다. 인계 준비만 지시한 경우는 업무 전환 승인과 구분한다.
2. 현직은 역할·승인 원본·현재 업무·필요한 추가 이력만 정리한다. 원본 링크·전체 SHA·조회 시각을 남기고 상세 대화 전체를 복제하지 않는다. Owner 제한 인계서를 전달하며 공개 Git에 원문을 자동 게시하지 않는다.
3. 후임은 최신 main, AGENTS.md·부서 운영 규칙·자기 부서 README, 관련 승인·진행 티켓/PR과 인계서를 직접 확인한다. 역할·현재 업무·첫 행동·미확인 사항을 짧게 회신하고 지정 시각부터 허용된 업무를 시작한다. INF·HQ·Owner의 별도 합격·전환 재승인을 기다리지 않는다.
4. 기존 담당은 승인된 종료 시각 이후 인계 업무의 신규 쓰기를 중단한다. 질의용 자료·과거 작성 이력을 보존하고 임의 삭제하지 않는다. 공유 worktree·진행 PR에 동시 쓰기가 남아 있으면 해당 쓰기부터 정리한다.
5. 후속 등록은 Owner가 직접 수행하거나 지정·승인한 담당자가 수행하고 HQ는 담당·의존성을 갱신한다. Owner 직접 등록 시 INF의 추가 수행·승인·검수를 필수로 요구하지 않으며 INF는 요청 시 정합성 확인·복구를 지원한다. 등록부 병합 지연을 업무 개시의 일괄 대기 사유로 삼지 않는다. [전환 규정](agents/REGISTRY_TRANSITION_RULES.md)에 따라 미반영 ID 예약·업무 효력·등록 반영 상태를 분리한다.

최초 Owner 지시에 정확히 열거된 티켓의 유효한 Commit/Push/PR 권한을 같은 경로·브랜치·기간·종료 조건으로 후임에게 이전한다고 명시할 수 있다. 해당 권한은 재승인받지 않는다. 명시되지 않은 동작·새 범위·만료 권한은 인계서만으로 부여되지 않는다. main 병합·릴리스는 해당 동작에 대한 별도 승인 또는 유효한 명시 위임을 따른다.

통상 인계에서 ACHC와 T1~T10은 필수가 아니다. 시험은 NOT_RUN(정책상 생략), 평가는 NOT_ASSESSED로 기록하며 ACCEPTANCE_VERIFIED/PASS를 만들어내지 않는다. 모든 부서와 INF 자체 교체에 같은 원칙을 적용한다.

### 예외 검증과 중단 범위

Owner가 상세 검증을 요청하거나 권한 충돌·중대한 인계 누락이 발견되면 필요한 항목만 보완한다. 선택적 T1~T10 전체 시험을 요청한 경우에만 기존 CRITICAL 5/5·NORMAL 4/5 기준을 사용한다. 요청된 범위·검증자·해제 조건을 기록하며 매 인계에 자동 적용하지 않는다.

ID 중복·불명확한 전환 시각·승인 없는 쓰기·자료 파괴 위험은 영향을 받는 전환 또는 작업을 보류하고 근거를 확인한다. 독립적인 승인 업무까지 일괄 중단하지 않는다. 종료된 전임 권한을 자동 복원하지 않고 승인 Git 원본으로 복구하며, 전임 복귀가 필요하면 그 결정은 Owner에게 맡긴다.

## 7. 비상 복구와 보안
현직에 접근 불가하면 Git의 최신 **승인된** 원본·PR·티켓을 사용한다. 로컬 미커밋 변경·채팅 전용 결정은 `UNKNOWN`/`NOT_VERIFIED`로 표시. 개발 환경(worktree·로컬 변경) 점검은 개발 소관. 인계 문서에 비밀값·내부 추론·개인 대화 전문을 수록하지 않는다.

**공개 Git:** 운영 규정·빈 양식·식별 가능한 공개 업무 근거만. **Owner 제한 자료:** 개별 진단 점수·오류·비공개 세션 식별자·개별 인계의 비공개 상세. 공개 필요성이 생기면 별도 Owner 검토 후 최소화한다.

## 8. 운영 회고
INF는 인계 누락·복구 비용·등록 지연·권한 충돌을 F-12에서 HQ·Convention과 함께 추적한다. F-11의 작업별 권한 확인은 최초 전환 지시의 유효한 승계 근거로 충족할 수 있다. QA 원본·접근권한·백업 복구는 실제 재검증 전까지 NOT_VERIFIED/NOT_RUN으로 남긴다. 자동화·CI 구현·ENFORCE·게임 범위는 이번 인계 간소화로 변경하지 않는다.
