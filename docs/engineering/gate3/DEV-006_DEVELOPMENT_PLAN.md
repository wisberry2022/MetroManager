## 3. 기술 경계와 의존성

기본 방향은 데이터/규칙 검증, 권위 있는 정수 게임 시각·상태/원장, 사용자 명령, 읽기 전용 UI 스냅샷, 시각 연출을 구분하는 것이다. 화면·열차 연출이 시뮬레이션 시간이나 돈을 생성하지 않는다. Godot의 구체 클래스·노드·저장 포맷은 각 실행 티켓에서 필요한 만큼만 정한다. 범용 이벤트 프레임워크·전역 Autoload·미승인 저장 체계를 미리 구축하지 않는다.

- W01 기반/규칙 데이터 → W02 시간/원장, W03 행정/노선/예측. W02와 W03은 입력/변경 경로를 분리하면 병행 가능.
- W02+W03 → W04A 입찰, W04B 회사 제안. 두 경로는 공통 계약 효과를 사용하되 별도 명령·판정·실패 경로를 유지.
- W04 공통 사업 확보 상태+W02 → W05 시공/시험 → W06 실제 운행/완료 운임/보고. W06의 순수 OD 계산·시각 피드백 준비는 앞서 병행 가능하나 실제 운행은 검증 통과 후만 허용.
- W07 UI 계약 초안·Design 와이어프레임은 초기부터 병행. 최종 UI 통합은 해당 상태 공급과 교차 수용 이후.

## 6. 첫 플레이 가능한 Slice 제안

**VS-01: 공공입찰 B01 → 표준 공사 → 시범/안전 → 실제 운행·일일 보고 → 다음 사업 조회.** 정부 확률 분기가 필요 없는 입찰 경로를 먼저 연결해 공통 시간·자금·시공·운행·UI를 검증한다. 이는 구현 순서 제안이며 VP-01이나 정부 심사의 제외가 아니다.

초기 데이터는 시작일06:00/C1000000/R0/K0/B0, 공고 고정 운임100/지급800000/표준600000·2880분, 시범60·안전60을 사용한다. 정상 낙찰86 대80, 낙찰 후 정부 심사 없음. 영업 전 C1200000/R200000/F1000000/K0/B0 기대값을 원장으로 검증하고 실제 완료통행 n과 발생비 e/지급 p로 보고를 대조한다.

플레이어가 공고/고정값/결과 이유를 보고 계약·시공·검증을 조작하고, 정지/1·2·4배속·자정 후 실적 보고와 다음 사업 후보를 확인할 수 있어야 한다. 열차 이동·정차/승하차 아이콘은 실제 집계와 연결한다. 기획 기간·비용을 “첫 Slice 단축” 목적으로 바꾸지 않는다. 테스트 러너의 빠른 시간 진행은 실제 제품 시간과 별도로 표시한다.

VS-01 종료 증거: 독립 초기 상태 입력 로그·원장·첫 실적 보고·화면/실플레이 기록, 동일 명령 재실행 결과 일치, 중복 지급·미검증 영업·보호금 유용 없음. 합의한 최소 표현/상태 수용 필요. 날짜 마감 전후 영업0분이면 운임0임을 별도 검증한다.

**VS-02:** 같은 공통 기반에 회사 제안·수요 비교·정부3분기·설득/신규 사실을 연결해 VP-01을 독립 초기 상태에서 완주한다. 정상 RNG 성공 시드는 실제 엔진으로 탐색·기록하며 임의로 성공을 고정하지 않는다. 두 VP 및 AC의 실패·경계·회귀까지 확보한 후에야 MVP 인수 요청이 가능하다.

재현 묶음은 규칙·데이터/엔진/코드 버전, 시드·실제 난수 추출 순서, 초기 상태, command_id/requested_at/effective_at, 틱·사건·원장·보고, 기대/실제 diff를 포함한다. 이는 테스트 기능이며 사용자 저장/중간 복원 SHOULD를 MUST로 승격하지 않는다. 정산 후의 계약 여력을 표시해도 A의 승인 정의 자체를 바꾸지 않는다.

검증 시점: 매 작업 순수 규칙/상태 자동+회귀 → headless 프로젝트 로드 → 통합 UI 실제 조작 → 두 VP 독립 재현 → Windows build/대상 PC 측정. 공통 시각/원장 수정은 두 경로·시공·보고 회귀, 예측/지도 수정은 관할·노선·OD·기존 VP, 계약 변경은 자금·입찰·제안 회귀를 다시 실행한다. 이번 계획 단계에서 해당 미래 검증 PASS를 미리 기록하지 않는다.

이슈 관리에서는 위 항목의 미정 자체를 모든 업무의 BLOCKED로 확장하지 않는다. 이번 DEV-006은 분석 제출 가능하며 후속 실행의 차단 시점만 명시한다. 다른 부서에 자동 메시지를 보내거나 작업을 배정하지 않는다.

다음 점검 주기의 우선 과제 3개: (1) HQ가 VS-01 및 W01~W03 착수/완료 범위를 통합, (2) 정적 수용한 UI revision을 실행 티켓에 인계하고 지도 목업/성능 장면의 실제 검증 입력 준비, (3) 승인된 실행 티켓부터 데이터/검사 기반과 시각/원장 경계 회귀를 구축. AI 작업을 인간 인일로 환산하지 않는다. 단계 완료·결함·외부 입력·재검증 비용을 보고하며 납기는 HQ/Owner 계획에 연결한다.

명세 변경 필요: 현재 없음. 기존 승인 의미와 충돌이 발견되면 해당 ID·영향 AC/VP·대안·Owner 필요 여부를 Issue RFC로 기록하고 정책을 임의 수정하지 않는다.
