## 3. 선행·병렬·통합과 차단 시점

1. **W01 → W02/W03:** 승인 데이터 버전·안정 ID·초기 상태·통화 정수/게임분·명령/결과·snapshot 출처·fixture 입출력/실패 기준을 DEV가 연결한다.
2. **W02 ∥ W03:** 입력·변경 경로를 분리해 병행한다. 공통 인터페이스의 실제 기반이 갖춰지기 전에 병렬 완료를 선언하지 않는다. Design의 정보구조·상태표·저충실도 흐름 검토도 병행 가능하다.
3. **해당 UI 통합 전:** DEV가 실제 snapshot/명령 결과·값/단위·기간/게임시각·reason_codes/allowed_actions와 정상/실패/오래된 응답 fixture를 공급한다. 미공급은 해당 UI 통합만 PENDING이며 독립 모델/자동검증 전체를 차단하지 않는다.
4. **W03 시각 검수/상세 에셋 확정 전:** Design 목업의 12후보·6/8역·오류·밀집/클릭 대체경로와 지도/목록 동등성을 DEV 판정값으로 대조한다. 판정은 안정 ID/부모/소속/간선이 원본이며 도형으로 재분류하지 않는다. Planning의 새 폴리곤 납품은 선행조건이 아니다.
5. **전체 P05/P06/P07/다음사업 통합 전:** 실제 운행 cohort·계약/정산·시험/개통 공급 및 공동 UI 검수를 후속 티켓에서 수행한다. 기존 정적 의미 수용을 실제 인수로 대체하지 않는다.

W02 검수에는 SEM-03 순서, 후순위 운임 선사용 금지(FX-R01-A), R/K 보호, B 정산, 중복 명령·낡은 계획, 자정·분할 재현이 필수다. 실패하면 W02 수용 및 의존 통합을 차단한다. W03의 독립 계산 검증까지 일괄 중단시키지는 않는다. 새 충돌이 발견된 행만 L2 협의하고, 승인 규칙/범위 변경·중대한 공통 원장 충돌은 RFC_AND_DECISION에 따라 HQ/Owner에 L3 상정한다.
