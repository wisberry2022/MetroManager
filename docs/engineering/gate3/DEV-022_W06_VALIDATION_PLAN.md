## 1. 증거 구분과 순서

1. **MODEL_CHAIN:** 실제 Pipeline 초기 상태에서 W04A 접수/계약/정부 지급 → W05 표준 공사/시험/안전/개통 명령 → W06 운행 → 최초 유효 보고/조회까지 자동 진행한다. OPEN·도착 운임을 직접 주입하지 않는다. 실제 GUI 완주로 표시하지 않는다.
2. **MODEL_FIXTURE:** 자금·carry·도착 경계 등 원인을 통제하는 모델/서비스 입력. 정상 제품 경로로 만들지 않은 상태를 명시한다.
3. **CONSUMER_FIXTURE:** DEV-023/Design용 공급 정상/오류/0/자료 없음·현재/과거 사본. 이것만으로 모델이 해당 실패를 자연 발생시켰다고 주장하지 않는다.
4. P1 단위 검증 → P2 실제 모델 연결 → P3 W06 전체/공통 영향 회귀 → 프로젝트 로드 → 공급·L3 결과 제출 순서다. 코드 변경 없이 통과한 검사를 임의 반복하지 않는다.

## 3. 수치 oracle와 과잉 해석 방지

- 기존 W03 P-A의 carry0·자금 무제한·06:00부터 온전한 영업일 조건에서는 [360,1440) 요청/탑승4860, 미탑승0, 완료4852, 운임485200, 서비스 비용108000, 이동 중8을 기준으로 대조한다. 마지막 서비스 구간 비용까지 반영한 1440 마감에서 T=1440 도착은 다음 날짜다. 잔여 완료 후 완료4860/운임486000, 추가 서비스 비용0도 확인한다. P-B 완료1460의 기존 조건은 해당 W03 입력과 함께 대조한다.
- 위 값은 TEST_ONLY 개통/초기 carry 조건을 명시한 비교다. 실제 표준 공사를 거쳐 부분일에 개통하는 MODEL_CHAIN에 같은 숫자를 강제하지 않는다. 실제 명령의 opened_at, 분별 OD 정수화, 도착 시각, 허용 구간 수로 독립 기대값을 계산한다.
- 과수요의 기존 경계 입력 D01=1296·U1·10분에서는 요청12/탑승10/미탑승2를 비교한다. 이 입력을 제품 기본 U10·승인 수요로 오해하지 않는다.
- CLOSE-01: 23:59 탑승8·이동10분 → 다음날00:09 완료8/운임800. 도착 직전 B500·기타 제약 없으면 B0·자유현금 순증300, 비용500 재인식0, 잔여 도착 추가비0, 전일 보고 불변. 이는 통제 cohort 사례이며 승인 P-A의 실제 OD가 같은10분을 자연 생성했다는 주장이 아니다. 별도의 실제 OD 자정 사례도 필수다.
- 각 날짜 `opening_in_transit + boarded − completed = closing_in_transit`, `requested = boarded + unboarded`, 완료×100=도착 운임을 검산한다. 경제 원장은 C/R/F/K/A/B와 발생 비용·실지급·B 정산을 각각 비교하며 화면 반올림값으로 재계산하지 않는다.

## 4. 실행 명령·회귀 범위

아래는 **Owner가 승인한 실행 계획**이며 명령 자체를 실행 로그로 간주하지 않는다. 실제 명령·종료코드는 검증 JSON의 runs를 따른다. Godot 4.7.2 콘솔 바이너리의 실제 경로·버전을 확인해 사용했다.

## 5. 증거·종료 기준

실제 구현 시 검증 JSON/결과서에는 task/agent, 소스/기준 SHA·dirty 여부, 엔진/도구 버전, 정확한 명령·입력 종류·명령 시각, 사용 DATA/fixture 해시, 사례별 기대/실제·종료코드·로그 해시, 미실행/미해결을 기록한다. 현재 W06는 결정적 계산이며 RNG seed는 N/A다. 최초 RNG 도입이 필요해지면 F-01 적용 시점과 범위를 먼저 검토한다.

DEV-022 수용 검토 조건은 실제 개통→운행 모델 연결, W06 필수 사례와 영향 회귀, immutable 보고/첫 실제 보고→조회 공급, L3 영향의 검증 결과, DEV-023용 공급/fixture·미해결 인계다. 신규 UI 설계/표현은 화면 통합 전에 Design L2를 거친다. 자동 PASS는 Design 수용·HQ 통합·Owner DONE이 아니다. 실제 정책 해석 차이가 없으면 기존 승인 의미의 재승인을 요구하지 않는다.

최초 계획 시점의 게임 자동·Godot 로드는 NOT_RUN이었으며 후속 실행에서 PASS했다. 실제 GUI/게임 플레이·빌드/성능·Design 독립 검수는 계속 **NOT_RUN**이다. [DEV-022 결과서](../tasks/DEV-022_RESULT.md)에 최초 준비와 실제 실행 결과를 구분해 기록한다.
