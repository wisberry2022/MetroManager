## 경로와 기존 부서 규칙

공용 오류 보고서의 위치는 `docs/co-work/err-report/`다. 전 부서가 승인된 자기 티켓의 범위에서 직속 Markdown 보고서 `ERR-YYYYMMDD-NNN_요약.md`와 공용 색인 `README.md`를 관리한다. 날짜 8자리·번호 3자리 이상·비어 있지 않은 요약을 사용하고 한국어 요약도 허용한다. 번호 중복과 날짜의 실제 의미는 작성·리뷰 시 확인한다.

티켓은 기존 부서 경로를 유지한다. 기획은 `docs/planning/tasks/PLN-NNN_TITLE.md`, 개발은 `docs/engineering/tasks/DEV-NNN_TITLE.md` 또는 기존 `tasks/DEV-NNN_TITLE.md`를 사용하며 나머지도 부서 매핑을 따른다. 결과 보고서만으로 티켓을 대체하지 않는다. 공용 경로에 별도 티켓을 두거나 부서 표기를 바꾸지 않는다.

허용 범위는 보고서와 색인뿐이다. `docs/co-work/` 전체, 다른 공유 공간, 하위 디렉터리, Python/GDScript/설정 파일, 타 부서 산출물, 정책/CI 변경 권한을 부여하지 않는다. 부서별 제목·브랜치·티켓 일치, 중간 커밋, rename의 출발/도착 경로, symlink/submodule 및 단일 부모 검사를 유지한다. 내용 승인·타 부서 작성 보고서의 수정 범위는 해당 티켓/Owner 검토로 확인하며 검사기는 실제 신원이나 승인 진위를 판정하지 않는다.
