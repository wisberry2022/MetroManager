## 검증 중 보완과 증거 한계

- 신규 runner의 스크립트 로드 오류를 수정하고 필수 사례 완료·최소 실행 단언 수 및 실제 엔진 오류 확인을 추가했다. 0건/중도 오류를 성공 처리하지 않는다.
- 수리 부족 fixture에서 과거 원장 시각 입력이 거부된 문제를 현재 게임분의 유효 자금 소모로 정합화했다. 제품 모델의 자금 규칙은 바꾸지 않았다. 최종173단언 PASS는 보완 후 실행이다.
- Windows 임시/Godot 사용자 디렉터리 접근 제한으로 초기 로컬 검사 실행이 실패해, 같은 승인 범위 검사를 필요한 접근 권한으로 다시 실행했다. 최종 결과와 초기 환경 실패를 구분한다.
- GUI 캡처 도구의 JPEG 원본을 PNG 확장자로 저장한 초기 임포트 실패는 동일 픽셀의 PNG 재인코딩으로 수정했다. 최종 프로젝트 로드는 오류0이며 화면 내용·텍스트를 수정하거나 생성하지 않았다.
- 사용자 입력이 섞인 최초 제품 실행은 제외했다. 별도 초기 보조 도구 입력은 효과 확인이 없어 PASS로 주장하지 않는다.
- 실제품 직접 실행 중 추가된 관측 로그와 다음 처리분의 야간 이연 보충 문구는 이미 실행 중이던 제품에 hot reload되지 않았다. 명령/경제 동작은 동일하며 최종 자동검사·최종 보조 GUI·로드 검증과 캡처 시점의 표현을 구분한다.
- 실제 GUI 창 종료는 관측했으나 분리 실행 프로세스의 OS 종료코드는 수집하지 못했다. 자동/로드 검사의 exit0과 구분해 GUI exit_code는 NOT_CAPTURED로 기록한다.
- 상세 거래별 수리 R/A 분담·전체 과거 시험 이력은 미공급이며 UI가 추정하지 않는다. 대용량 CASES를 도구로 읽기 어려우면 저장소 파일/로컬 재현 및 본 문서의 작은 요약을 이용한다.
