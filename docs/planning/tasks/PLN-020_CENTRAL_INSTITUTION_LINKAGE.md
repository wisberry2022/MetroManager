## 게시와 검증 방식

GitHub 플러그인/API로 게시하면 로컬 commit/push 훅 실행을 주장하지 않는다. 게시 전 doctor·문서 정합성·policy check·pre-commit·commit-msg를 확인하고, 게시 후 실제 커밋을 fetch하여 tree/부모/경로와 preflight를 확인한다.

현재 워크플로의 PR 이벤트 검사와 브랜치 게시 확인을 구분한다. PR의 정확한 head에서 필수 policy·department-policy 통과 및 병합 가능 상태를 확인하고, 승인된 squash 병합 후 실제 main SHA와 4개 파일을 확인한다. 정책 검사 성공은 제품 검수나 부서 인수를 뜻하지 않는다. 이번 병합 권한은 DEC-PLN-020-05에서 확인한다.
