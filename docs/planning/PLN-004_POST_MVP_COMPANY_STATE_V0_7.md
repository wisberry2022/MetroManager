## 1. Owner 결정으로 확정된 공통 원칙

1. 플레이어 회사의 내재적 상태를 나타내는 수치이며, **각 노드의 값은 0 이상 10 이하, 소수 허용**이다. 범위 밖 값은 가질 수 없다.
2. 값은 게임 시스템 내부에서 지속적으로 보유·평가한다. 플레이어는 **정확한 내부 수치를 직접 확인하지 못한다**. 미래 이벤트 발동 조건, 회사 평판, 실제 플레이 결과 등에 의해 바뀔 수 있다. 정확한 이벤트 효과는 아직 미설계.
3. 값은 **계층형**이다. 자식을 가진 노드의 값은 언제나 *직접 자식값의 산술평균*이다. 자식 수와 계층 깊이(Depth)에 **제한이 없다**. 최상위 7개 카테고리는 Owner 승인이다. 회사 전체 7개를 다시 평균한 단일 종합점수는 **미승인/미정의**.
4. 하위 말단의 **기본 초기값은 5.0**, 실제 평가 근거가 없으면 숫자는 보유하면서도 `UNOBSERVED`(미관측)로 구분한다. **미관측 5.0과 실제 관측 결과 5.0은 다르다.**
5. 향후 난이도별로 **초기값을 다르게 세팅**할 수 있어야 한다. 쉬움·중간·어려움·극한 등에 대한 *실제 초기값 숫자와 프리셋의 세부*는 미결정. 지정된 별도 초기값이 없는 경우 5.0을 기본으로 한다.
6. 점수 방향은 **B안**: 긍정적 성과·상태를 측정하는 **평가형 5개**, 단순한 관계 형성·인식 범위를 측정하는 **규모형 2개**. 규모형의 10은 반드시 좋은 상태/보상이라는 뜻이 아니다.
7. 유관기관 연계율은 **기관과의 관계·교류·업무 협력의 범위/활성화**를 평가하며, 기관의 호감·우호·신뢰·규제 지지 등의 *관계의 질*을 측정하지 않는다. 제재·감시만으로 자동 증가한다고 결정하지 않았으며 유효한 접점/평가식은 후속 정의.
8. 후임 기획은 승인된 내용의 재승인 요청 없이 나머지 카테고리를 정의한다. 이 문서의 등록·PR·병합은 게임 구현/정식 AC/VP 완료나 새로운 수치 승인 자체를 뜻하지 않는다.

### 계층·평균·관측 상태의 구분

- **확정된 산술평균:** `parent.value = sum(direct_child.value) / direct_child.count`. 미관측 자식 역시 **5.0이라는 실제 보유값**을 평균에 포함하는 해석으로 앞선 Planning 설계가 진행되었다. 만약 후속 Owner가 다르게 선택하면 계층 평균 해석을 명시적으로 개정해야 한다.
- **제안된 관측 메타:** 말단 `UNOBSERVED/OBSERVED`, 부모 `UNOBSERVED/PARTIALLY_OBSERVED/OBSERVED`. '미관측을 별도 표시'는 Owner 확정, 이 세 가지 영문 enum/기술 모델과 부분관측의 정확한 데이터 표현은 **후속 상세계약 검토** 대상이다.
- 말단 입력에만 점수 변경을 적용하고 자식이 있는 부모는 평균으로 재산출하는 방향을 따른다. 0~10 범위 보호는 `clamp(value,0,10)`을 사용할 수 있지만 증감량·결합 순서·정밀도·지표/사건 혼합 산식은 후속 승인 대상이다.
- **무제한 Depth의 결과:** 깊이와 각 자식 수가 달라지면 하위의 *실효 영향 비중*이 달라진다. 전체 말단을 일괄 평균하지 않는다. 분기 추가·이동 때 기존 상태값 승계/기본값/관측 취급과 기존 값 변동은 계층 버전 변경으로 명시적 후속 판단 필요.
- 일시정지·조회·중복 수신·배속·일괄/분할 실행만으로 실제 사건이 추가 평가되어서는 안 된다. 특정 게임 시각의 이벤트 적용 순서는 미래 시스템 도입 시 SEM-03와 연결하여 결정해야 한다.

## 4. FIN-01~07 — Owner 채택 평가 기준선

**Owner 결정:** 2026-11-08 Planning 대화에서 **FIN-01~07 기준안을 '이 방향으로 채택'**. FIN-01~06의 *첫 밸런스 수치 기준선*을 승인했고, FIN-07은 **5.0·미관측 및 신용/부채 도입 시 산식 확정**을 승인했다. 채택한 숫자/방향과 아직 필요한 세칙(기준 투자액, 관측 예외, 세션 실측)을 혼동하지 않는다.

### FIN-01 운영자금 완충력

- 입력 `A=max(0,F−ΣK)` (기존 승인 원장), `E_d>0`: 유효한 정상 운영계획의 **기준 1게임일 운영비**(실제 일시정지 때문에 0으로 조작되지 않음), `D=A/E_d` 게임일.
- 점수 기준 `D=0 / 3 / 15` → `0 / 5 / 10`, 구간별 선형 보간 및 0~10 제한.
- 식: `S=5D/3` (0≤D≤3), `S=5+5(D−3)/12` (3<D<15), `S=10` (D≥15).
- 현 MVP 단일 노선·06~24시/100통화·게임분 전부 영업의 **설명용 계산**: `E_d=18×60×100=108,000`. 미래 모든 사업/회사에 공통으로 고정되는 비용 기준은 아님.
- 정상 운영계획·기준 비용이 아직 없거나 `E_d=0`이면 **0/10을 임의 부여하지 않고 미관측** 유지 또는 기존 유효 관측값 취급을 후속 세칙으로 확정.

### FIN-02 신규 투자 자금여력

- 입력 `A`, `M>0`: 평가에 쓰는 **기준 신규 사업의 회사 자기부담 필요액**, `Q=A/M`.
- 기준 `Q=0 / 1 / 3` → `0 / 5 / 10`.
- 식: `S=5Q` (0≤Q≤1), `S=5+2.5(Q−1)` (1<Q<3), `S=10` (Q≥3).
- **기준 양수 M 자체는 아직 미정**. MVP B01 정부금800,000·표준 공사600,000으로 자기부담 M=0인 사례를 사용해 가짜 10점을 만들지 않는다. 양수 기준이 없으면 `UNOBSERVED` 처리.
- 이 점수는 **새 계약 허용 여부**가 아니며, 기존 사업 자격/가용액/K 검사를 대체하지 않는다.

### FIN-03 수익성 공통 환산

- 대상 비용 `E>0`, 대상 매출 `R`: `m=(R−E)/E`; `S_profit=clamp(5+5m,0,10)`.
- 손익률 `m=−100% / 0% / +100%` → `S=0 / 5 / 10`; 사이 연속 선형 보간. `E=0`이면 분모가 없으므로 임의 평가 금지.
- 수익성에서 지급 지연으로 현금 지출이 없더라도 **이미 발생한 비용**은 사라지지 않는다.

### FIN-04 운행 수익성 평가기간

- **최근 7게임일의 확정 운영 실적**을 평가기간으로 채택(실제 도착 완료 운임 매출 및 **발생** 운영비).
- `m_ops=(R_fare−E_ops)/E_ops`, `E_ops>0`인 경우 FIN-03 환산식 적용.
- 기존 SEM-03에 따라 운임은 **도착 완료일**, 운영비는 **발생일**에 귀속. 과거 확정 보고를 재작성하거나 현금 지급분으로 발생 비용을 대체하지 않는다.
- **최소 유효 기간(예: 정상운영 1일 상당), 부분 영업일·0수요/0비용 기간의 최초 관측/마지막 값 보유 처리, 회계 기간 경계의 왜곡 처리**는 후속 상세 검증/Owner 승인 대상.

### FIN-05 사업 수익성

- 채택한 1차 MVP 범위: **정부 사업비 매출 `G`와 직접 사업비/시공비 `X`**를 구별. `X>0`이고 해당 사업의 평가 대상 비용이 확정됐을 때 `m_project=(G−X)/X` 및 FIN-03 적용.
- **B01 완료 후 설명용 예시:** `G800,000 / X600,000` → 손익률 `1/3`, 점수 `6.666...`. 정부 제한잔액 R200,000이 자유현금으로 자동 전환된다는 뜻이 아님.
- 시공 중 계약 시점의 정부 매출만으로 최종사업 수익성을 확정하지 않는다. 운행 수입·운영비는 FIN-04와 **중복 반영하지 않는** 1차 범위.
- 여러 사업을 합산해 평가할 때 합산 손익률을 쓸지/사업별 관측 창과 완료 요건을 어떻게 처리할지는 **후속 상세 규칙**, 기존 1차 기준선 변경 아님.

### FIN-06 미지급 부담 관리 수준

- `B≥0`: 미지급 **운영비** 잔액, `E_7≥0`: 최근 7게임일 **발생** 운영비.
- `max(B,E_7)>0`인 유효 관측 시 `r_B=B/max(B,E_7)`, `S_B=10(1−r_B)`. `B/E_7=100% / 50% / 0%`인 관측 예시에서 `0 / 5 / 10`.
- `B=0,E_7=0`이면 평가 근거가 없으므로 10점 자동 부여 금지. **관측 이력/기본 5.0의 유지**, 실제 지급 의무 존재와 최초 평가 가능 시점은 상세 규칙에서 구분한다.
- 7게임일 B·발생비만으로 연체 지속기간의 모든 위험을 측정하진 못한다. **미지급 지속기간/지급 지연 이력**은 향후 하위 확장 후보일 뿐 승인된 7번째 재정 말단값이 아님.
- FIN-06은 **MVP에서 제외된 B>0 신규 계약 제재나 6개월 연체 제재를 되살리지 않는다**.

### FIN-07 채무 구조 건전성

- **현 적용:** `value=5.0 / UNOBSERVED`.
- 실제 대출·이자·원금·상환·만기 구조는 이번 MVP에 없으며, **채무 구조 건전성 평가 공식은 아직 승인되지 않았다**.
- 향후 신용·부채 시스템이 확정되면 상환능력(상환가능현금흐름/기간 원리금), 부채 규모·만기 집중 등 후보 요소와 0·5·10 앵커를 별도 기획·Owner 승인해야 한다.

## 5. 원천 데이터·효과 충돌 금지

- 기존 MVP 권위 원장: 총현금 `C`, 사업별 제한자금 `Rᵢ`, `F=C−ΣRᵢ`, 자기 예약 `Kᵢ`, `A=max(0,F−ΣKᵢ)`, 운영비 미지급 `B`. 정부 지급은 제한사업 매출·현금 유입으로 인정되지만 R의 용도 제한은 유지.
- 기존 **입찰 재무점수 0~100**, **이행능력 점수**, **승객 만족도 0~100**은 새 회사 내부 상태값 0~10과 **독립**. 새 재정 점수로 기존 입찰 점수/낙찰·정부 승인·요금·원장·OD 수요를 자동 대체·재계산하거나 확률 보정하지 않는다.
- 새 시스템의 역방향 효과(평판·공공심사·신용·안전 이벤트에 작용하는 계수/조건)와 이벤트 소비/재현·SEM-03 단계 추가는 **미승인**. 별도 HQ/Owner 결정 후 실제 구현.
- 재정과 재무위기 대응역량을 구분한다: 전자는 현재 상태, 후자는 위험 **예방/대응 능력**. 서비스 성과와 이용자 신뢰·인지도도 자동 동일 점수로 취급하지 않는다.

## 9. 서비스 수준 1차: 평가 대상과 산식

### 9.1 목적·용어·적용 경계

서비스 수준은 회사가 **지역의 이동을 연결하는지, 실제 승차 요청을 수송하는지, 계획한 운행을 제공하는지**를 구분해 평가한다. 기존 직접 자식인 교통 접근성·수송 충족도·운행 신뢰성 3개를 말단으로 유지한다. 이용자 신뢰도·만족도·입찰 점수와는 별개이며, 이 점수로 기존 운임·수요·입찰·제재를 자동 보정하지 않는다.

| 용어 | 설계상 의미 |
|---|---|
| 기준 수요 | 노선 선택률 `q(T)`, 실제 승차, 용량 제한을 적용하기 전의 유효 잠재 OD 수요 |
| 책임 서비스 지역 | 시나리오가 정한 교통 접근성 평가 지역. 개통한 노선의 역세권과 다름 |
| 여정 | 최초 출발지에서 원래 최종 목적지까지의 이동 1건. 환승해도 하나 |
| 승차 기회 | 실제로 도달한 최초 승차 또는 환승 단계에서, 영업·재무 등 승차 허용 조건을 충족하여 용량 판정을 받은 요청 1건 |
| 실제 운행 단위 | 회사의 독립된 운행 계획·제공 의무를 대표하는 집계 단위. 화면 노선명·개별 열차 수와 다름(§11.2) |
| 승차 허용 조건 | 영업시간, 유효 개통, 운행 가능 상태, 기존 재무 조건 등. 용량 부족과 구분 |
| 확정일 | 일일 마감이 끝난 게임 날짜. 진행 중인 당일은 7일 평가 창에서 제외 |
| 평가 근거 버전 | 지역·수요·연결·실제 운행·산식 등의 의미를 재현하고 비교 가능성을 판정하는 정보. 저장 구조/enum 이름은 DEV 소관 |

이하 기호 `S_A/S_F/S_R`는 서비스 점수이며, 현금 원장의 `A/F/R`과 다르다. **산식과 정확한 점수는 내부 설계·검증용이고 플레이어 공개 UI의 내용이 아니다.**

### 9.2 세 지표와 부모값

| 지표 | 비율의 분자 / 분모 | 내부 점수 | 책임 범위 |
|---|---|---|---|
| 교통 접근성 | 책임 지역 안의 양 끝점을 회사의 개통망으로 연결할 수 있는 기준 OD 수요 / 책임 지역 안의 모든 기준 OD 수요 | `S_A=10a` | 구조적으로 연결되지 않은 수요 |
| 수송 충족도 | 실제 탑승한 승차 기회 수 / 실제 유효 승차 요청 수 | `S_F=L_0.90(f)` | 승차 가능 상태에서의 용량 부족 |
| 운행 신뢰성 | 계획대로 제공한 실제 운행 단위·분 / 제공하기로 계획한 실제 운행 단위·분 | `S_R=L_0.95(r)` | 계획 운행의 미제공. 정시 도착 평가는 제외 |

`L_b(x)=5x/b` (0≤x≤b), `L_b(x)=5+5(x−b)/(1−b)` (b<x≤1).

- 접근성 `0% / 50% / 100%`, 충족도 `0% / 90% / 100%`, 신뢰성 `0% / 95% / 100%`를 각각 내부 점수 `0 / 5 / 10`에 대응시킨다.
- `서비스 수준=(S_A+S_F+S_R)/3`. 하위 보유값이 미관측 기본값/과거 유지값인 경우에도 내부 평균에는 포함한다. **현재 종합 단계의 공개 조건은 별도**로 §15.5를 따른다.
- 충족도와 신뢰성은 먼저 회사 전체의 분자·분모를 각각 합산한 뒤 비율을 구한다. 노선별 비율/점수를 단순 평균하지 않는다. 책임 지역 밖의 정상 회사 운행·실제 요청도 충족도/신뢰성에는 포함한다.
- 분자·분모는 같은 대상·기간·규칙의 자료를 사용한다. 유효 비율은 0~1이고 최종 점수는 0~10이다. 분자>분모 등 불일치를 점수 제한으로 숨기지 말고 새 평가를 보류한다.
- 하나의 실패에 임의의 추가 감점을 중첩하지 않는다. 구조적 미연결은 접근성, 용량 실패는 충족도, 계획 운행 미제공은 신뢰성에 각각 귀속한다. 중도 종료 건수만으로 별도 벌점을 만들지 않는다.

### 9.3 최초 관측·갱신·자료 부족

| 상황 | 접근성 | 충족도·신뢰성 |
|---|---|---|
| 회사의 첫 유효 개통 전 | 5.0·미관측 | 5.0·미관측 |
| 첫 유효 개통 후 | 현재 지역·수요·연결 자료가 완전하면 평가. 개통 또는 공식 구조/수요 변경의 T 처리 완료 뒤 갱신 | 최근 7개 마감 게임일 중 개통 이후의 실제 자료로 평가. 당일 제외 |
| 최소 자료 | 현재 기준 수요의 유효한 양수 분모와 완전한 연결 정보 | 충족도 누적 **100승차 기회 이상**, 신뢰성 누적 **1,080 실제 운행 단위·분 이상** |
| 부분 영업일 | 유효한 현재 구조 평가 | 실제 존재한 부분만 합산. 1일 상당으로 외삽하지 않음 |
| 최초 자료 부족·분모 0 | 평가 불가·기본값 유지 | 5.0·미관측/자료 수집 중 |
| 유효 관측 이후 자료 부족·분모 0 | 마지막 유효값·근거 시점 유지, 현재 평가 불가 표시 | 마지막 유효값·근거 시점 유지, 현재 평가 불가 표시 |
| 누락·손상·불일치 | 새로운 평가 중단, 마지막 유효 근거 또는 미관측 상태 유지 | 동일. 유효한 실적 0과 오류를 구별 |

- 100은 **사람/완료 여정 100명**이 아닌 승차 기회 100건이다. 최초 관측에 7일이 모두 차야 하는 것은 아니다. 다만 추세는 §15.2의 완전한 비교 창 조건을 별도로 적용한다.
- 정상 영업이나 실제 요청이 0이면 충족도는 새 평가를 만들지 않는다. 계획 운행 시간이 충분하고 모두 제공했다면 같은 기간 신뢰성은 10이 될 수 있다. 계획 시간이 양수이고 모두 미제공했다면 신뢰성 비율은 유효한 0이다(최소 표본 충족 필요).
- 미개통·휴업·재개·재로딩만으로 값이 5나 10으로 자동 회복하지 않는다. 일시 중단으로 과거 계획·요청·미제공 이력을 삭제하지 않는다.
- T의 계약/공정/개통/도착/정산/승차 결과를 서로 다른 시점의 자료로 섞지 않는다. 같은 게임 사건·시간에는 조회·일시정지·중복 수신·배속·일괄/분할 진행과 무관하게 같은 평가가 나와야 한다. 실제 저장/호출 단계는 DEV가 기존 SEM-03와 연결해 검증한다.

## 10. 책임 지역·기준 수요·다노선 연결

### 10.1 책임 지역과 수요 변경

1. 책임 지역은 시나리오가 정한 지역이며 **OD의 출발지와 목적지가 모두 안에 있을 때** 접근성 분모에 포함한다. 중간 경로가 지역 밖을 지나도 양 끝점이 안이면 인정한다.
2. 개통 지역만 책임 지역으로 삼지 않는다. 노선 개통·폐지·이름 변경·일시 중단으로 분모를 줄일 수 없다. 사전에 정한 시나리오 사건만 지역을 변경한다.
3. 기준 수요에는 공식 상시 변화와 유효기간이 있는 임시 변화가 효력 시점에 반영된다. `q(T)`나 실제 승차·용량·중단으로 이미 줄어든 수요를 접근성 분모에 넣지 않는다.
4. 한 OD를 여러 역·노선·환승 경로가 연결해도 그 기준 수요를 한 번만 센다. 동일 동의 복수 역에 수요를 복제하지 않는다.
5. 새 지역/수요는 해당 T 사건 처리가 완료된 일관된 자료로 즉시 반영한다. 유예기간·임의 보정·점수 초기화·기존 7일 실적 삭제는 없다. 기존 보고와 과거 평가의 당시 기준을 보존한다.
6. 새 기준의 필수 데이터가 없으면 마지막 유효값을 유지하고 현재 평가 자료 부족을 알린다. 새 분모와 옛 연결 결과를 섞어 임시 점수를 만들지 않는다.

### 10.2 연결 인정과 경로 선택

- 같은 회사의 **유효 개통된 서로 다른 실제 운행**이 동일 역 ID를 정차역으로 공유하고, 필요한 승하차·진행 방향을 허용하면 역내 환승을 인정한다. 별도 환승 시설 건설·해금은 1차에서 요구하지 않는다.
- 정차하지 않는 통과역, 진행 불가능한 방향, 미개통 구간을 연결로 인정하지 않는다. 계획상 연결과 일시적인 실제 운행 제한을 분리한다. 일시 영업/재무 중단만으로 구조적 접근성을 삭제하지 않는다.
- 다른 역 ID끼리는 같은 동·같은 역명·인접 간선이라는 이유로 도보 연결하지 않는다. 다른 회사의 노선은 1차 연결망에서 제외한다.
- 유효한 회사 경로는 환승 횟수의 임의 상한 없이 고려한다. 무의미한 반복 순환을 수요/환승으로 생성하지 않는다. 같은 실제 운행을 타고 계속 가는 중 표시명만 바뀌면 환승이 아니다.
- 여정 생성 시 **예상 총 이동시간 최소 → 환승 횟수 최소 → 안정된 역/노선 ID 순서**로 경로 하나를 정한다. 모든 후보를 독립 수요로 만들지 않는다.
- 예상 총 이동시간은 기존 간선 이동시간·중간역 정차시간에 **실제 환승마다 이동 2분+정상 대기 1분**을 더한다. 최초 승차에 이 1분을 추가하지 않는다.
- 계획상 각 신규 승차는 해당 운행의 영업시간 안이어야 한다. 마지막 구간의 목적지 도착은 영업 종료 후라도 가능하다. 계획된 밤샘 환승 대기를 경로로 만들지 않는다.
- `q(T)`는 이 전체 예상 시간에 **한 번만** 적용한다. 이후 실제 추가 대기·지연 때문에 원래 요청량이나 선택률을 소급 재계산하지 않는다.

## 11. 환승 콘텐츠와 실제 운행의 동일성

### 11.1 첫 콘텐츠 기준

| 사례 | 판정 |
|---|---|
| P-A `S01→S02→S03→S04→S08→S12`, P-B `S01→S05→S09→S10→S11→S12`가 각각 독립 운행으로 개통 | 공통 정차역 S01·S12에서 환승 가능. 필요한 방향의 승하차가 허용되어야 함 |
| 미래 다른 회사 내 노선들이 다른 역 ID를 공통 정차역으로 공유 | 동일 규칙 적용. S01·S12만 영구 허용하는 목록이 아님 |
| S08↔S12(둘 다 D08), S05↔S09(둘 다 D05) | 다른 역 ID이므로 기본 도보 환승 없음. 실제 개통된 구간을 타는 것과 구분 |
| 선로가 만남·같은 동·같은 역명이나 공통 정차/승하차 불가 | 환승 불가 |
| 동일한 실제 운행의 노선 표시명만 전환 | 계속 승차. 추가 환승 시간·승차 기회·운임 없음 |

경로 예: 승인된 간선/정차 시간을 쓰면 P-A의 S04→S01 5분, 역내 환승 3분, P-B의 S01→S05 1분으로 총 9분이다. S04→S12 3분, 환승 3분, P-B의 S12→S09 5분은 총 11분이다. 서로 다른 목적 역으로 같은 목적 동에 접근할 수 있어도 동 수요를 복제하지 않고 더 짧은 유효 전체 경로를 선택한다.

### 11.2 같은 실제 운행과 독립 운행

**기준은 표기가 아니라 회사의 공식 운행 계획과 실제 제공 의무다.** 경로·정차·방향·운행시간 및 실제 수송 기회/용량 사용을 추적한다.

| 판정 | 기준과 집계 결과 |
|---|---|
| 동일 실제 운행의 별칭 | 같은 계획·실제 수송 기회·자원 사용 1회·운행 제공 의무 1건을 가리킴. 신뢰성 분모/분자, 요청/탑승을 중복 생성하지 않음 |
| 기존 운행의 증편·차량 교체·시간표 변경 | 개별 차량·출발편·방향 표시마다 새 노선 분모를 만들지 않는다. 실질적 계획 변경은 효력 시점과 변경 이력으로 반영 |
| 독립 운행 | 서로 다른 운행 계획과 제공 의무가 실제 존재. 같은 선로·역·차량·차량기지·재원·용량 풀을 공유하거나 동시에 중단되었다는 이유만으로 합치지 않음 |
| 실제 계획의 분리·통합 | 효력 이후의 실질 제공 의무에 반영. 과거 계획/중단·7일 창을 소급 삭제하거나 이름 변경으로 평가를 리셋하지 않음 |

- P-A/P-B가 독립 운행이면 신뢰성은 각 계획 시간을 합산한다. 이것만으로 수송 용량·차량·운영비가 두 배 승인되는 것은 아니다. **자원 공급 규칙은 기존 권위 계획과 실제 공유 관계를 따른다.**
- 동일한 용량 풀을 여러 표기가 참조해도 각 호출마다 용량을 새로 지급하지 않는다. 독립 운행 여부와 공유 용량 여부는 별도 정보다.
- 신뢰성의 한 운행 단위·분은 **그 분에 계획상 필요한 경로·정차·운행 범위를 모두 제공**했을 때 1이다. 필요한 일부가 빠지면 그 분은 0으로 집계한다. 부분 제공 비율로 0.5 등을 주지 않는다.
- 일부 미제공으로 신뢰성 0분이 되더라도 실제로 제공 중인 나머지 구간을 강제로 정지시키거나 정상 승차 실적을 지우지 않는다. 용량이 꽉 찬 상태 자체는 운행 미제공이 아니다.

## 12. 여정 상태·환승 대기·운임·종료

### 12.1 환승 시각과 대기 처리

환승 단계의 앞 구간 도착 시각을 `t_arrival`, 환승 준비 완료를 `t_ready=t_arrival+2`로 둔다. 최초 용량 판정 가능 시각은 `t_ready+1`, 최종 대기 기한은 `t_ready+5`다. 5분에는 정상 대기 1분이 포함된다.

| 상황 | 처리 | 충족도 반영 |
|---|---|---|
| 준비 중·정상 대기 중 | 아직 승차 판정 없음 | 요청으로 먼저 생성하지 않음 |
| 최초 판정 가능 이후 승차 허용 조건이 닫힘 | 최종 기한까지 기다릴 수 있음 | 아직 유효 승차 요청이 아님. 제한 원인은 별도 기록 |
| 허용 조건 충족, 용량 있음 | 해당 단계 1회 탑승 | 요청 1·탑승 1 |
| 허용 조건 충족, 용량 부족 | 그 단계 실패로 즉시 종료. 다음 분 재시도 없음 | 요청 1·탑승 0 |
| 최종 기한 T에 허용 조건 회복 | 정상 T 처리 후 마지막 판정 기회 제공 | 위 성공/용량 실패 중 하나 |
| 최종 기한 T 처리 후에도 허용 불가 | 대기 만료로 중도 종료 | 가상의 용량 실패 요청을 추가하지 않음 |
| 최종 기한 다음에 회복 | 이미 종료한 여정을 부활시키지 않음 | 재요청 없음 |

예: 10:00 도착 → 10:02 준비 완료 → 10:03 최초 판정 → 10:07 마지막 판정 후 만료. 10:07 회복은 인정하고 10:08 회복은 늦다. 일시정지는 게임 시간을 멈추며, 자정·영업 종료·재로딩은 기한을 늘리거나 초기화하지 않는다.

### 12.2 경쟁 순서·경로 고정·일자 귀속

- 같은 실제 용량을 경쟁하는 대기자는 **준비 완료 시각 → OD ID → 여정 생성 순서**로 처리한다. 신규 최초 승차는 현재 시각을 준비 시각으로 보며 더 오래 기다린 환승자와 같은 기준으로 경쟁한다. 아직 정상 대기 1분이 끝나지 않은 환승자는 판정 대상이 아니다.
- 용량은 공유 풀 단위로 1회 소모한다. 별칭·경로 후보·여러 조회 호출로 복제하지 않는다. 실제 첫 용량 판정 후 용량 부족은 기다리거나 다른 경로로 재시도할 권리가 되지 않는다.
- 여정 생성 후 경로를 고정한다. 자동 우회·재탐색은 1차에서 하지 않는다. 다음 연결이 무효가 되어도 이미 승차한 현재 구간의 정상 도착 처리는 보존하며, 원래 목적지에 도착했다고 꾸미지 않는다.
- 최초 승차 실패는 **미시작**이다. 최초 승차 이후의 용량 실패·대기 만료·유효한 다음 연결 소멸은 **중도 종료**다. 자료 누락 자체를 실제 연결 소멸이나 강제 종료로 추정하지 않는다.
- 앞 단계 실패 후 아직 도달하지 않은 환승 단계의 요청은 생성하지 않는다. 한 여정이 여러 실제 단계에 도달하면 단계별 승차 기회는 각각 셀 수 있지만 동일 단계는 한 번만 센다.
- 승차 기회는 실제 판정일, 탑승은 실제 탑승일, 최종 운임은 최종 도착일에 기록한다. 자정 때문에 완료 전의 미래 단계를 앞 날짜에 배분하거나 마감 보고를 다시 쓰지 않는다.

### 12.3 운임과 회계

1. 회사 내 한 여정의 **기본 운임은 한 번**이다. 환승 횟수별 추가 운임을 만들지 않는다. 현재 쉬움 운임 100은 예시 기준이며 새 난이도 공통 운임표를 승인한 것은 아니다.
2. **최초 성공 승차 시점의 운임을 고정**한다. 이 시점에는 선결제·매출·미수금을 만들지 않는다. 환승 중 운임이 바뀌어도 해당 여정의 운임은 바꾸지 않는다.
3. **원래 최종 목적지 도착 완료 때 1회 징수·매출 인식**한다. 중간 환승역 도착은 과금 사건이 아니다. 기존 SEM-03의 도착일 귀속·도착 운임 유입→B 우선 정산→신규 승차 순서와 R/K 보호를 유지한다.
4. 최초 승차 실패, 승차 후 중도 종료에는 운임 0이다. 부분 이용 운임을 징수하지 않는다. 이미 발생한 운영비·성공한 과거 승차 실적은 남는다.
5. 지연되어도 최종 완료하면 고정 운임 전액을 징수한다. 지연 할인·환불·자동 현금 보상은 1차에 없다. 원래 징수하지 않은 운임은 **미징수**이지 환불이 아니다. 오류 중복 징수의 원장 정정은 정상 환불 콘텐츠와 구별한다.

중간 환승역에 도착한 여정은 종료하지 않고 이동/대기/다음 승차 상태로 이어진다. 마지막 구간이 영업 종료 후 도착해도 정상 완료·운임 인식한다. 잔여 승객 도착만으로 추가 영업 운영비를 생성한다는 뜻은 아니다.

### 12.4 보존 관계

- `기초 진행 중 여정 + 신규 최초 탑승 여정 = 최종 완료 + 중도 종료 + 기말 진행 중 여정`.
- 진행 중에는 탑승·환승 이동·대기 상태가 모두 포함된다. 현재 MVP의 '차내 승객'만으로 전체 진행 중 여정을 대체하지 않는다.
- 단계별 `유효 요청 = 탑승 + 용량 실패`를 중복 없는 같은 자료 범위에서 확인한다. 허용 조건 대기·기한 만료·미도달 미래 단계는 이 등식의 가상 요청으로 넣지 않는다.
- 예: 100여정이 첫 구간에 모두 탑승하고 둘째 구간에서 80탑승/20용량 실패하면 요청 200·탑승 180, 충족도 90%→내부 5점이다. 최종 완료 80·중도 종료 20이며 운임 100 기준 매출은 8,000이다. 종료 20건을 이유로 첫 성공 탑승 100건을 취소하지 않는다.

## 13. C01 서비스 확장 시나리오

### 13.1 별도 시나리오와 지역 확장

서비스 지역 확장 콘텐츠는 **새로 선택하는 별도 C01 시나리오**에 적용한다. 기존 C01 기본 시나리오와 기존 세이브를 이 시나리오로 자동 전환하지 않는다. `T0`는 시나리오 시작 시각이며 첫 개통일·점수 관측일이 아니다.

C01의 전체 역과 실제 잠재 수요는 시작부터 존재한다. 단계별로 바뀌는 것은 접근성의 책임 평가 지역이다. 평가 지역 밖 운행도 정상 사업/관할 규칙을 따라 가능하며, 해당 회사의 충족도·신뢰성 실적에는 포함된다.

| 효력 시각 | 접근성 책임 지역 | 다른 수요 변화가 없을 때 기준 분모 | P-A만 유효 연결된 경우 연결 수요 / 점수 |
|---|---|---:|---|
| T0 | G01·G02 = D01~D04 | 4,700 | 4,700 / 10 |
| T0+7게임일 | G03 추가 = D01~D06 | 6,100 | 4,700 / 7.704918… |
| T0+14게임일 | G04 추가 = D01~D08 | 7,000 | 4,900 / 7 |

검산 근거는 DATA의 출발 수요 `D01~D08=[2000,1500,1200,800,600,400,300,200]`, 목적지 다음 동 순환(D08→D01)이다. 양 끝점이 책임 지역 안인 OD만 합산하므로 초기에는 D04→D05를 제외한다. P-A 연결 동은 D01~D04·D08이며 전체 지역에서는 D08→D01의 200이 더해진다. 표는 **이미 유효 개통되어 관측 가능한 조건**의 기대값이다. 미개통이면 예정 시나리오 수요만으로 미관측 5.0을 관측 점수로 바꾸지 않는다.

### 13.2 임시 수요 사건

- `[T0+21게임일, T0+28게임일)` 동안 **D05→D06 잠재 수요에 하루 기준 +300**을 더한다. 시작은 포함하고 종료는 제외한다.
- 다른 유효 수요 규칙을 적용한 권위 기준 수요에 이 사건의 +300을 **가산**한다. 이 사건을 배수로 적용하거나 다른 사건의 효과와 함께 지우지 않는다.
- 다른 변화가 없으면 해당 OD는 600→900→600, 전체 기준 수요는 7,000→7,300→7,000이다. P-A만 연결된 상태의 사건 중 접근성은 `10×4900/7300=6.712328…`이다.
- 사건 종료 때 자기 가산 300만 제거한다. 다른 사건이 남아 있으면 무조건 600으로 되돌리지 않는다. 기존 일반 수요 사건의 결합 산식을 이 콘텐츠만으로 재정의하지 않는다.
- 실제 요청 생성과 접근성 평가가 같은 유효 잠재 수요를 사용한다. 실제 요청의 `q(T)`·시간대 배분·소수 이월은 이후 단계다. 과거 미처리 요청을 소급 생성하거나 저장/불러오기 때 사건을 재적용하지 않는다.
- 지역 확장과 임시 수요 일정·효력은 사전에 플레이어에게 알린다. 이벤트로 인한 점수 변화 외에 자동 벌금·보상·강제 계약을 추가하지 않는다.

## 14. 적용 개시·세이브·과거 실적 승계

### 14.1 적용 시점과 버전 판정

`τ`는 세이브를 정상 복구·검증한 **마지막 처리 완료 게임 시점**이다. 도입을 위해 게임 시간을 인위적으로 진행하거나 이미 처리한 T를 재생하지 않는다. 이후 미처리 대상에 새 규칙을 적용한다. 신규 게임도 시나리오 시작 정보와 적용 규칙을 함께 식별한다.

| 자료 상태 | 현재 평가로의 승계 |
|---|---|
| 이 시스템 최초 도입 | 이미 개통했고 현재 권위 자료가 완전하면 접근성은 현재 상태로 평가. 충족도·신뢰성은 5.0·미관측으로 시작하여 적용 이후의 실제 실적만 수집 |
| 같은 의미·호환 버전의 유효 평가/실적 | 값·평가 기간·최초 관측·마지막 유효 시점·적용 기준을 유지. 재로딩이 새 최초 도입이 되지 않음 |
| 같은 의미의 과거 유효값은 있으나 현재 자료 부족 | 과거값과 날짜 유지, 현재 자료 부족 표시. 과거값을 새로운 관측으로 재발행하지 않음 |
| 비호환이거나 의미를 확인할 수 없는 구버전 점수 | 구버전 기록으로 보존하되 현재 평가/추세에 혼합하지 않음. 접근성은 유효한 현재 자료로 재평가 가능, 충족도·신뢰성은 새 규칙 5.0·미관측에서 수집 |

기존 합계 보고·예측치만으로 과거의 실제 단계별 요청, 계획/제공 시간을 추정해 채우지 않는다. 과거 보고는 당시 규칙과 수치 그대로 보존한다. 이 규칙은 서비스 수준 범위이며 FIN의 미결 관측 세칙을 대신 확정하지 않는다.

### 14.2 최초 창·기존 진행 여정

- 충족도·신뢰성은 적용 후 최근 7개 마감 게임일의 해당 실제 구간만 사용한다. 최소 100기회/1,080분은 동일하며, 적용 전 자료를 끌어와 표본을 채우지 않는다.
- 예: 단일 06~24시 운행에 12:00부터 처음 적용했다면 그날 720분은 실제 표본으로 남지만 신뢰성 최초 관측의 1,080분에 아직 미달한다. 1,080분으로 외삽하지 않는다.
- `τ` 전에 진행 중인 여정은 **원래 규칙으로 종료까지 처리**한다. 기존 경로·운임·대기 기한·도착을 보존하고 강제 재시작·강제 종료·재과금하지 않는다. 새 규칙에 없던 대기 기한을 옛 여정에 소급 부여하지 않는다.
- `τ` 이후 새로 생성한 여정은 새 규칙을 사용한다. 최초 도입 시 충족도에는 **새 규칙 여정의 실제 승차 기회만** 포함한다. 옛 여정이 실제로 차지하는 용량은 그대로 소모된다. 신뢰성은 승객 규칙 버전과 별개로 적용 이후의 실제 운행 제공 시간을 평가한다.
- 기존 시나리오는 시나리오·게임 시간을 유지한다. 이미 지난 +7일/+14일을 새 시나리오 사건으로 강제 재생하지 않는다.

### 14.3 저장 안전성과 반복 실행

- 원본 세이브를 보존하고 별도의 변환 사본을 검증한 후 전환 완료로 취급한다. 일부 변환만 성공한 상태를 정상 플레이 가능한 현재 상태로 인정하지 않는다.
- `τ`, 시나리오 `T0`, 이미 소비된 사건, 여정 기한, 최초 개통, 관측 창, 과거 평가 상태를 보존한다. 같은 저장본의 재로딩으로 지역 확대/수요 사건을 중복 적용하거나 평가 표본을 초기화하지 않는다.
- 기존 C/R/F/K/A/B 원장, 공사·시험·기성/미지급, 소수 수요 이월을 서비스 설계 도입 때문에 재생성하거나 재결제하지 않는다.
- 실제 저장 형식·변환 절차·복구 가능성은 **미검증**이다. 이 절은 제품 동작 기준이며 현재 세이브가 이미 이를 지원한다는 진술이 아니다.

| 기준 변경 | 새 평가 기준 및 비교 제한을 알림. 자동 초기화 의미가 아님 |

상태 구분은 승인 사항이지만 화면 문구의 세부 표현·색상·아이콘·배치는 Design 소관이다. 정보의 최신성은 경과 시간 하나로 판정하지 않는다. 접근성은 구조/수요가 그대로이고 현재 기준 자료가 유효하면 오래된 평가 시각이라도 현재 유효할 수 있다. 충족도·신뢰성은 마지막으로 도래한 마감 갱신 주기와 창의 유효성을 확인한다.

최근 **28게임일의 마감 시점 단계 이력**과 관측 상태·평가 기간·기준 변경·확인된 원인을 제공한다. 정밀 점수 선그래프, 빈 구간 보간, 과거 유지값을 새 관측으로 복제하는 표현은 금지한다. 당시 기록을 보존하며 나중 자료가 생겼다는 이유로 과거 표시를 새 평가로 다시 쓰지 않는다. 28일은 표시 범위이고 저장 자료 삭제 기한이 아니다.

### 15.5 종합 단계

내부 서비스 부모값은 §9.2대로 계속 계산하지만 **3개 말단 모두 각자의 갱신 주기와 현재 기준에서 유효할 때만 현재 종합 단계를 표시**한다. 일부만 유효하면 종합은 '평가 대기'와 이유를 표시하고 유효한 개별 단계는 보여 준다. 마지막으로 모두 유효했던 종합 단계는 과거 평가임과 날짜를 명시하여 별도로 제공할 수 있다. 서로 다른 기간의 과거값을 섞은 평균을 현재 종합으로 내보내지 않는다.
