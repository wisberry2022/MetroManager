## 1. Owner 결정으로 확정된 공통 원칙

1. 플레이어 회사의 내재적 상태를 나타내는 수치이며, **각 노드의 값은 0 이상 10 이하, 소수 허용**이다. 범위 밖 값은 가질 수 없다.
2. 값은 게임 시스템 내부에서 지속적으로 보유·평가한다. 플레이어는 **정확한 내부 수치를 직접 확인하지 못한다**. 미래 이벤트 발동 조건, 회사 평판, 실제 플레이 결과 등에 의해 바뀔 수 있다. 정확한 이벤트 효과는 아직 미설계.
3. 값은 **계층형**이다. 자식을 가진 노드의 값은 언제나 *직접 자식값의 산술평균*이다. 자식 수와 계층 깊이(Depth)에 **제한이 없다**. 최상위 7개 카테고리는 Owner 승인이다. 회사 전체 7개를 다시 평균한 단일 종합점수는 **미승인/미정의**.
4. 하위 말단의 **기본 초기값은 5.0**, 실제 평가 근거가 없으면 숫자는 보유하면서도 `UNOBSERVED`(미관측)로 구분한다. **미관측 5.0과 실제 관측 결과 5.0은 다르다.**
5. 향후 난이도별로 **초기값을 다르게 세팅**할 수 있어야 한다. 쉬움·중간·어려움·극한 등에 대한 *실제 초기값 숫자와 프리셋의 세부*는 미결정. 지정된 별도 초기값이 없는 경우 5.0을 기본으로 한다.
6. 점수 방향은 **B안**: 긍정적 성과·상태를 측정하는 **평가형 5개**, 단순한 관계 형성·인식 범위를 측정하는 **규모형 2개**. 규모형의 10은 반드시 좋은 상태/보상이라는 뜻이 아니다.
7. 유관기관 연계율은 **기관과의 관계·교류·업무 협력의 범위/활성화**를 평가하며, 기관의 호감·우호·신뢰·규제 지지 등의 *관계의 질*을 측정하지 않는다. 제재·감시만으로 자동 증가한다고 결정하지 않았으며 유효한 접점/평가식은 후속 정의.
8. 후임 기획은 승인된 내용의 재승인 요청 없이 나머지 카테고리를 정의한다. 이 문서의 등록·PR·병합은 게임 구현/정식 AC/VP 완료나 새로운 수치 승인 자체를 뜻하지 않는다.

### 계층·평균·관측 상태의 구분

- **확정된 산술평균:** `parent.value = sum(direct_child.value) / direct_child.count`. 미관측 자식 역시 **5.0이라는 실제 보유값**을 평균에 포함하는 해석으로 앞선 Planning 설계가 진행되었다. 만약 후속 Owner가 다르게 선택하면 계층 평균 해석을 명시적으로 개정해야 한다.
- **제안된 관측 메타:** 말단 `UNOBSERVED/OBSERVED`, 부모 `UNOBSERVED/PARTIALLY_OBSERVED/OBSERVED`. '미관측을 별도 표시'는 Owner 확정, 이 세 가지 영문 enum/기술 모델과 부분관측의 정확한 데이터 표현은 **후속 상세계약 검토** 대상이다.
- 말단 입력에만 점수 변경을 적용하고 자식이 있는 부모는 평균으로 재산출하는 방향을 따른다. 0~10 범위 보호는 `clamp(value,0,10)`을 사용할 수 있지만 증감량·결합 순서·정밀도·지표/사건 혼합 산식은 후속 승인 대상이다.
- **무제한 Depth의 결과:** 깊이와 각 자식 수가 달라지면 하위의 *실효 영향 비중*이 달라진다. 전체 말단을 일괄 평균하지 않는다. 분기 추가·이동 때 기존 상태값 승계/기본값/관측 취급과 기존 값 변동은 계층 버전 변경으로 명시적 후속 판단 필요.
- 일시정지·조회·중복 수신·배속·일괄/분할 실행만으로 실제 사건이 추가 평가되어서는 안 된다. 특정 게임 시각의 이벤트 적용 순서는 미래 시스템 도입 시 SEM-03와 연결하여 결정해야 한다.

## 4. FIN-01~07 — Owner 채택 평가 기준선

**Owner 결정:** 2026-11-08 Planning 대화에서 **FIN-01~07 기준안을 '이 방향으로 채택'**. FIN-01~06의 *첫 밸런스 수치 기준선*을 승인했고, FIN-07은 **5.0·미관측 및 신용/부채 도입 시 산식 확정**을 승인했다. 기존 산식·앵커는 유지하며 후속 계산·관측, 적용·승계, 정보 전달의 20개 승인 세칙을 §19~21에 통합했다. 현재 C01·채무 미적용 범위의 정책 결정은 완료됐고 실제 데이터 공급·세션 실측은 별도 확인 대상이다.

### FIN-01 운영자금 완충력

- 입력 `A=max(0,F−ΣK)` (기존 승인 원장), `E_d>0`: 유효한 정상 운영계획의 **기준 1게임일 운영비**(실제 일시정지 때문에 0으로 조작되지 않음), `D=A/E_d` 게임일.
- 점수 기준 `D=0 / 3 / 15` → `0 / 5 / 10`, 구간별 선형 보간 및 0~10 제한.
- 식: `S=5D/3` (0≤D≤3), `S=5+5(D−3)/12` (3<D<15), `S=10` (D≥15).
- 현 MVP 단일 노선·06~24시/100통화·게임분 전부 영업의 **설명용 계산**: `E_d=18×60×100=108,000`. 미래 모든 사업/회사에 공통으로 고정되는 비용 기준은 아님.
- 정상 운영계획·기준 비용이 아직 없거나 `E_d=0`이면 **0/10을 임의 부여하지 않는다**. 이력이 없으면 5.0·미관측, 과거 유효값이 있으면 날짜와 함께 유지하고 현재 평가 불가로 구분한다(§19.1, §19.7).

### FIN-02 신규 투자 자금여력

- 입력 `A`, `M>0`: 평가에 쓰는 **기준 신규 사업의 회사 자기부담 필요액**, `Q=A/M`.
- 기준 `Q=0 / 1 / 3` → `0 / 5 / 10`.
- 식: `S=5Q` (0≤Q≤1), `S=5+2.5(Q−1)` (1<Q<3), `S=10` (Q≥3).
- **C01의 기준 M=300,000**으로 확정했다(§19.2). MVP B01 정부금800,000·표준 공사600,000으로 자기부담 M=0인 사례를 사용해 가짜 10점을 만들지 않는다. 다른 시나리오의 양수 기준액은 콘텐츠 추가 때 별도 확정하며, 유효 기준이 없으면 평가하지 않는다.
- 이 점수는 **새 계약 허용 여부**가 아니며, 기존 사업 자격/가용액/K 검사를 대체하지 않는다.

### FIN-03 수익성 공통 환산

- 대상 비용 `E>0`, 대상 매출 `R`: `m=(R−E)/E`; `S_profit=clamp(5+5m,0,10)`.
- 손익률 `m=−100% / 0% / +100%` → `S=0 / 5 / 10`; 사이 연속 선형 보간. `E=0`이면 분모가 없으므로 임의 평가 금지.
- 수익성에서 지급 지연으로 현금 지출이 없더라도 **이미 발생한 비용**은 사라지지 않는다.

### FIN-04 운행 수익성 평가기간

- **최근 7개 마감 게임일의 확정 운영 실적(진행 중 당일 제외)**을 평가기간으로 채택(실제 도착 완료 운임 매출 및 **발생** 운영비).
- `m_ops=(R_fare−E_ops)/E_ops`, `E_ops>0`인 경우 FIN-03 환산식 적용.
- 기존 SEM-03에 따라 운임은 **도착 완료일**, 운영비는 **발생일**에 귀속. 과거 확정 보고를 재작성하거나 현금 지급분으로 발생 비용을 대체하지 않는다.
- **실제 영업 합계 1,080분 이상·양수 발생비·유효 자료**를 최초 평가 조건으로 확정했다. 부분일은 실제 분량만 인정하고, 표본 충족 시 실제 매출0은 손실로 평가한다. 비용0/자료 부족/과거값 유지는 §19.3·§19.7, 과거 자료 승계는 §20.2를 따른다.

### FIN-05 사업 수익성

- 채택한 1차 MVP 범위: **정부 사업비 매출 `G`와 직접 사업비/시공비 `X`**를 구별. `X>0`이고 해당 사업의 평가 대상 비용이 확정됐을 때 `m_project=(G−X)/X` 및 FIN-03 적용.
- **B01 완료 후 설명용 예시:** `G800,000 / X600,000` → 손익률 `1/3`, 점수 `6.666...`. 정부 제한잔액 R200,000이 자유현금으로 자동 전환된다는 뜻이 아님.
- 시공 중 계약 시점의 정부 매출만으로 최종사업 수익성을 확정하지 않는다. 운행 수입·운영비는 FIN-04와 **중복 반영하지 않는** 1차 범위.
- **유효 개통과 매출·직접 비용 확정** 후 평가하며 직접 개통 전 시험·수리비도 포함한다. 회사 설립 이후 요건을 충족한 전체 사업의 매출·비용을 각각 합산한 뒤 FIN-03을 적용한다. 사업별 점수 평균은 사용하지 않는다. 정산 변경은 장래 평가에 반영하고 과거 확정 기록은 보존한다(§19.5~6, §20.4).

### FIN-06 미지급 부담 관리 수준

- `B≥0`: 미지급 **운영비** 잔액, `E_7≥0`: **현재 시각까지 최근 7게임일 발생** 운영비. FIN-04의 마감일 창과 구별한다.
- `max(B,E_7)>0`인 유효 관측 시 `r_B=B/max(B,E_7)`, `S_B=10(1−r_B)`. `B/E_7=100% / 50% / 0%`인 관측 예시에서 `0 / 5 / 10`.
- `B=0,E_7=0`이면 평가 근거가 없으므로 10점 자동 부여 금지. 실제 지급 의무와 유효 자료가 생기면 같은 시각의 정산 완료 뒤 평가하며 1,080분/7일 경과를 기다리지 않는다. 관측 이력/기본 5.0·자료 부족은 §19.4·§19.7, 과거 자료 부족은 §20.3을 따른다.
- 7게임일 B·발생비만으로 연체 지속기간의 모든 위험을 측정하진 못한다. **미지급 지속기간/지급 지연 이력**은 향후 하위 확장 후보일 뿐 승인된 7번째 재정 말단값이 아님.
- FIN-06은 **MVP에서 제외된 B>0 신규 계약 제재나 6개월 연체 제재를 되살리지 않는다**.

### FIN-07 채무 구조 건전성

- **현 적용:** `value=5.0 / UNOBSERVED`.
- 실제 대출·이자·원금·상환·만기 구조는 이번 MVP에 없으며, **채무 구조 건전성 평가 공식은 아직 승인되지 않았다**.
- 향후 신용·부채 시스템이 확정되면 상환능력(상환가능현금흐름/기간 원리금), 부채 규모·만기 집중 등 후보 요소와 0·5·10 앵커를 별도 기획·Owner 승인해야 한다.

## 5. 원천 데이터·효과 충돌 금지

- 기존 MVP 권위 원장: 총현금 `C`, 사업별 제한자금 `Rᵢ`, `F=C−ΣRᵢ`, 자기 예약 `Kᵢ`, `A=max(0,F−ΣKᵢ)`, 운영비 미지급 `B`. 정부 지급은 제한사업 매출·현금 유입으로 인정되지만 R의 용도 제한은 유지.
- 기존 **입찰 재무점수 0~100**, **이행능력 점수**, **승객 만족도 0~100**은 새 회사 내부 상태값 0~10과 **독립**. 새 재정 점수로 기존 입찰 점수/낙찰·정부 승인·요금·원장·OD 수요를 자동 대체·재계산하거나 확률 보정하지 않는다.
- 새 시스템의 역방향 효과(평판·공공심사·신용·안전 이벤트에 작용하는 계수/조건)와 이벤트 소비/재현·SEM-03 단계 추가는 **미승인**. 별도 HQ/Owner 결정 후 실제 구현.
- 재정과 재무위기 대응역량을 구분한다: 전자는 현재 상태, 후자는 위험 **예방/대응 능력**. 서비스 성과와 이용자 신뢰·인지도도 자동 동일 점수로 취급하지 않는다.

## 9. 서비스 수준 1차: 평가 대상과 산식

### 9.1 목적·용어·적용 경계

서비스 수준은 회사가 **지역의 이동을 연결하는지, 실제 승차 요청을 수송하는지, 계획한 운행을 제공하는지**를 구분해 평가한다. 기존 직접 자식인 교통 접근성·수송 충족도·운행 신뢰성 3개를 말단으로 유지한다. 이용자 신뢰도·만족도·입찰 점수와는 별개이며, 이 점수로 기존 운임·수요·입찰·제재를 자동 보정하지 않는다.

| 용어 | 설계상 의미 |
|---|---|
| 기준 수요 | 노선 선택률 `q(T)`, 실제 승차, 용량 제한을 적용하기 전의 유효 잠재 OD 수요 |
| 책임 서비스 지역 | 시나리오가 정한 교통 접근성 평가 지역. 개통한 노선의 역세권과 다름 |
| 여정 | 최초 출발지에서 원래 최종 목적지까지의 이동 1건. 환승해도 하나 |
| 승차 기회 | 실제로 도달한 최초 승차 또는 환승 단계에서, 영업·재무 등 승차 허용 조건을 충족하여 용량 판정을 받은 요청 1건 |
| 실제 운행 단위 | 회사의 독립된 운행 계획·제공 의무를 대표하는 집계 단위. 화면 노선명·개별 열차 수와 다름(§11.2) |
| 승차 허용 조건 | 영업시간, 유효 개통, 운행 가능 상태, 기존 재무 조건 등. 용량 부족과 구분 |
| 확정일 | 일일 마감이 끝난 게임 날짜. 진행 중인 당일은 7일 평가 창에서 제외 |
| 평가 근거 버전 | 지역·수요·연결·실제 운행·산식 등의 의미를 재현하고 비교 가능성을 판정하는 정보. 저장 구조/enum 이름은 DEV 소관 |

이하 기호 `S_A/S_F/S_R`는 서비스 점수이며, 현금 원장의 `A/F/R`과 다르다. **산식과 정확한 점수는 내부 설계·검증용이고 플레이어 공개 UI의 내용이 아니다.**

### 9.2 세 지표와 부모값

| 지표 | 비율의 분자 / 분모 | 내부 점수 | 책임 범위 |
|---|---|---|---|
| 교통 접근성 | 책임 지역 안의 양 끝점을 회사의 개통망으로 연결할 수 있는 기준 OD 수요 / 책임 지역 안의 모든 기준 OD 수요 | `S_A=10a` | 구조적으로 연결되지 않은 수요 |
| 수송 충족도 | 실제 탑승한 승차 기회 수 / 실제 유효 승차 요청 수 | `S_F=L_0.90(f)` | 승차 가능 상태에서의 용량 부족 |
| 운행 신뢰성 | 계획대로 제공한 실제 운행 단위·분 / 제공하기로 계획한 실제 운행 단위·분 | `S_R=L_0.95(r)` | 계획 운행의 미제공. 정시 도착 평가는 제외 |

`L_b(x)=5x/b` (0≤x≤b), `L_b(x)=5+5(x−b)/(1−b)` (b<x≤1).

- 접근성 `0% / 50% / 100%`, 충족도 `0% / 90% / 100%`, 신뢰성 `0% / 95% / 100%`를 각각 내부 점수 `0 / 5 / 10`에 대응시킨다.
- `서비스 수준=(S_A+S_F+S_R)/3`. 하위 보유값이 미관측 기본값/과거 유지값인 경우에도 내부 평균에는 포함한다. **현재 종합 단계의 공개 조건은 별도**로 §15.5를 따른다.
- 충족도와 신뢰성은 먼저 회사 전체의 분자·분모를 각각 합산한 뒤 비율을 구한다. 노선별 비율/점수를 단순 평균하지 않는다. 책임 지역 밖의 정상 회사 운행·실제 요청도 충족도/신뢰성에는 포함한다.
- 분자·분모는 같은 대상·기간·규칙의 자료를 사용한다. 유효 비율은 0~1이고 최종 점수는 0~10이다. 분자>분모 등 불일치를 점수 제한으로 숨기지 말고 새 평가를 보류한다.
- 하나의 실패에 임의의 추가 감점을 중첩하지 않는다. 구조적 미연결은 접근성, 용량 실패는 충족도, 계획 운행 미제공은 신뢰성에 각각 귀속한다. 중도 종료 건수만으로 별도 벌점을 만들지 않는다.

### 9.3 최초 관측·갱신·자료 부족

| 상황 | 접근성 | 충족도·신뢰성 |
|---|---|---|
| 회사의 첫 유효 개통 전 | 5.0·미관측 | 5.0·미관측 |
| 첫 유효 개통 후 | 현재 지역·수요·연결 자료가 완전하면 평가. 개통 또는 공식 구조/수요 변경의 T 처리 완료 뒤 갱신 | 최근 7개 마감 게임일 중 개통 이후의 실제 자료로 평가. 당일 제외 |
| 최소 자료 | 현재 기준 수요의 유효한 양수 분모와 완전한 연결 정보 | 충족도 누적 **100승차 기회 이상**, 신뢰성 누적 **1,080 실제 운행 단위·분 이상** |
| 부분 영업일 | 유효한 현재 구조 평가 | 실제 존재한 부분만 합산. 1일 상당으로 외삽하지 않음 |
| 최초 자료 부족·분모 0 | 평가 불가·기본값 유지 | 5.0·미관측/자료 수집 중 |
| 유효 관측 이후 자료 부족·분모 0 | 마지막 유효값·근거 시점 유지, 현재 평가 불가 표시 | 마지막 유효값·근거 시점 유지, 현재 평가 불가 표시 |
| 누락·손상·불일치 | 새로운 평가 중단, 마지막 유효 근거 또는 미관측 상태 유지 | 동일. 유효한 실적 0과 오류를 구별 |

- 100은 **사람/완료 여정 100명**이 아닌 승차 기회 100건이다. 최초 관측에 7일이 모두 차야 하는 것은 아니다. 다만 추세는 §15.2의 완전한 비교 창 조건을 별도로 적용한다.
- 정상 영업이나 실제 요청이 0이면 충족도는 새 평가를 만들지 않는다. 계획 운행 시간이 충분하고 모두 제공했다면 같은 기간 신뢰성은 10이 될 수 있다. 계획 시간이 양수이고 모두 미제공했다면 신뢰성 비율은 유효한 0이다(최소 표본 충족 필요).
- 미개통·휴업·재개·재로딩만으로 값이 5나 10으로 자동 회복하지 않는다. 일시 중단으로 과거 계획·요청·미제공 이력을 삭제하지 않는다.
- T의 계약/공정/개통/도착/정산/승차 결과를 서로 다른 시점의 자료로 섞지 않는다. 같은 게임 사건·시간에는 조회·일시정지·중복 수신·배속·일괄/분할 진행과 무관하게 같은 평가가 나와야 한다. 실제 저장/호출 단계는 DEV가 기존 SEM-03와 연결해 검증한다.

## 10. 책임 지역·기준 수요·다노선 연결

### 10.1 책임 지역과 수요 변경

1. 책임 지역은 시나리오가 정한 지역이며 **OD의 출발지와 목적지가 모두 안에 있을 때** 접근성 분모에 포함한다. 중간 경로가 지역 밖을 지나도 양 끝점이 안이면 인정한다.
2. 개통 지역만 책임 지역으로 삼지 않는다. 노선 개통·폐지·이름 변경·일시 중단으로 분모를 줄일 수 없다. 사전에 정한 시나리오 사건만 지역을 변경한다.
3. 기준 수요에는 공식 상시 변화와 유효기간이 있는 임시 변화가 효력 시점에 반영된다. `q(T)`나 실제 승차·용량·중단으로 이미 줄어든 수요를 접근성 분모에 넣지 않는다.
4. 한 OD를 여러 역·노선·환승 경로가 연결해도 그 기준 수요를 한 번만 센다. 동일 동의 복수 역에 수요를 복제하지 않는다.
5. 새 지역/수요는 해당 T 사건 처리가 완료된 일관된 자료로 즉시 반영한다. 유예기간·임의 보정·점수 초기화·기존 7일 실적 삭제는 없다. 기존 보고와 과거 평가의 당시 기준을 보존한다.
6. 새 기준의 필수 데이터가 없으면 마지막 유효값을 유지하고 현재 평가 자료 부족을 알린다. 새 분모와 옛 연결 결과를 섞어 임시 점수를 만들지 않는다.

### 10.2 연결 인정과 경로 선택

- 같은 회사의 **유효 개통된 서로 다른 실제 운행**이 동일 역 ID를 정차역으로 공유하고, 필요한 승하차·진행 방향을 허용하면 역내 환승을 인정한다. 별도 환승 시설 건설·해금은 1차에서 요구하지 않는다.
- 정차하지 않는 통과역, 진행 불가능한 방향, 미개통 구간을 연결로 인정하지 않는다. 계획상 연결과 일시적인 실제 운행 제한을 분리한다. 일시 영업/재무 중단만으로 구조적 접근성을 삭제하지 않는다.
- 다른 역 ID끼리는 같은 동·같은 역명·인접 간선이라는 이유로 도보 연결하지 않는다. 다른 회사의 노선은 1차 연결망에서 제외한다.
- 유효한 회사 경로는 환승 횟수의 임의 상한 없이 고려한다. 무의미한 반복 순환을 수요/환승으로 생성하지 않는다. 같은 실제 운행을 타고 계속 가는 중 표시명만 바뀌면 환승이 아니다.
- 여정 생성 시 **예상 총 이동시간 최소 → 환승 횟수 최소 → 안정된 역/노선 ID 순서**로 경로 하나를 정한다. 모든 후보를 독립 수요로 만들지 않는다.
- 예상 총 이동시간은 기존 간선 이동시간·중간역 정차시간에 **실제 환승마다 이동 2분+정상 대기 1분**을 더한다. 최초 승차에 이 1분을 추가하지 않는다.
- 계획상 각 신규 승차는 해당 운행의 영업시간 안이어야 한다. 마지막 구간의 목적지 도착은 영업 종료 후라도 가능하다. 계획된 밤샘 환승 대기를 경로로 만들지 않는다.
- `q(T)`는 이 전체 예상 시간에 **한 번만** 적용한다. 이후 실제 추가 대기·지연 때문에 원래 요청량이나 선택률을 소급 재계산하지 않는다.

## 11. 환승 콘텐츠와 실제 운행의 동일성

### 11.1 첫 콘텐츠 기준

| 사례 | 판정 |
|---|---|
| P-A `S01→S02→S03→S04→S08→S12`, P-B `S01→S05→S09→S10→S11→S12`가 각각 독립 운행으로 개통 | 공통 정차역 S01·S12에서 환승 가능. 필요한 방향의 승하차가 허용되어야 함 |
| 미래 다른 회사 내 노선들이 다른 역 ID를 공통 정차역으로 공유 | 동일 규칙 적용. S01·S12만 영구 허용하는 목록이 아님 |
| S08↔S12(둘 다 D08), S05↔S09(둘 다 D05) | 다른 역 ID이므로 기본 도보 환승 없음. 실제 개통된 구간을 타는 것과 구분 |
| 선로가 만남·같은 동·같은 역명이나 공통 정차/승하차 불가 | 환승 불가 |
| 동일한 실제 운행의 노선 표시명만 전환 | 계속 승차. 추가 환승 시간·승차 기회·운임 없음 |

경로 예: 승인된 간선/정차 시간을 쓰면 P-A의 S04→S01 5분, 역내 환승 3분, P-B의 S01→S05 1분으로 총 9분이다. S04→S12 3분, 환승 3분, P-B의 S12→S09 5분은 총 11분이다. 서로 다른 목적 역으로 같은 목적 동에 접근할 수 있어도 동 수요를 복제하지 않고 더 짧은 유효 전체 경로를 선택한다.

### 11.2 같은 실제 운행과 독립 운행

**기준은 표기가 아니라 회사의 공식 운행 계획과 실제 제공 의무다.** 경로·정차·방향·운행시간 및 실제 수송 기회/용량 사용을 추적한다.

| 판정 | 기준과 집계 결과 |
|---|---|
| 동일 실제 운행의 별칭 | 같은 계획·실제 수송 기회·자원 사용 1회·운행 제공 의무 1건을 가리킴. 신뢰성 분모/분자, 요청/탑승을 중복 생성하지 않음 |
| 기존 운행의 증편·차량 교체·시간표 변경 | 개별 차량·출발편·방향 표시마다 새 노선 분모를 만들지 않는다. 실질적 계획 변경은 효력 시점과 변경 이력으로 반영 |
| 독립 운행 | 서로 다른 운행 계획과 제공 의무가 실제 존재. 같은 선로·역·차량·차량기지·재원·용량 풀을 공유하거나 동시에 중단되었다는 이유만으로 합치지 않음 |
| 실제 계획의 분리·통합 | 효력 이후의 실질 제공 의무에 반영. 과거 계획/중단·7일 창을 소급 삭제하거나 이름 변경으로 평가를 리셋하지 않음 |

- P-A/P-B가 독립 운행이면 신뢰성은 각 계획 시간을 합산한다. 이것만으로 수송 용량·차량·운영비가 두 배 승인되는 것은 아니다. **자원 공급 규칙은 기존 권위 계획과 실제 공유 관계를 따른다.**
- 동일한 용량 풀을 여러 표기가 참조해도 각 호출마다 용량을 새로 지급하지 않는다. 독립 운행 여부와 공유 용량 여부는 별도 정보다.
- 신뢰성의 한 운행 단위·분은 **그 분에 계획상 필요한 경로·정차·운행 범위를 모두 제공**했을 때 1이다. 필요한 일부가 빠지면 그 분은 0으로 집계한다. 부분 제공 비율로 0.5 등을 주지 않는다.
- 일부 미제공으로 신뢰성 0분이 되더라도 실제로 제공 중인 나머지 구간을 강제로 정지시키거나 정상 승차 실적을 지우지 않는다. 용량이 꽉 찬 상태 자체는 운행 미제공이 아니다.

## 12. 여정 상태·환승 대기·운임·종료

### 12.1 환승 시각과 대기 처리

환승 단계의 앞 구간 도착 시각을 `t_arrival`, 환승 준비 완료를 `t_ready=t_arrival+2`로 둔다. 최초 용량 판정 가능 시각은 `t_ready+1`, 최종 대기 기한은 `t_ready+5`다. 5분에는 정상 대기 1분이 포함된다.

| 상황 | 처리 | 충족도 반영 |
|---|---|---|
| 준비 중·정상 대기 중 | 아직 승차 판정 없음 | 요청으로 먼저 생성하지 않음 |
| 최초 판정 가능 이후 승차 허용 조건이 닫힘 | 최종 기한까지 기다릴 수 있음 | 아직 유효 승차 요청이 아님. 제한 원인은 별도 기록 |
| 허용 조건 충족, 용량 있음 | 해당 단계 1회 탑승 | 요청 1·탑승 1 |
| 허용 조건 충족, 용량 부족 | 그 단계 실패로 즉시 종료. 다음 분 재시도 없음 | 요청 1·탑승 0 |
| 최종 기한 T에 허용 조건 회복 | 정상 T 처리 후 마지막 판정 기회 제공 | 위 성공/용량 실패 중 하나 |
| 최종 기한 T 처리 후에도 허용 불가 | 대기 만료로 중도 종료 | 가상의 용량 실패 요청을 추가하지 않음 |
| 최종 기한 다음에 회복 | 이미 종료한 여정을 부활시키지 않음 | 재요청 없음 |

예: 10:00 도착 → 10:02 준비 완료 → 10:03 최초 판정 → 10:07 마지막 판정 후 만료. 10:07 회복은 인정하고 10:08 회복은 늦다. 일시정지는 게임 시간을 멈추며, 자정·영업 종료·재로딩은 기한을 늘리거나 초기화하지 않는다.

### 12.2 경쟁 순서·경로 고정·일자 귀속

- 같은 실제 용량을 경쟁하는 대기자는 **준비 완료 시각 → OD ID → 여정 생성 순서**로 처리한다. 신규 최초 승차는 현재 시각을 준비 시각으로 보며 더 오래 기다린 환승자와 같은 기준으로 경쟁한다. 아직 정상 대기 1분이 끝나지 않은 환승자는 판정 대상이 아니다.
- 용량은 공유 풀 단위로 1회 소모한다. 별칭·경로 후보·여러 조회 호출로 복제하지 않는다. 실제 첫 용량 판정 후 용량 부족은 기다리거나 다른 경로로 재시도할 권리가 되지 않는다.
- 여정 생성 후 경로를 고정한다. 자동 우회·재탐색은 1차에서 하지 않는다. 다음 연결이 무효가 되어도 이미 승차한 현재 구간의 정상 도착 처리는 보존하며, 원래 목적지에 도착했다고 꾸미지 않는다.
- 최초 승차 실패는 **미시작**이다. 최초 승차 이후의 용량 실패·대기 만료·유효한 다음 연결 소멸은 **중도 종료**다. 자료 누락 자체를 실제 연결 소멸이나 강제 종료로 추정하지 않는다.
- 앞 단계 실패 후 아직 도달하지 않은 환승 단계의 요청은 생성하지 않는다. 한 여정이 여러 실제 단계에 도달하면 단계별 승차 기회는 각각 셀 수 있지만 동일 단계는 한 번만 센다.
- 승차 기회는 실제 판정일, 탑승은 실제 탑승일, 최종 운임은 최종 도착일에 기록한다. 자정 때문에 완료 전의 미래 단계를 앞 날짜에 배분하거나 마감 보고를 다시 쓰지 않는다.

### 12.3 운임과 회계

1. 회사 내 한 여정의 **기본 운임은 한 번**이다. 환승 횟수별 추가 운임을 만들지 않는다. 현재 쉬움 운임 100은 예시 기준이며 새 난이도 공통 운임표를 승인한 것은 아니다.
2. **최초 성공 승차 시점의 운임을 고정**한다. 이 시점에는 선결제·매출·미수금을 만들지 않는다. 환승 중 운임이 바뀌어도 해당 여정의 운임은 바꾸지 않는다.
3. **원래 최종 목적지 도착 완료 때 1회 징수·매출 인식**한다. 중간 환승역 도착은 과금 사건이 아니다. 기존 SEM-03의 도착일 귀속·도착 운임 유입→B 우선 정산→신규 승차 순서와 R/K 보호를 유지한다.
4. 최초 승차 실패, 승차 후 중도 종료에는 운임 0이다. 부분 이용 운임을 징수하지 않는다. 이미 발생한 운영비·성공한 과거 승차 실적은 남는다.
5. 지연되어도 최종 완료하면 고정 운임 전액을 징수한다. 지연 할인·환불·자동 현금 보상은 1차에 없다. 원래 징수하지 않은 운임은 **미징수**이지 환불이 아니다. 오류 중복 징수의 원장 정정은 정상 환불 콘텐츠와 구별한다.

중간 환승역에 도착한 여정은 종료하지 않고 이동/대기/다음 승차 상태로 이어진다. 마지막 구간이 영업 종료 후 도착해도 정상 완료·운임 인식한다. 잔여 승객 도착만으로 추가 영업 운영비를 생성한다는 뜻은 아니다.

### 12.4 보존 관계

- `기초 진행 중 여정 + 신규 최초 탑승 여정 = 최종 완료 + 중도 종료 + 기말 진행 중 여정`.
- 진행 중에는 탑승·환승 이동·대기 상태가 모두 포함된다. 현재 MVP의 '차내 승객'만으로 전체 진행 중 여정을 대체하지 않는다.
- 단계별 `유효 요청 = 탑승 + 용량 실패`를 중복 없는 같은 자료 범위에서 확인한다. 허용 조건 대기·기한 만료·미도달 미래 단계는 이 등식의 가상 요청으로 넣지 않는다.
- 예: 100여정이 첫 구간에 모두 탑승하고 둘째 구간에서 80탑승/20용량 실패하면 요청 200·탑승 180, 충족도 90%→내부 5점이다. 최종 완료 80·중도 종료 20이며 운임 100 기준 매출은 8,000이다. 종료 20건을 이유로 첫 성공 탑승 100건을 취소하지 않는다.

## 13. C01 서비스 확장 시나리오

### 13.1 별도 시나리오와 지역 확장

서비스 지역 확장 콘텐츠는 **새로 선택하는 별도 C01 시나리오**에 적용한다. 기존 C01 기본 시나리오와 기존 세이브를 이 시나리오로 자동 전환하지 않는다. `T0`는 시나리오 시작 시각이며 첫 개통일·점수 관측일이 아니다.

C01의 전체 역과 실제 잠재 수요는 시작부터 존재한다. 단계별로 바뀌는 것은 접근성의 책임 평가 지역이다. 평가 지역 밖 운행도 정상 사업/관할 규칙을 따라 가능하며, 해당 회사의 충족도·신뢰성 실적에는 포함된다.

| 효력 시각 | 접근성 책임 지역 | 다른 수요 변화가 없을 때 기준 분모 | P-A만 유효 연결된 경우 연결 수요 / 점수 |
|---|---|---:|---|
| T0 | G01·G02 = D01~D04 | 4,700 | 4,700 / 10 |
| T0+7게임일 | G03 추가 = D01~D06 | 6,100 | 4,700 / 7.704918… |
| T0+14게임일 | G04 추가 = D01~D08 | 7,000 | 4,900 / 7 |

검산 근거는 DATA의 출발 수요 `D01~D08=[2000,1500,1200,800,600,400,300,200]`, 목적지 다음 동 순환(D08→D01)이다. 양 끝점이 책임 지역 안인 OD만 합산하므로 초기에는 D04→D05를 제외한다. P-A 연결 동은 D01~D04·D08이며 전체 지역에서는 D08→D01의 200이 더해진다. 표는 **이미 유효 개통되어 관측 가능한 조건**의 기대값이다. 미개통이면 예정 시나리오 수요만으로 미관측 5.0을 관측 점수로 바꾸지 않는다.

### 13.2 임시 수요 사건

- `[T0+21게임일, T0+28게임일)` 동안 **D05→D06 잠재 수요에 하루 기준 +300**을 더한다. 시작은 포함하고 종료는 제외한다.
- 다른 유효 수요 규칙을 적용한 권위 기준 수요에 이 사건의 +300을 **가산**한다. 이 사건을 배수로 적용하거나 다른 사건의 효과와 함께 지우지 않는다.
- 다른 변화가 없으면 해당 OD는 600→900→600, 전체 기준 수요는 7,000→7,300→7,000이다. P-A만 연결된 상태의 사건 중 접근성은 `10×4900/7300=6.712328…`이다.
- 사건 종료 때 자기 가산 300만 제거한다. 다른 사건이 남아 있으면 무조건 600으로 되돌리지 않는다. 기존 일반 수요 사건의 결합 산식을 이 콘텐츠만으로 재정의하지 않는다.
- 실제 요청 생성과 접근성 평가가 같은 유효 잠재 수요를 사용한다. 실제 요청의 `q(T)`·시간대 배분·소수 이월은 이후 단계다. 과거 미처리 요청을 소급 생성하거나 저장/불러오기 때 사건을 재적용하지 않는다.
- 지역 확장과 임시 수요 일정·효력은 사전에 플레이어에게 알린다. 이벤트로 인한 점수 변화 외에 자동 벌금·보상·강제 계약을 추가하지 않는다.

## 14. 적용 개시·세이브·과거 실적 승계

### 14.1 적용 시점과 버전 판정

`τ`는 세이브를 정상 복구·검증한 **마지막 처리 완료 게임 시점**이다. 도입을 위해 게임 시간을 인위적으로 진행하거나 이미 처리한 T를 재생하지 않는다. 이후 미처리 대상에 새 규칙을 적용한다. 신규 게임도 시나리오 시작 정보와 적용 규칙을 함께 식별한다.

| 자료 상태 | 현재 평가로의 승계 |
|---|---|
| 이 시스템 최초 도입 | 이미 개통했고 현재 권위 자료가 완전하면 접근성은 현재 상태로 평가. 충족도·신뢰성은 5.0·미관측으로 시작하여 적용 이후의 실제 실적만 수집 |
| 같은 의미·호환 버전의 유효 평가/실적 | 값·평가 기간·최초 관측·마지막 유효 시점·적용 기준을 유지. 재로딩이 새 최초 도입이 되지 않음 |
| 같은 의미의 과거 유효값은 있으나 현재 자료 부족 | 과거값과 날짜 유지, 현재 자료 부족 표시. 과거값을 새로운 관측으로 재발행하지 않음 |
| 비호환이거나 의미를 확인할 수 없는 구버전 점수 | 구버전 기록으로 보존하되 현재 평가/추세에 혼합하지 않음. 접근성은 유효한 현재 자료로 재평가 가능, 충족도·신뢰성은 새 규칙 5.0·미관측에서 수집 |

기존 합계 보고·예측치만으로 과거의 실제 단계별 요청, 계획/제공 시간을 추정해 채우지 않는다. 과거 보고는 당시 규칙과 수치 그대로 보존한다. 이 규칙은 서비스 수준 범위이며 FIN의 미결 관측 세칙을 대신 확정하지 않는다.

### 14.2 최초 창·기존 진행 여정

- 충족도·신뢰성은 적용 후 최근 7개 마감 게임일의 해당 실제 구간만 사용한다. 최소 100기회/1,080분은 동일하며, 적용 전 자료를 끌어와 표본을 채우지 않는다.
- 예: 단일 06~24시 운행에 12:00부터 처음 적용했다면 그날 720분은 실제 표본으로 남지만 신뢰성 최초 관측의 1,080분에 아직 미달한다. 1,080분으로 외삽하지 않는다.
- `τ` 전에 진행 중인 여정은 **원래 규칙으로 종료까지 처리**한다. 기존 경로·운임·대기 기한·도착을 보존하고 강제 재시작·강제 종료·재과금하지 않는다. 새 규칙에 없던 대기 기한을 옛 여정에 소급 부여하지 않는다.
- `τ` 이후 새로 생성한 여정은 새 규칙을 사용한다. 최초 도입 시 충족도에는 **새 규칙 여정의 실제 승차 기회만** 포함한다. 옛 여정이 실제로 차지하는 용량은 그대로 소모된다. 신뢰성은 승객 규칙 버전과 별개로 적용 이후의 실제 운행 제공 시간을 평가한다.
- 기존 시나리오는 시나리오·게임 시간을 유지한다. 이미 지난 +7일/+14일을 새 시나리오 사건으로 강제 재생하지 않는다.

### 14.3 저장 안전성과 반복 실행

- 원본 세이브를 보존하고 별도의 변환 사본을 검증한 후 전환 완료로 취급한다. 일부 변환만 성공한 상태를 정상 플레이 가능한 현재 상태로 인정하지 않는다.
- `τ`, 시나리오 `T0`, 이미 소비된 사건, 여정 기한, 최초 개통, 관측 창, 과거 평가 상태를 보존한다. 같은 저장본의 재로딩으로 지역 확대/수요 사건을 중복 적용하거나 평가 표본을 초기화하지 않는다.
- 기존 C/R/F/K/A/B 원장, 공사·시험·기성/미지급, 소수 수요 이월을 서비스 설계 도입 때문에 재생성하거나 재결제하지 않는다.
- 실제 저장 형식·변환 절차·복구 가능성은 **미검증**이다. 이 절은 제품 동작 기준이며 현재 세이브가 이미 이를 지원한다는 진술이 아니다.

## 15. 플레이어 정보 전달 계약

### 15.1 단계와 비공개 원칙

3개 말단과 서비스 수준 부모에 같은 5단계를 사용한다. 아래 경계는 내부 검수용이다.

| 내부 범위 | 표시 단계 |
|---|---|
| 0≤값<2 | 취약 |
| 2≤값<4 | 미흡 |
| 4≤값<6 | 보통 |
| 6≤값<8 | 양호 |
| 8≤값≤10 | 우수 |

- 플레이어 화면·도움말·툴팁·알림·평가 내보내기에 **정확한 내부 점수, 경계 수치, 점수 산식**을 공개하지 않는다. 동일 단계 안에서 막대 길이·좌표·색상 세기 등을 세밀하게 바꾸어 정확한 점수를 드러내지 않는다.
- 기존 운영 보고가 공개해 온 실제 승객 수·매출 등 사실 수치의 공개 범위를 축소하거나 새 점수 공개로 확대하지 않는다. 내부 설계서/개발 검증 자료의 수식과 플레이어 제품 표시는 구분한다.
- 기본값 5.0·미관측을 '보통'으로 표시하지 않는다. 관측된 5점만 해당 단계를 갖는다.

### 15.2 추세

- 현재 유효 단계와 **7게임일 전의 유효 단계**를 비교해 높은 단계면 '개선', 같으면 '비슷한 수준', 낮으면 '악화'로 표시한다. 같은 단계는 정확한 점수가 같다는 뜻이 아니다.
- 충족도·신뢰성은 양 비교 시점 모두 **각각 완전한 최근 7개 마감일 자료**와 유효 평가가 있어야 한다. 최소 표본 충족만으로 현재 단계는 먼저 보여 줄 수 있어도 추세는 더 늦게 열릴 수 있다.
- 비교값 없음/자료 부족이면 '비교 자료 수집 중', 관련 기준 변경으로 의미가 달라졌으면 '기준 변경으로 비교 보류'를 표시한다. 과거 유지값을 오늘의 새 관측으로 삼지 않는다.
- 지역·수요 변경이 접근성 비교 기준을 바꾸더라도 회사 전체 실적 의미가 동일한 충족도·신뢰성 추세까지 자동 중단하지 않는다. 지표별로 비교 가능성을 판단한다.

### 15.3 원인과 현재 운행 제한

- **확인된 사실만 최대 2개**를 제시한다. 우선순위는 기준 변경 → 미충족/미제공 → 개선 사실이다. 근거가 없는 점수 기여율·인과를 추정하지 않는다.
- 새 역이 생겨도 새로 연결된 OD가 없으면 접근성 개선이라고 말하지 않는다. 운행 제한으로 기다리다 끝난 여정을 용량 부족으로 설명하지 않는다. 부분 운행 미제공으로 그 분의 신뢰성 집계가 0이어도 전 노선의 실제 정지라고 표현하지 않는다.
- 평가 기간의 원인과 **현재 운행 제한**을 구분한다. 최근 7일의 좋은 단계와 현재 중단 사실이 동시에 존재할 수 있다. 현재 중단을 알리기 위해 과거 평가를 덮어쓰지 않는다.
- 원인 자료가 없으면 '상세 사유 확인 불가'로 표시한다. 부족한 원인 자료를 임의의 설명으로 메우지 않는다.

### 15.4 관측 상태와 28일 이력

| 구별할 상태 | 플레이어에게 전달할 의미 |
|---|---|
| 미관측 | 아직 평가할 수 없음. 기본 숫자를 단계로 노출하지 않음 |
| 최초 표본 부족 | 자료 수집 중. 현재 평가 단계가 아직 없음 |
| 현재 유효 평가 | 해당 지표의 주기와 현재 기준에 맞는 평가 |
| 과거 유효값 유지 + 현재 자료 부족 | 마지막 평가 단계·당시 날짜와 현재 평가 불가 사유를 함께 전달 |
| 자료 오류/불일치 | 현재 평가 보류. 실적 0으로 오해시키지 않음 |
| 유효한 실적 0 | 정상 관측된 낮은 결과. 자료 없음으로 숨기지 않음 |
| 기준 변경 | 새 평가 기준 및 비교 제한을 알림. 자동 초기화 의미가 아님 |

상태 구분은 승인 사항이지만 화면 문구의 세부 표현·색상·아이콘·배치는 Design 소관이다. 정보의 최신성은 경과 시간 하나로 판정하지 않는다. 접근성은 구조/수요가 그대로이고 현재 기준 자료가 유효하면 오래된 평가 시각이라도 현재 유효할 수 있다. 충족도·신뢰성은 마지막으로 도래한 마감 갱신 주기와 창의 유효성을 확인한다.

최근 **28게임일의 마감 시점 단계 이력**과 관측 상태·평가 기간·기준 변경·확인된 원인을 제공한다. 정밀 점수 선그래프, 빈 구간 보간, 과거 유지값을 새 관측으로 복제하는 표현은 금지한다. 당시 기록을 보존하며 나중 자료가 생겼다는 이유로 과거 표시를 새 평가로 다시 쓰지 않는다. 28일은 표시 범위이고 저장 자료 삭제 기한이 아니다.

### 15.5 종합 단계

내부 서비스 부모값은 §9.2대로 계속 계산하지만 **3개 말단 모두 각자의 갱신 주기와 현재 기준에서 유효할 때만 현재 종합 단계를 표시**한다. 일부만 유효하면 종합은 '평가 대기'와 이유를 표시하고 유효한 개별 단계는 보여 준다. 마지막으로 모두 유효했던 종합 단계는 과거 평가임과 날짜를 명시하여 별도로 제공할 수 있다. 서로 다른 기간의 과거값을 섞은 평균을 현재 종합으로 내보내지 않는다.

### 19.1 정상 운영비 기준

운영자금 완충력은 현재 유효한 정상 운영계획을 하루 수행하는 데 필요한 운영비를 기준으로 평가한다. 일시 중단이나 자금 부족으로 실제 지출이 줄어도 기준 운영비를 줄이지 않는다. 정식 계획이나 비용 단가가 변경되면 그 효력 시점부터 반영한다.

여러 운행은 실제 비용 부담을 합산하되 같은 운행의 별칭 때문에 중복 계산하지 않는다. 공사비·수리비는 하루 운영비에 섞지 않는다. 정상 운영계획이 없으면 평가를 기다리며, 과거 유효값이 있는 경우에는 세칙 7을 적용한다.

현재 단일 운행의 06~24시·분당 100 기준 예시는 하루 108,000이다. 실제 가용자금 324,000이면 3일분이다. 108,000을 모든 미래 운행의 고정 비용으로 사용하는 것은 아니다.

### 19.2 기준 투자액

C01의 첫 기준 사업 자기부담액을 300,000으로 정한다. 같은 시나리오에서는 고정하며 플레이어가 선택한 실제 사업의 가격에 따라 낮추지 않는다.

가용자금 300,000이면 기준 사업 1건분, 900,000이면 3건분으로 기존 FIN-02 산식에 대입한다. 기준액과 자금 자료가 유효하면 개통 전에도 평가할 수 있다.

이 금액은 투자 여력을 비교하기 위한 기준이다. 실제 계약에 새 비용·예약금·의무 보유금·계약 제한을 부과하지 않는다. 다른 시나리오에 같은 금액을 일괄 적용하는 것은 이번 승인에 포함하지 않는다.

### 19.3 운행 수익성의 평가 기간과 최소 표본

최근 7개 마감 게임일의 확정 실적을 사용하며 진행 중인 당일은 제외한다. 그 기간에 실제 영업한 운행시간이 합계 1,080분 이상이고 발생 운영비가 양수일 때 평가한다.

독립 운행은 실제 영업시간을 합산하고 동일 운행은 중복 계산하지 않는다. 비용이 발생하지 않는 중단 시간이나 기존 승객의 잔여 도착만으로 표본을 채우지 않는다. 부분 영업일은 실제 분량만 보존하며 하루치로 외삽하지 않는다.

정오 개통 후 자정까지 영업했다면 720분으로 최초 표본에 미달한다. 표본이 충분하면 승객·매출이 0이어도 실제 비용에 따른 손실로 평가한다. 운임은 최종 도착일, 운영비는 발생일에 귀속하고 기존 마감 보고를 재작성하지 않는다.

이 1,080분은 재정에서 새로 승인한 실제 영업 표본이다. 서비스 수준 운행 신뢰성의 계획 운행시간 표본과 의미가 다르다.

### 19.4 미지급 부담의 평가 개시와 갱신

실제 운영비 지급 의무가 발생하고 자료가 유효하면 평가를 시작한다. 최소 영업 1,080분이나 7일 경과를 기다리지 않는다.

현재 남은 미지급 운영비와 현재 시각까지 최근 7게임일의 실제 발생 운영비를 함께 사용한다. 새 비용 발생·지급·자동 정산 등 같은 시각의 처리가 끝난 상태에서 갱신한다. 처리 중 잠깐 생겼다가 바로 정산된 잔액을 별도 미지급 상태로 남기지 않는다.

최근 발생 운영비가 0이어도 과거 미지급이 남아 있으면 기존 산식으로 평가한다. 비용 발생도 미지급도 없는 상태를 자동 만점으로 처리하지 않는다. 공사 미지급은 운영비 미지급과 구별하며 새로운 벌금·계약 제재를 추가하지 않는다.

### 19.5 개별 사업의 평가 가능 시점과 비용 범위

유효 개통을 완료하고 해당 사업의 평가 대상 매출·직접 비용이 확정됐을 때 처음 평가한다. 기존 수익성 산식의 양수 비용 조건도 유지한다.

시공비와 해당 사업에 직접 발생한 개통 전 시험·결함 수리비를 포함한다. 실제 발생하지 않은 비용은 만들지 않는다. 개통 후 운임과 운영비는 운행 수익성에서 평가하며 사업 수익성에 중복 반영하지 않는다.

정부 사업비만 받은 시점이나 공사만 끝내고 안전검증이 남은 시점에는 최종 사업 수익성을 확정하지 않는다. 중단·미개통 사업은 진행 중으로 구분한다.

### 19.6 여러 사업의 합산과 정산 변경

회사 설립 이후 평가 요건을 충족한 사업 전체의 매출·비용을 각각 합산한 뒤 기존 수익성 산식에 넣는다. 사업별 점수를 단순 평균하거나 최근 3개 사업만 남기는 방식은 채택하지 않는다.

새 사업이 없다는 이유로 기존 실적을 제외하거나 초기화하지 않는다. 유효한 정산 변경이 발생하면 그 시점 이후 평가에 반영하고, 과거 확정 평가 기록은 보존한다.

예를 들어 한 사업에서 200,000을 벌고 다른 사업에서 200,000을 잃었다면 합산 성과는 손익분기점이다. 이 예시는 합산 원리를 설명하는 것이며 실제 사업 금액을 추가한 것이 아니다.

### 19.7 미관측과 자료 부족

| 상태 | 확정 처리 |
|---|---|
| 유효한 평가 이력이 없음 | 기본값 5.0을 보유하며 미관측으로 구분 |
| 과거 유효 평가가 있으나 현재 자료 부족 | 마지막 유효값과 당시 날짜를 유지하고 현재 평가 불가 상태로 구분 |
| 자료가 충분하고 실제 결과가 0 | 정상적인 평가 결과로 반영 |
| 자료 누락·오류·불일치 | 실적 0으로 추정하지 않음. 유효한 새 평가를 만들지 않음 |

휴업 등으로 최근 표본이 부족해져도 값이 자동으로 5나 10으로 회복하지 않는다. 누적 사업 수익성은 새 사업이 없더라도 기존 대상 자료가 유효하면 계속 계산할 수 있다. 새 사건이 없음과 자료 부족을 구분한다.

### 19.8 중간 반올림 금지

비율과 하위 점수는 중간 반올림 없이 계산하고 부모 평균에 전달한다. 평가 경계도 반올림 전 값을 기준으로 판정한다. 저장·계산 형식은 이 결과를 재현하도록 개발팀에서 설계할 사항이다.

정확한 내부 점수는 플레이어에게 공개하지 않는다. 이 세칙만으로 재정의 단계명·추세·종합 표시 방식까지 확정한 것은 아니다.

## 20. 재정 적용 개시·기존 세이브·과거 실적 승계

### 20.1 적용 시작 시점

기존 세이브는 정상 복구·검증 후 마지막 처리가 완료된 게임 시점부터 새 재정 평가를 적용한다. 새 게임은 초기 자금·시나리오 설정이 완료된 시점부터 적용한다. 이하 이 최초 적용 시점을 적용 시작점이라 한다.

도입을 위해 시간을 다음 날로 넘기거나 이미 끝난 거래를 다시 처리하지 않는다. 현재 자료가 충분하면 운영자금 완충력·투자 여력을 즉시 평가한다. 정상 운영계획이 없거나 다른 평가 자료가 부족한 항목에는 기존 미관측·과거값 유지 규칙을 적용한다.

예를 들어 게임 20일째 12시의 정상 저장본을 불러오면 그 시간과 자금을 유지한 채 평가한다. 도입 때문에 운영비를 추가 청구하거나 정부 사업비를 다시 지급하지 않는다.

### 20.2 과거 운행 실적의 인정

최근 7개 마감일의 실제 운임 매출·발생 운영비·실제 영업시간이 새 기준에 맞게 빠짐없이 확인되는 과거 실적은 인정한다. 1,080분과 양수 발생비 조건도 충족하면 불러오기 직후 운행 수익성을 평가할 수 있다. 플레이 기간이 7일보다 짧으면 실제 존재하는 기간을 확인한다.

과거 자료가 불완전하면 적용 시작점 이후부터 새로 모은다. 확인되는 좋은 날짜만 골라 가져오거나 누락 비용을 0으로 채우지 않는다. 총손익만으로 영업시간이나 비용을 추정하지 않는다.

과거 자료가 없는 단일 운행에 정오부터 적용했다면 자정까지 실제 영업한 720분만 첫 마감에 기록한다. 아직 1,080분 미만이므로 자료 수집 중이다. 진행 중인 당일 제외·실제 부분일 기록·발생일/도착일 귀속은 기존 세칙을 유지한다.

### 20.3 미지급은 보존하고 부족한 평가만 보류

현재 미지급 운영비와 현재까지 최근 7게임일 발생비가 확인되면 즉시 평가한다. 과거 비용 기록이 부족하면 미지급 부담의 새 평가만 보류한다. 같은 기준의 과거 유효값이 있으면 날짜와 함께 유지하고, 없으면 기본값 5.0·미관측으로 둔다.

실제 미지급액과 기존 정산·운행 제한은 계속 유지한다. 자료 부족을 이유로 미지급을 없애거나, 과거 비용을 0으로 가정해 낮은 점수를 부여하지 않는다. 자료가 충분한 다른 재정 항목은 평가할 수 있다.

과거의 빈 구간이 평가 대상에서 완전히 빠지는 데 최대 7게임일이 걸릴 수 있다. 이는 신규 최소 영업기간이 아니다. 완전한 자료가 확보된 뒤에도 비용 발생과 미지급이 모두 0이면 기존 평가 근거 없음 규칙을 따른다.

### 20.4 사업별 기록을 확인한 누적 승계

과거 사업은 사업별로 평가 자격과 금액을 확인하여 승계한다. 유효 개통·매출 확정·직접 비용 확정 조건을 충족한 과거 사업도 회사 설립 이후 누적 합산에 포함한다. 사업별 내역이 부족한 상태에서 전체 합계만 검증해 승계하는 대안은 채택하지 않았다.

진행 중 사업은 도입 전후의 기록을 이어 붙인다. 도입 전 정부 사업비 800,000, 도입 전 공사비 400,000, 도입 후 추가 공사비 200,000이면 평가 요건 충족 시 매출 800,000·비용 600,000으로 계산한다.

과거 평가 대상 사업 일부의 자료가 빠졌다면 확인된 사업만으로 회사 전체 누적 사업 수익성을 확정하지 않는다. 해당 평가를 보류한다. 과거 자료를 복구하지 못하면 이 항목의 평가 불가 상태가 계속될 수 있으며, 최근 실적만으로 회사 누적 범위를 대체하지 않는다.

### 20.5 유효 평가 승계와 과거 기록 보존

계산 규칙·기준액·평가 범위가 같은 것으로 확인되는 기존 유효 평가는 값·기간·관측 상태를 승계한다. 현재 자료가 부족하면 승인된 과거값 유지 규칙을 적용한다.

규칙이 다르거나 의미를 확인할 수 없는 옛 점수는 구버전 기록으로 보존하고 현재 점수에 섞지 않는다. 과거 원천자료로 새 평가를 계산해도 적용 시점의 새 평가로 기록한다. 과거 날짜에 새 평가가 있었던 것처럼 이력을 채우거나 새 기준의 참고 평가 이력을 별도로 만들지 않는다.

기존 일일 보고와 거래 기록은 덮어쓰지 않는다. 부모는 기존 승인대로 직접 자식값의 평균이며, 이번 승계가 새 평균 방식이나 새 재정 점수를 추가하지 않는다.

### 20.6 원본 보존과 반복 불러오기

정상적인 불러오기 과정에서 원본을 보존한 별도의 변환 사본을 만들고 검증한 뒤 사용한다. 별도 전환 명령을 사용자가 선택해야 하는 대안은 채택하지 않았다.

현금·정부 제한자금·예약금·미지급액, 진행 중 공사와 승객 처리를 이어 간다. 도입 전에 탄 승객이 도입 후 도착하면 기존 규칙대로 운임을 한 번 인식한다. 평가 도입 때문에 과거 비용·거래를 재실행하지 않는다.

적용 시작점과 승계한 자료를 저장한다. 다시 불러와도 최초 도입을 반복하거나 실적을 중복 합산하지 않는다. 핵심 자금 장부를 정상 복구하지 못하면 변환 실패로 처리한다. 과거 평가 자료가 부족한 경우는 미관측·평가 보류 상태로 정상 전환할 수 있다.

## 21. 재정의 플레이어 정보 전달

### 21.1 단계와 정확한 내부 점수 비공개

서비스 수준과 같은 5단계와 같은 내부 구간을 적용한다. 아래 경계는 기획·개발 검수용이다.

| 내부 범위 | 플레이어 단계명 |
|---|---|
| 0≤값<2 | 취약 |
| 2≤값<4 | 미흡 |
| 4≤값<6 | 보통 |
| 6≤값<8 | 양호 |
| 8≤값≤10 | 우수 |

정확한 점수·경계 수치·산식은 플레이어 화면·도움말·툴팁·알림·평가 내보내기에 공개하지 않는다. 같은 단계 안에서 막대 길이·좌표·색상 농도 등을 미세하게 바꿔 점수를 드러내지 않는다. 기존 운영 보고의 실제 현금·매출·비용은 기존 공개 범위를 유지한다. 미관측 기본값 5.0은 보통으로 표시하지 않는다.

### 21.2 최근 마감 기준의 7일 추세

최근 마감 평가와 7게임일 전 마감 평가의 단계를 비교한다. 높은 단계면 개선, 같은 단계면 비슷한 수준, 낮은 단계면 악화다. 같은 단계라는 것은 정확한 점수가 같다는 뜻이 아니다.

현재 단계는 각 지표의 갱신 주기에 따라 보여 주고, 추세는 최근 마감 기준임을 명시한다. 두 비교 시점 모두 유효한 평가여야 한다. 운행 수익성과 미지급 부담은 양쪽 평가의 각 7일 자료도 완전해야 한다. 현재 단계 표시가 가능해도 추세 표시는 더 늦게 시작될 수 있다.

비교 자료가 없으면 비교 자료 수집 중, 산식·기준 투자액·평가 범위 정의가 달라졌으면 해당 지표만 기준 변경으로 비교 보류로 표시한다. 새 사업 완료·예약금 증가 같은 정상적인 게임 내 변화는 추세에 반영한다. 현재 평가가 불가능한 상태에서 과거 유지값을 새 현재값처럼 사용해 추세를 만들지 않는다.

### 21.3 확인된 원인과 현재 제한의 구분

각 평가에 확인된 주요 사실을 최대 2개 제시한다. 우선순위는 평가기준 변경 → 부담 증가·손익 악화 → 개선 사실이다. 근거가 없는 점수 기여율이나 인과를 만들지 않는다.

예를 들어 예약자금 증가로 실제 가용자금이 줄었거나, 미지급 정산으로 남은 미지급액이 감소한 사실을 설명한다. 정부 사업비가 들어와도 사업 전용자금이므로 가용자금이 늘지 않았다면 투자 여력이 개선됐다고 설명하지 않는다. 미지급 지급을 이미 발생한 비용의 새로운 손실로 설명하지 않는다.

현재 운행 제한은 평가 원인과 별도로 알린다. 좋은 과거 평가가 현재의 자금 부족·승차 제한을 가리지 않게 한다. 과거 평가를 보여 줄 때는 당시 사유와 현재 상황을 섞지 않는다. 원인 자료가 없으면 평가 사유 확인 불가로 표시한다.

### 21.4 최근 28일의 마감 단계 이력

최근 28게임일의 마감 단계와 당시 평가 기간·관측 상태·기준 변경·확인된 원인을 제공한다. 정확한 점수 선그래프, 자료 없는 날짜의 임의 연결, 마지막 평가를 새 평가처럼 채우는 표현은 사용하지 않는다.

호환되는 실제 과거 평가 기록은 승인된 승계 규칙에 따라 가져올 수 있다. 원천자료만 존재하는 과거 날짜에 새 평가 이력을 만들지 않는다. 당시 기록은 보존한다. 28일은 화면 표시 범위이며 회사 누적 사업 기록·원장의 삭제 기한이 아니다.

### 21.5 자료 부족과 과거값의 상태 구별

상태의 의미를 기본 정보에서 구별한다. 아래 표현은 의미 전달 기준이며 최종 문구·배치·색상·상호작용은 Design 소관이다.

| 상황 | 전달할 의미 |
|---|---|
| 정상 운영계획이나 평가 가능한 완료 사업이 없음 | 평가 대상 없음 |
| 최초 실제 영업시간 등 표본 부족 | 자료 수집 중 |
| 과거 사업 기록 누락 | 과거 사업 자료 부족으로 평가 보류 |
| 과거 유효값은 있으나 현재 평가 불가 | 마지막 평가 단계·날짜와 현재 부족 사유를 함께 표시 |
| 자료 오류·불일치 | 자료 확인 필요 |
| 채무 평가 미적용 | 채무 구조 평가 미적용. 기본값 5.0을 보통으로 표시하지 않음 |
| 자료가 유효하고 실제 결과가 낮음 | 정상적인 평가 단계로 표시. 자료 부족으로 숨기지 않음 |

자료 부족을 낮은 성적처럼 보이게 하지 않는다. 오래전에 계산됐다는 이유만으로 낡은 평가라고 판정하지 않는다. 누적 사업 자료가 그대로 유효하면 새 사업이 없어도 현재 평가일 수 있다. 운행 수익성은 최신 마감 기간의 자료가 유효한지 확인한다. 나머지 항목도 각자의 현재 기준·원장·갱신 주기에 맞춰 현재 유효 여부를 구분한다.

### 21.6 재정의 참고평가와 종합 표시

재정에 한정하여 채무만 평가 미적용인 경우 참고평가를 허용한다. 내부 평균은 미관측 채무 기본값 5.0을 포함하는 기존 산식 그대로다. 관측된 항목만 새로 평균하거나 가중치를 바꾸지 않는다.

| 표시 대상 | 현재 단계 표시 조건 |
|---|---|
| 유동성 | 두 하위 항목 모두 현재 유효하면 정상 단계 표시 |
| 수익성 | 두 하위 항목 모두 현재 유효하면 정상 단계 표시 |
| 재무 건전성 | 미지급 부담이 현재 유효하고 채무만 평가 미적용이면 참고평가 표시 |
| 재정 전체 | 채무를 제외한 나머지 5개 모두 현재 유효하면 참고평가 표시 |

참고평가와 채무 구조 평가 미적용이라는 사실을 항상 함께 전달한다. 다른 항목까지 자료가 부족하거나 과거값 유지 중이면 그 항목을 포함하는 종합은 평가 대기로 표시하고, 유효한 개별 항목·축은 계속 보여 준다. 참고평가 추세는 두 비교 시점의 구성과 상태가 같을 때만 제공한다.

이 예외는 현재 채무 평가 미적용 상황에 한정한다. 서비스 수준의 종합 표시 조건을 바꾸거나 채무의 실제 산식을 승인한 것이 아니다. 향후 채무 평가 도입은 별도 기획 범위다.

## 22. 재정 1차의 미결 여부와 조건부 후속 범위

현재 C01과 채무 평가 미적용을 전제로 한 재정 1차 범위의 잔여 정책 결정은 0건이다. 계산·관측 8개, 적용·승계 6개, 정보 전달 6개는 모두 채택 완료다. 화면 상세 설계·데이터 공급 확인·실제 검증은 남아 있지만 승인 정책의 재선택과 구별한다.

조건부 후속 업무는 다음과 같다.

| 조건 | 후속 기획 | 현재 처리 |
|---|---|---|
| 다른 시나리오·규모의 콘텐츠 추가 | 시나리오별 양수 기준 투자액과 변경/승계 기준 | C01은 승인된 300,000 사용. 현재 C01 기준의 미결 사항으로 되돌리지 않음 |
| 대출·이자·상환 시스템 도입 | 채무 구조 건전성의 실제 관측 요소와 산식 | 기존 승인대로 5.0·미관측 유지 |

일반 난이도 초기값, 상태값의 역방향 효과, 다른 회사 상태값 분야는 회사 전체의 별도 후속 범위다. 재정의 20개 세칙 채택으로 함께 승인된 것으로 해석하지 않는다. 개발·디자인 확인에서 실제 모순이나 제약이 발견되면 해당 정책과 영향을 명시한 변경안으로 다룬다.

## 23. 향후 재정 개발·디자인 확인 사항

### 23.1 개발팀 데이터 요구사항

아래 12개는 추후 확인할 준비 목록이다. 현재 자료가 실제로 제공되는지 검증하지 않았으며 요청을 발송하지 않았다. 각 항목의 확인 결과에는 기존 자료의 위치, 누락 여부, 추가 기록 필요 여부, 보존 가능 범위를 구분하면 된다. 필요한 정보의 의미를 정리한 것으로 클래스·파일·API·저장 형식은 지정하지 않는다.

| 번호 | 필요한 자료 | 확인하려는 이유 |
|---|---|---|
| 1 | 같은 게임 시점의 현금·정부 제한자금·예약자금·가용자금, 시나리오/기준 투자액 식별 | 실제 사용 가능한 돈으로 완충력·투자 여력을 계산하고 C01 기준액을 적용하기 위해 |
| 2 | 현재 정상 운영계획·영업시간·적용 비용 단가·효력 이력·실제 비용 부담의 공유 관계 | 일시 중단으로 기준 비용이 사라지거나 노선 별칭으로 이중 계산되는 것을 막기 위해 |
| 3 | 실제 비용이 발생한 영업구간과 시간·독립 운행 식별·중단/잔여 도착 구분 | 최근 7개 마감일의 실제 영업 1,080분을 중복 없이 확인하기 위해 |
| 4 | 마감 게임일별 확정 도착 운임과 발생 운영비·자료 완전성·마감 상태 | 진행 중 당일 제외, 도착일/발생일 귀속, 미지급이어도 비용 보존을 확인하기 위해 |
| 5 | 현재 미지급 운영비, 최근 7게임일 발생비의 시각별 이력, 지급·자동 정산 완료 상태 | 현재까지의 기간과 잔액을 일치시키고 공사 미지급과 구분하기 위해 |
| 6 | 사업별 정부 매출·시공비·직접 시험/수리비·유효 개통·금액 확정 여부·정산 변경 | 평가 가능한 사업만 누적 합산하고 비용 중복과 과거 평가 덮어쓰기를 막기 위해 |
| 7 | 마지막 유효 평가·당시 기준/기간·자료 부족/오류·과거 원천자료와 저장본의 버전, 최초 적용 시점·승계 대상·원본/변환본 검증 상태 | 유효 0과 자료 없음을 구분하고, 승인된 승계 정책의 호환성·사업별 완전성·반복 적용 방지를 확인하기 위해 |
| 8 | 중복 사건 식별과 처리 완료 시점, 비율·점수의 계산/보관 정밀도 | 같은 사건이 중복 반영되지 않고 중간 반올림 없이 동일한 결과가 나오는지 확인하기 위해 |
| 9 | 지표별 현재 유효 여부·마지막 유효 시점·부족 사유·채무 평가 미적용 여부·직접 자식 구성 | 현재 평가와 과거 유지값, 종합 평가 대기와 참고평가의 조건을 구분하기 위해 |
| 10 | 최근 28게임일 마감 평가의 단계·당시 기간·규칙/기준·관측 상태, 7일 비교 양쪽의 자료 완전성 | 과거 실제 평가만 보존하고 최근 마감 기준 추세와 기준 변경 보류를 재현하기 위해 |
| 11 | 평가 변화와 연결되는 확인된 자금·비용·정산 사실, 당시 원인과 현재 운행 제한 | 원인 최대 2개를 근거에 따라 설명하고 현재 제한을 과거 평가에 섞지 않기 위해 |
| 12 | 단계·추세·상태를 제공하는 화면/도움말/알림/내보내기의 정보 범위 | 내부 정밀 점수·경계·산식이 플레이어 경로에 노출되지 않는지, 기존 운영 사실의 공개 범위가 보존되는지 확인하기 위해 |

1,080분을 모으는 실제 속도, C01 기준액 300,000의 체감 난이도, 사업별 과거 자료의 실제 존재 여부, 원본/변환본 분리와 반복 불러오기의 안전성, 실제 세이브/자료 연결은 후속 검증 대상이다. 이는 승인한 정책을 미정으로 되돌리는 것이 아니다. 검증 결과 정책 변경이 필요하면 근거와 영향이 있는 별도 변경안으로 다룬다.

### 23.2 디자인팀 표현 확인 사항

아래 8개는 승인된 정보 계약을 실제 화면에서 전달하는 방식의 확인 목록이다. 요청은 미발송이다. 배치·색상·아이콘·세부 문구·상호작용은 Design 소관이며, 이 목록이 화면 제작이나 부서 검토 착수 지시가 되지는 않는다.

| 번호 | 확인할 표현 | 확인 목적 |
|---|---|---|
| 디자인 1 | 5단계 명칭과 시각적 구별 | 동일 단계 안에서 정밀 점수 차이가 드러나지 않으며 미관측을 보통으로 오해하지 않는지 |
| 디자인 2 | 평가 대상 없음·표본 수집·과거 자료 누락·오류·채무 평가 미적용 | 기다리면 해결되는 문제와 과거 자료 복구가 필요한 문제를 구별할 수 있는지 |
| 디자인 3 | 재정·재무 건전성의 참고평가와 채무 평가 미적용 안내 | 참고라는 조건이 항상 함께 보이며 일반 종합 평가와 혼동하지 않는지 |

## 26. 재무위기 대응역량 1차: 평가 규칙 8개

재무위기 대응역량 1차 기준선 v1.0은 자금 위험이 생겼을 때 지급 차질을 예방하고 안정적인 운영 상태로 회복한 실적을 평가한다. 현재의 재정 상태를 평가하는 기존 재정 지표와 역할을 구분한다. 평가 규칙 8개·적용과 승계 6개·정보 전달 6개 및 설명·경계 사례가 승인 범위다.

기존 재정 3축·6말단과 산식, 서비스 수준의 평가·운행·환승 규칙, 정부 제한자금·공사 예약금 보호·운영비 미지급 자동 정산·기존 승차 제한을 유지한다. 리스크 관리도의 세 직접 자식과 산술평균, 0~10·기본 5.0과 미관측의 구별, 정확한 내부 점수 비공개도 유지한다. 사례 집계를 새 하위 상태값으로 만들지 않으며 새 벌금·계약 제한·보상·대출 기능을 추가하지 않는다.

정책 채택과 실제 자료 공급·화면·게임 구현의 검증 완료는 구분한다. 이 절 이후의 수치·사례는 내부 설계·검증용이며 제품의 모든 플레이어 노출 경로에서는 §28의 비공개 원칙을 따른다.

### 26.1 최초 평가 범위

유효 개통 후 회사의 운영자금 위험 사례부터 평가한다. 위험 신호 단계에서 지급 차질을 막은 경우도 예방 실적으로 인정한다. 기존 재무위기 대응역량 한 항목을 사용하며 새 하위 항목은 만들지 않는다.

공사 자금 부족·채무 상환까지 한꺼번에 평가하는 대안은 채택하지 않았다. 사업위험 대응역량과의 구분 및 실제 채무 모델은 별도 기획 범위다.

### 26.2 위험 사례의 시작

정상 운영계획과 자료가 유효할 때 가용자금이 정상 운영비 3일분 미만이 되면 시작한다. 운영비 미지급이나 기존 재무 조건에 따른 신규 승차 제한이 발생해도 시작한다.

3일분은 기존 재정의 운영자금 기준과 연결하는 위험 신호 기준이다. 재정 점수가 특정 값이라는 이유로 위험 사례를 자동 생성하는 방식은 아니다.

같은 게임 시각의 도착 운임·자동 정산 등이 완료된 상태로 판정한다. 처리 도중 잠깐 생겼다가 해소된 미지급은 별도 실패로 기록하지 않는다.

### 26.3 회복의 인정 조건

미지급 해소, 기존 재무상 승차 조건 충족, 가용자금 3일분 확보를 1게임일 유지해야 회복으로 인정한다. 사례 중 가장 높았던 정상 하루 운영비를 회복 기준으로 사용한다.

이는 이 대응 사례의 회복 판정에만 적용한다. 정식 계획 변경 시 기존 재정 지표가 정상 운영비를 갱신하는 승인 규칙은 유지한다. 비용을 줄인 효과는 실제 자금 회복으로 인정하되, 평가 문턱 자체가 낮아져 즉시 성공하는 것을 막는다.

회복 확인의 1일에는 정상 계획상의 영업 기회가 있어야 한다. 운영계획을 없애거나 자료가 끊긴 상태를 회복으로 인정하지 않는다.

### 26.4 대응 실적의 인정 방식

실제 자금·지급·운행 결과로 판단한다. 수동 조작과 자동 정산을 차별하지 않고 메뉴 열기·중단 버튼 누르기·계획 변경 횟수에는 점수를 주지 않는다.

정부 제한자금이나 공사 예약금의 기존 용도 제한을 유지한다. 총현금 증가와 실제 사용 가능한 가용자금 증가를 동일시하지 않는다.

### 26.5 사례별 평가 기준

회복 확인에 필요한 1일도 소요시간에 포함한다. 다음 숫자는 내부 기획·검수용이며 플레이어에게 공개하지 않는다.

| 사례 결과 | 내부값 |
|---|---:|
| 미지급·재무상 승차 제한 없이, 시작 후 3게임일 이내 회복 확인 완료 | 10 |
| 위 조건에는 못 미치지만 7게임일 이내 회복 확인 완료 | 5 |
| 시작 후 7게임일까지 회복 확인을 완료하지 못함 | 0 |

- 1게임일은 게임 시각 24시간이다. 야간에도 기간은 흐르고 게임 일시정지 중에는 멈춘다.
- 7일 경계에서는 그 시각의 처리를 마친 뒤 회복 여부를 먼저 확인한다. 조건을 충족하면 5, 충족하지 못하면 0이다.
- 0이 확정돼도 실제 사례는 회복할 때까지 이어진다. 나중에 자금이 회복됐다는 이유로 해당 사례를 성공으로 다시 쓰지 않는다.
- 자료가 없어 회복 여부를 모르는 경우에는 0을 확정하지 않는다. 실제 실패와 확인 불가를 구분한다.

### 26.6 반복·겹치는 위험 처리

회사 전체에서 겹치는 위험은 한 사례로 묶는다. 회복 후 7게임일간 안정 상태를 유지하기 전에 재발하면 이전 사례를 다시 열고 최초 시작 시각을 유지한다.

재발로 현재 평가가 바뀌어도 당시 확정된 과거 보고·평가 이력은 덮어쓰지 않는다. 회복할 때마다 새 사례를 만들어 좋은 사례 수를 늘리는 방식은 채택하지 않았다.

### 26.7 회사 평가로 합치는 방식

최근 28게임일 안에 종료된 사례와 아직 해소되지 않은 평가 확정 사례 중 가장 낮은 결과를 사용한다. 위험 관리의 취약했던 대응을 우선 보는 방식이다.

사례별 평균은 채택하지 않았다. 좋은 사례가 생겨도 낮은 평가가 바로 회복되지 않는다는 특성이 있다. 작은 성공 여러 건으로 큰 실패를 희석하지 않는다.

### 26.8 평가 기회·자료가 없을 때

평가 사례가 없으면 5.0·미관측이다. 과거 유효값만 있으면 날짜와 함께 보존한다. 자료 누락이나 아직 평가가 확정되지 않은 진행 사례는 현재 평가 대기로 구분한다.

계속 건전하게 운영해 위험 사례가 없었던 회사는 대응 능력을 확인할 사례가 없는 상태로 남는다. 이를 낮은 성적처럼 전달하지 않는다. 위기 없이 일정 기간 운영하면 높은 점수를 부여하는 대안은 채택하지 않았다.

### 26.9 승인안의 설명 예시

정상 하루 운영비 108,000이면 위험 기준은 가용자금 324,000이다. 미래 모든 운행의 정상 운영비를 108,000으로 고정하는 의미가 아니다.

| 예시 | 내부 평가 |
|---|---:|
| 위험 발생 후 1일째 자금 회복, 2일째까지 안정 유지, 지급 차질 없음 | 10 |
| 같은 기간에 회복했지만 중간에 실제 운영비 미지급 발생 | 5 |
| 지급 차질은 없었지만 회복 확인이 4일째 완료 | 5 |
| 7일째에도 회복 확인 조건 미충족 | 0 |

현재 자금이 같은 두 회사라도 위기를 예방하고 회복한 과정에 따라 대응역량 평가는 달라질 수 있다. 내부 사례 점수와 부모의 직접 평균을 플레이어에게 그대로 공개하지 않는다.

## 27. 재무위기 대응역량 적용·기존 세이브·과거 사례 승계

아래 6개는 Owner가 권고안대로 채택한 적용·승계 기준이다. 승인 추적표의 RFR-D09~14와 연결하며 미채택 대안은 이 기준선에 포함하지 않는다.

### 27.1 적용 시점과 최초 관측을 구분

최초 적용 시점을 τ라 한다. 기존 세이브는 τ에 원장을 복구·검증한 뒤 평가를 연결한다. 도입을 위해 다음 날로 시간을 넘기거나 비용·정부 지급·도착 운임·자동 정산을 재실행하지 않는다.

새 게임의 평가 기능은 초기 설정 완료부터 적용하되, 실제 위험 사례를 평가하려면 승인된 유효 개통 이후의 운영자금 위험 범위와 정상 운영계획·자료 조건을 충족해야 한다. 기능 적용과 최초 평가 가능 시점을 같게 취급하지 않는다.

기존 세이브의 현재 자료와 승계 근거가 충분하면 τ에서 바로 현재 평가를 만들 수 있다. 모든 저장본에 새 28일 대기를 부과하지 않는다. 재정·서비스 수준이 먼저 적용되어 있더라도 그 적용 시점·표본·평가·승계 상태를 초기화하지 않는다.

### 27.2 과거 종료 사례의 인정 범위

최근 28게임일에 종료된 평가 대상 사례를 사례별로 확인한다. 그 사례가 28일보다 앞서 시작했으면 최초 시작까지 필요한 기록을 확인한다. 아직 해소되지 않은 평가 확정 사례는 시작·평가 시점이 오래됐다는 이유로 제외하지 않는다. 회복 후 7일 안정 확인 전의 사례는 재발 관계를 판정할 수 있도록 함께 승계한다.

확인 대상에는 최초 시작, 같은 회사의 겹치는 위험, 미지급·재무상 승차 제한, 사례 중 최고 정상 하루 운영비, 회복 조건의 1일 유지와 영업 기회, 종료·재발, 확정 결과가 포함된다. 저장 필드명·파일 구조는 지정하지 않는다.

과거 종료 사례 일부가 확인된 것과 현재 회사 평가에 필요한 전체 범위가 완전한 것은 구분한다. 좋은 사례만 골라 가져오지 않으며, 기록이 없는 기간을 위험이 없었던 기간으로 간주하지 않는다. 회사 설립 후 28일이 지나지 않았다면 실제 존재하는 기간을 확인하되, 실제 기록 누락과 아직 존재하지 않았던 날짜를 구별한다.

과거 평가 기록이 없어도 완전한 원천자료로 현재 평가에 필요한 사례 결과를 계산할 수는 있다. 이는 현재 시점의 계산이며 과거 날짜에 새 평가 기록을 만들어 넣는 권한은 아니다.

### 27.3 진행 중 사례와 재발 감시의 연속성

확인된 기존 사례는 τ에 새로운 사례로 바꾸지 않는다. 원래 최초 시작을 기준으로 3일·7일 기한을 유지하고, 회복 확인 1일 및 회복 후 안정 7일도 남은 시간만 이어 간다. 사례 중 최고 정상 하루 운영비를 현재의 낮아진 비용으로 바꾸지 않는다.

이미 내부0이 확정된 미해소 사례는 그 결과와 진행 상태를 보존한다. 새 평가 기능의 도입이나 불러오기로 성공 기회를 다시 부여하지 않는다. 7일이 지난 미해소 상태를 완전한 원천자료로 처음 확인한 경우에는 τ의 새 평가로 기록하며 과거 마감 보고에 소급 기입하지 않는다.

회복 후 7게임일 안정 유지 전에 재발하면 원래 사례를 다시 열며 최초 시작과 당시 최고 기준 비용을 이어받는다. 같은 사례를 종료 사례와 새 사례로 이중 집계하지 않는다. 과거 확정 보고·평가 이력은 당시 상태로 보존한다.

### 27.4 불완전한 과거 자료 처리

적용 이후의 실제 자료는 즉시 수집한다. 확인된 기록도 보존하되 평가 대상 전체가 불완전하면 확인된 일부만으로 현재 회사 점수를 확정하지 않는다. 같은 의미의 과거 유효 평가가 있으면 날짜와 함께 유지하고, 없으면 5.0·미관측으로 둔다. 현재 자금 부족·미지급·승차 제한은 기존 경제 규칙대로 계속 처리한다.

부족한 자료는 두 경우로 나눈다.

- **이미 종료된 과거 사례의 범위만 부족한 경우:** 자료를 복구하거나 부족한 구간이 최근 28일 범위에서 완전히 빠지고 현재 필요한 사례 정보가 모두 확인되면 새 평가를 시작한다. 최대 28게임일 정도의 새 기록 축적이 필요할 수 있지만, 이는 모든 회사에 적용하는 최소 관측기간이 아니다.
- **진행·재발 감시 중인 이월 사례의 정보가 부족한 경우:** 28일이 지났다는 이유만으로 그 사례를 삭제하지 않는다. 원래 사례의 필요한 근거를 복구하거나 승인된 조건에 따른 종료·재발 관계를 검증할 수 있어야 한다. 최초 시작이나 과거 최고 운영비 등을 몰라 판정할 수 없으면 평가 보류가 장기화될 수 있다.

특히 최고 기준 운영비가 없는 옛 사례를 적용 이후의 최고 비용만으로 바꿔 회복했다고 판정하지 않는다. 불러온 시각을 새 사례 시작으로 사용하지 않는다. 정체를 알 수 없는 옛 사례를 새 관측 범위로 강제 분리하는 예외는 이번 권고에 포함하지 않는다. 그런 전환 예외를 원하면 기존 사례 보존에 미치는 영향을 별도 결정해야 한다.

실제 실패가 확인된 0과 자료 부족을 구분한다. 과거 기록이 없다는 이유만으로 7일 미회복을 추정하지 않는다. 반대로 과거의 확정0을 자료 부족을 핑계로 삭제하지 않는다. 재무위기 대응역량의 현재 평가 보류가 유효한 기존 재정·서비스 평가의 중단으로 번지지 않게 한다.

### 27.5 평가값과 과거 보고의 승계

승계할 평가는 규칙 버전, 평가 대상 범위, 사례 묶음, 3일·7일 기한, 회복 기준, 28일 최저 사례 방식 및 당시 관측 상태의 의미가 같은지 확인한다. 호환되는 유효 평가값과 날짜·근거는 보존한다. 현재 평가를 새로 확정하려면 현재 대상 사례의 포함·누락 여부까지 확인해야 한다.

재정 점수·서비스 점수·현재 미지급액을 재무위기 대응역량의 과거 점수로 대체하지 않는다. 의미가 다르거나 확인할 수 없는 옛 점수는 구버전 기록으로 분리하고 현재 점수/평균에 섞지 않는다. 원천자료로 다시 계산한 결과는 τ 또는 실제 계산 시점의 새 평가로만 기록한다.

실제로 있었던 호환 과거 평가는 승계할 수 있지만 당시 존재하지 않았던 평가 이력을 채우지 않는다. 일일 보고와 실제 거래 기록도 덮어쓰지 않는다. 부모의 직접 자식 산술평균과 정확한 내부 점수 비공개 원칙을 유지한다.

### 27.6 원본 보존과 반복 불러오기

정상 불러오기에서 원본을 보존한 별도의 변환 사본을 만들고 검증한 뒤 사용한다. 현금·제한자금·예약금·미지급, 공사·운행·진행 승객, 재정·서비스 평가 기록을 이어 간다. 과거 거래나 평가를 다시 실행해 원장을 변경하지 않는다.

τ, 승계한 사례와 근거, 원래 시작·최고 기준 비용·회복/재발 상태, 평가 확정 상태와 당시 날짜, 과거 자료 부족 범위를 보존한다. 다시 불러와도 τ·3일/7일 기한·1일 확인·7일 안정 감시·28일 범위를 새로 시작하거나 사례를 복제하지 않는다.

핵심 원장·공사·승객 등 기존 게임 진행 상태 또는 안전한 변환의 필수 조건을 검증하지 못하면 변환 실패로 처리하며 원본을 유지한다. 재무위기 평가 자료만 부족한 경우에는 평가 보류 상태로 정상 전환할 수 있다. 자료 부족과 자금/세이브 손상을 같은 실패로 취급하지 않는다.

## 28. 재무위기 대응역량의 플레이어 정보 전달

아래 6개는 Owner가 권고안대로 채택한 정보 전달 기준이다. 승인 추적표의 RFR-D15~20과 연결하며 미채택 대안은 이 기준선에 포함하지 않는다.

### 28.1 단계와 정확한 내부 점수 비공개

재무위기 대응역량과, 향후 표시 조건을 충족한 리스크 관리도 부모에 기존 재정·서비스의 같은5단계 체계를 사용한다. 다음 표는 OWNER·기획·개발의 내부 검수용이며 플레이어 공개 내용이 아니다.

| 내부 범위 | 플레이어 단계명 |
|---|---|
| 0≤값<2 | 취약 |
| 2≤값<4 | 미흡 |
| 4≤값<6 | 보통 |
| 6≤값<8 | 양호 |
| 8≤값≤10 | 우수 |

현재 승인된 재무위기 사례 결과와 최저 사례 집계는 내부0/5/10이므로, 이 말단의 유효 평가는 현재 취약/보통/우수로 나타난다. 미흡·양호를 채우기 위해 새 점수·보간·가중치를 만들지 않는다. 다른 리스크 항목의 산식이나 관측 요건을 이번에 승인하는 것은 아니다.

미관측 기본값5.0은 보통으로 표시하지 않는다. 현재 평가 대기 상태의 과거 유효 단계는 현재 단계와 구별해 날짜를 붙인다. 유효한 낮은 결과는 자료 부족처럼 숨기지 않는다.

정확한 내부 점수, 점수 경계, 점수 환산·집계 산식은 플레이어 화면·도움말·툴팁·알림·평가 내보내기에 공개하지 않는다. 정밀 점수 그래프, 같은 단계 안의 미세한 막대 길이·좌표·색상 농도, 숨은 설명문 등으로 노출하지 않는다. 내부값과 단계의 숫자 대응표를 플레이어 안내에 넣지 않는다.

실제 잔액·미지급액·매출·비용·게임 시각 등 기존 운영 보고의 공개 범위는 유지한다. 새 평가를 이유로 기존 사실 수치를 숨기거나 새로운 점수 수치를 공개하지 않는다. 현재 운행 재개 조건과 평가상 회복 확인은 구분한다. 점수용 만점 목표나 평가 등급 경계까지의 카운트다운을 행동 안내로 추가하지 않는다.

### 28.2 최근 마감 기준 추세

최근 마감 평가와7게임일 전 마감 평가의 단계를 비교한다. 높은 단계면 개선, 같으면 비슷한 수준, 낮으면 악화다. 같은 단계는 정확한 내부 점수의 동일성을 뜻하지 않는다. 비교 대상 날짜와 최근 마감 기준이라는 사실을 함께 전달한다.

현재 단계는 승인된 사례 확정·재발·종료·28일 평가 대상 변화·자료 상태 변화의 결과를 반영하고, 추세는 마감 기록끼리 비교한다. 두 시점의 차이를 숨기지 않는다. 표시를 조회한다고 사건·회복 시간·평가를 중복 발생시키지 않는다.

비교 양쪽에 실제 유효 평가가 있어야 한다. 각 시점의 최근28일 종료 사례 범위, 기간 밖 미해소 평가 확정 사례, 관련 재발 연결과 자료 완전성을 승인된 기준으로 확인한다. 회사 설립 전 존재하지 않던 날짜와 기록 누락은 구분한다. 사례 기반 평가에 매출·운영비의7일 표본 기준을 새로 적용하지 않는다. 별도의28일 또는35일 최소 경과 조건도 만들지 않는다.

현재 평가가 보류 상태이면 과거 유지값을 현재 평가로 사용해 추세를 만들지 않는다. 비교 기록이 없거나 부족하면 비교 자료 수집 중/비교 불가 사유를 알린다. 원천자료만 있는 과거 날짜에 평가 기록을 소급 생성해 비교값을 채우지 않는다.

점수 환산·회복 기준·사례 묶음·평가 범위의 정의가 달라져 의미가 호환되지 않으면 해당 지표의 비교만 보류한다. 정상적인 사례 확정·회복·재발·계획 비용 변화·종료 사례의28일 범위 이탈은 그 자체로 규칙 변경이 아니며 승인 규칙에 따른 결과를 반영한다.

과거의 낮은 종료 사례가 범위 밖으로 빠져 단계가 올라간 경우에는 평가 대상 기간 변화로 설명한다. 새 대응 행동이 개선됐다고 단정하지 않는다. 모든 사례가 빠져 현재 평가 대상이 없어진 경우에는 개선 추세를 만들지 않는다. 미해소 평가 확정 사례를 시간 경과만으로 제외하지 않는다.

### 28.3 확인된 원인과 현재 위험

각 평가에 확인된 주요 사유를 최대2개 제공한다. 우선순위는 기준 변경 → 현재 평가를 제한하는 사례·악화/재발 사실 → 확인된 회복·개선 사실이다. 평가 대상 기간의 변화가 이유면 그 사실을 설명한다. 근거 없는 점수 기여율·플레이어 의도·원인을 만들지 않는다.

예를 들어 회복 확인이 늦었던 사례가 평가에 남아 있거나, 안정 확인 전에 같은 위험이 재발한 사실을 설명한다. 좋은 새 사례가 생겨도 이전의 불리한 사례 때문에 단계가 같다면 회사 평가가 개선됐다고 말하지 않는다. 자료가 없으면 사유 확인 불가로 표시한다.

현재 자금 위험·미지급·실제 신규 승차 제한, 평가상 회복 확인 중·재발 감시 중 상태는 평가 사유와 별도로 전달한다. 필수 현재 상태 안내를 사유 최대2개 제한 때문에 생략하지 않는다. 과거 높은 단계가 현재 위험을 가리지 않도록 한다. 실제 운행이 재개돼도 평가상 회복 확인은 진행 중일 수 있다. 반대로 낮은 과거 대응 평가가 남아 있어도 현재 운행 제한이 없을 수 있다.

정부 제한자금 입금만으로 가용자금 회복을 설명하지 않는다. 미지급 정산을 새 비용 발생으로 설명하지 않는다. 현재 비용이 줄어도 해당 사례의 최고 기준 비용이 유지된다는 승인 규칙을 따른다. 과거 기록을 설명할 때 당시 사유와 현재 사실을 섞지 않는다.

### 28.4 과거값과28일 이력

최근28게임일의 실제 마감 단계와 당시 평가 시점·대상 범위·관측 상태·기준 변경·확인된 사유를 제공한다. 과거 유효값을 계속 보유하는 경우에는 마지막 유효 평가의 날짜와 현재 부족 사유를 표시한다. 정밀 점수 선그래프, 빈 날짜 보간, 과거 유지값의 새 관측 위장은 사용하지 않는다.

호환되는 실제 과거 평가 기록은 승인된 승계 규칙대로 가져온다. 과거 원천자료로 도입 시점의 새 평가를 만들 수 있어도 과거 마감 평가를 새로 만들어 채우지 않는다. 재발 후 현재 결과가 바뀌어도 과거 마감 평가를 다시 쓰지 않는다. 구버전 기록은 현재 기준의 이력과 구분한다.

같은 사례와 현재 자료가 계속 유효하여 여러 마감에서 같은 단계가 나올 수는 있다. 이는 매일 새 대응 성공이 발생했다는 뜻이 아니다. 현재 유효한 반복 평가와 현재 평가 불가 상태의 과거값 유지를 구별한다.

28일은 이력의 기본 표시 범위이며 저장 자료 삭제 기한이 아니다. 평가의28일 종료 사례 범위와 화면의28일 마감 이력도 별개의 개념이다. 현재 평가에 포함되는 더 오래된 미해소 평가 확정 사례는 현재 사유·사례 정보에서 원래 시작/평가 시점과 함께 확인할 수 있게 한다. 원래 시작·최고 기준 운영비·재발 연결 등 필요한 근거를 잘라 버리지 않는다.

### 28.5 자료 부족과 사례 진행 상태

아래 표현은 전달할 의미다. 최종 문구·색상·아이콘·배치·상호작용은 Design 소관이다. 숫자 평가의 유효 여부와 실제 위험 상태는 별도 정보로 취급한다.

| 상황 | 전달할 의미 |
|---|---|
| 유효 개통 전 또는 정상 운영계획 등 평가 조건 미충족 | 평가 시작 전/평가 기준 부족. 기본값을 보통으로 표시하지 않음 |

| 아직 결과가 확정되지 않은 새 위험 사례 | 현재 평가 대기·위험 대응 진행 중. 과거 유효 단계는 날짜를 붙여 별도로 제공 |
| 기한 내 미회복이 확인돼 낮은 결과가 확정됐고 아직 미해소 | 자료 완전성 등 조건 충족 시 유효한 현재 낮은 단계와 미해소 상태를 함께 표시. 단순 자료 수집 중으로 숨기지 않음 |
| 회복 확인 후 결과가 확정됐고 재발 감시 중 | 나머지 조건 충족 시 현재 단계 표시 가능. 재발 감시 중이라는 이유만으로 평가를 다시 미관측으로 만들지 않음 |
| 최근 종료 사례의 과거 기록 일부가 누락 | 과거 사례 자료 부족. 확인된 좋은 사례만으로 회사 단계를 확정하지 않음 |
| 이월 사례의 최초 시작·최고 비용·재발 연결 등을 확인하지 못함 | 이월 사례 확인 필요.28일만 기다리면 반드시 해결된다고 안내하지 않음 |
| 자료 오류·불일치 | 자료 확인 필요. 실제 실패/위험과 자료 오류를 혼동하지 않음 |
| 현재 유효 평가를 만들 수 없고 과거 유효값만 있음 | 마지막 유효 단계·날짜와 현재 평가 불가 사유를 함께 표시 |
| 종료 사례가 모두 평가 범위에서 빠지고 현재 포함할 사례도 없음 | 현재 평가 대상 없음. 마지막 평가가 있으면 과거로 보존하며 자동 보통/우수·개선으로 바꾸지 않음 |

평가 이력이 오래됐다는 사실만으로 현재 평가가 무효인 것은 아니다. 현재 포함 대상과 자료가 유효한 오래된 미해소 평가 확정 사례는 계속 평가에 포함된다. 반대로 현재 범위를 벗어난 종료 사례의 옛 평가를 최신으로 보이지 않게 한다.

자료 부족으로 평가를 보류해도 기존 미지급·자동 정산·실제 승차 제한·재정·서비스 수준 처리는 유지한다. 재무위기 평가의 보류를 회사 자금 소멸이나 세이브 파손으로 안내하지 않는다. 단계가 낮다는 이유로 승인되지 않은 운행·계약 제한을 만들지 않는다.

### 28.6 리스크 관리도 부모의 표시 조건

리스크 관리도는 재무위기 대응역량·사업위험 대응역량·안전위험 관리역량 세 직접 자식의 기존 산술평균을 내부에서 유지한다. 미관측 기본값이나 승인된 과거 보유값을 평균에서 빼거나, 관측된 항목만 다시 평균하지 않는다.

세 항목이 모두 각자의 현재 기준과 갱신 주기에서 유효할 때만 부모의 현재 종합 단계를 표시한다. 하나라도 미관측·현재 평가 대기·과거값 유지 상태이면 종합은 평가 대기와 이유를 알리고, 현재 유효한 개별 평가는 보여 준다. 마지막으로 세 항목이 모두 유효했던 종합 이력이 있으면 당시 날짜와 함께 과거로 제공할 수 있다.

현재 다른 두 리스크 항목의 상세 기획과 현재 평가가 준비되지 않은 상태에서 재무위기 대응역량 하나만으로 리스크 관리도 전체가 우수하다고 표시하지 않는다. 재정의 채무만 미적용인 참고평가 예외는 리스크 관리도로 확대하지 않는다.

이 선택은 부모 표시 조건만 정한다. 다른 두 하위 항목의 산식·관측 요건·적용 개시나 회사 전체 단일 종합점수를 승인하지 않는다. 향후 부모 추세도 두 비교 시점 모두 같은 구성·기준의 현재 유효 종합 평가일 때만 제공한다.
