### 3.1 공동업무의 구체적인 인정 범위

첫 공동업무는 회사가 실제로 적용할 운영계획 변경의 준비로 제한한다. 예를 들어 같은 운행계획 변경에 대해 한 직원은 적용 대상·시각·필요 조건을 준비하고 다른 직원은 자신에게 배정된 운영 준비와 의존 사항을 맞춘다. 이는 역할의 예시이며 고정 직무나 신규 직원 수를 지정하지 않는다.

해당 역할이 실제로 필요하고 서로 다른 직원의 결과가 있어야 하며, 같은 최신 변경안을 기준으로 준비되어야 한다. 단순히 한 업무의 이름을 두 개로 나눈 것은 공동업무가 아니다. ‘회의 참석’ 대신 배정된 결과의 내용과 서로 맞아야 하는 조건이 실제로 맞는지 확인한다.

이미 정한 협력 책임을 이행했다면 이후 외부 수요 변화나 별도 운행 문제로 목표 매출·서비스 성과를 달성하지 못했다고 이 사례를 감점하지 않는다. 반대로 회사 성과가 좋더라도 실제 준비 누락을 덮지 않는다. 이 기준표가 준비 실패에 따른 운행 차단·비용·사고 효과를 새로 승인하지는 않는다.

### 3.2 인수인계의 다섯 필수 조건

1. **업무 상태:** 인계할 업무와 범위, 완료/진행 상태가 실제와 맞는다.
2. **미해결 사항과 기한:** 남은 책임, 문제, 다음에 해야 할 일과 기존 기한을 빠뜨리지 않는다. 실제로 없으면 확인된 ‘없음’을 인정한다.
3. **주의·변경 사항:** 알려진 제약, 업무에 필요한 변경, 확정되지 않은 내용을 구분해 전달한다. 알 수 없던 미래를 예측하지 못했다고 실패로 만들지 않는다.
4. **필요 자료와 접근:** 업무를 이어갈 필수 자료·대상에 실제로 접근할 수 있다. 주소만 전달하거나 열 수 없는 자료를 주면 완료가 아니다.
5. **새 담당 책임:** 자격·권한을 갖춘 새 담당자가 언제부터 어떤 책임을 맡는지 실제로 유효해야 한다. 단순 이름 기재로 책임 이전을 대신하지 않는다.

수신자의 특정 버튼 클릭이나 이후 실사용까지 기다려야 하는 기준은 채택하지 않는 것을 권한다. 필수 정보가 정확하고 실제 사용 가능하며 책임 이전이 유효한지를 확인한다. 무응답을 곧바로 거부로 추정하지 않고, 읽음 표시가 있어도 내용이 틀리면 성공으로 만들지 않는다.

미해결 문제가 없더라도 실제 진행 업무·운영 책임이 교대된다면 상태를 정확히 넘긴 인계는 실제 사례다. 실제 인계할 책임도 업무도 없는 빈 인계를 반복 생성한 경우에는 사례가 아니다. 완성된 인계 이후 새로 발생한 문제를 과거 인계 누락으로 소급하지 않는다.

### 3.3 상호 지원의 구체적인 인정 범위

첫 지원은 실제로 필요한 특정 업무 일부를 동료가 수행하는 경험으로 제한한다. 지원 대상·할 일·필수 결과·사용 시각을 정하고, 원래 담당자가 지원 결과를 받아 업무를 이어갈 수 있어야 한다. 예를 들어 업무에 필요한 자료 대조 일부를 다른 자격 있는 직원이 맡아, 확인한 결과와 미확인 항목을 약속한 시각까지 제공하는 경우다.

‘도와주겠다’는 의사나 오래 머문 시간은 완료 기준이 아니다. 실제 결과가 없으면 정상 이행으로 보지 않는다. 필요한 결과를 정확히 제공한 뒤 실제 운영 상황상 더 이상 사용하지 않게 된 것은 그 이후의 별도 변화로 판단한다.

단순히 인계를 받는 행동이나 공동업무에서 처음부터 맡은 역할을 수행한 일을 추가 지원 사례로 세지 않는다. 같은 작업 안의 지원은 COH-C08에 따라 원래 주된 사례에 포함한다. 자원도 필요도 없는 지원을 평가용으로 만들지 않는다.

## 4. COH-C04 성립 조건과 정당한 거절

원래 사례의 시작 시각 S에서 다음을 확인한다.

- 실제 업무의 필요와 참여자·역할·결과·기한이 구체적이고, 서로 다른 직접 고용 직원 두 명 이상의 경험이다.
- 담당자가 그 업무를 수행할 자격·권한과 필요한 정보·자원을 갖추거나, 기한에 맞게 제공되는 유효한 계획이 있다.
- 실제 배정된 업무시간 안에서 수행 가능하며 휴식·비번과 다른 유효한 의무를 침해하지 않는다.
- 정당한 수락 또는 이미 정해진 업무 배정 권한에 따른 유효 배정이 실제로 성립했다. 요청·예정표·수락 버튼만으로 앞의 조건을 생략하지 않는다.

기존 직원 콘텐츠가 해당 직무의 자격·권한·수행 가능 시간·배정 조건을 제공해야 한다. 이 자료가 없으면 성립 여부가 불명확한 것이며, ‘기회 없음’ 또는 직원의 실패로 처리하지 않는다. 이번 평가안이 새 강제 배치 권한이나 임의의 최소 작업시간을 만들지 않는다.

| 상황 | 권고 처리 |
|---|---|
| 정당한 추가 지원을 아직 수락하지 않았고 유효 배정도 없음 | 요청만으로 협력 책임·미해결 0 생성 금지. 거절만으로 가점도 없음 |
| 휴식 중·자격 없음·권한 없음·기존 의무와 양립 불가 | 정당한 거절. 책임 성립 제외 근거를 보존 |
| 기존 권한과 근무 조건 안에서 유효하게 배정됨 | 별도 수락 버튼 유무와 무관하게 실제 성립한 책임을 평가 |
| 수락했지만 실제로는 자격·자원·부담 조건을 위반 | 수락 버튼으로 부당한 의무를 정당화하지 않음 |
| 수행 가능 조건의 자료 자체가 없음 | 판정 불가. 나쁜 결과나 기회 없음으로 확정하지 않음 |

## 5. COH-C05 기한과 완료 판정

기한 T는 사례 시작 S에 실제 업무에서 그 결과가 필요한 예정 시각으로 고정한다. 모든 유형을 ‘요청 후 30분’ 등 같은 시간으로 재단하지 않는다. 시간 단위는 게임 시각이며 현실 시간 경과와 구분한다. 게임 시간이 멈추면 기한도 더 진행하지 않고, 자정·마감·재로딩이 원래 T를 초기화하지 않는다.

기한 T까지의 실제 이행은 포함한다. 예를 들어 T가 10:00이면 모든 필수 조건을 10:00에 충족한 이행도 제때 이행이다. 같은 시각의 실제 결과를 반영한 뒤 기한 초과 여부를 판정하며, 먼저 마감됐다는 처리 순서 때문에 거짓 실패를 만들지 않는다. 증거가 불명확하면 0 또는 10을 임의 선택하지 않는다.

T 전 일부 완료는 진행 중이다. T가 지난 뒤 정당한 필수 책임의 누락이 확인되면, 일부를 했다는 이유로 중간 점수를 주지 않고 기존 승인대로 미해결 0을 유지한다. 이후 실제 시정 전체가 완료되어야 5다. 정당한 최초 기한 이후의 일률 유예기간을 추가하지 않는다.

필수 조건에 들어 있지 않은 문체·서식·선택 설명은 실패 원인이 아니다. 필요한 결과의 정확성·사용 가능성·실제 책임 이행을 판단한다. 최종 사업 목표를 못 이룬 사실이나 협력 당사자가 통제할 수 없는 외부 차질만으로 협력 책임 위반을 추정하지 않는다.

외부 차질이 원래 업무를 불가능하거나 불필요하게 만들었다면 COH-C06의 유효 변경·종료 근거를 확인한다. 외부 차질만으로 자동 성공·기한 연장·실패를 만들지 않는다. 현재 의무나 이행을 확인할 근거가 부족하면 판정 불가로 둔다. 이때 확인된 기존 미해결 문제는 별도로 보존한다.

## 6. COH-C06 변경과 종료

변경은 실제 업무 대상·필요·자원 조건의 변화와 그에 따른 유효한 운영계획/책임 변경에 근거해야 한다. 변경 내용과 효력 시각, 이후 역할·필수 결과·기한이 실제로 정해져 있어야 한다. 변경 전에 이미 생긴 미이행은 사라지지 않는다.

| 상황 | 권고 처리 |
|---|---|
| 기한 전에 실제 운영 목적·적용 조건이 변경되고 그에 맞는 업무 변경이 유효 | 효력 이후 의무에 변경 적용. 같은 책임의 조정이면 원래 사례를 유지하며 성공 가점을 주지 않음 |
| 준비가 늦어서 평가 기한만 뒤로 옮김 | 유효 변경 아님. 원래 T와 미이행 판단 유지 |
| 동일 업무가 그대로인데 취소 후 같은 내용을 재등록 | 원래 사례와 기한 유지. 새 표본 생성 금지 |
| 직원 교체·부서 이동·역할 재배정 | 실제 이후 담당은 갱신하되 원래 사례·기한·과거 미해결 보존. 교체만으로 기한 연장 없음 |
| 아직 위반이 없고 실제 업무 필요가 소멸하여 유효 종료 | 이후 수행 의무를 끝내고 무채점 종료. 10·5·0이나 평가 표본으로 만들지 않음 |
| 이미 위반한 뒤 원래 업무가 취소됨 | 과거 문제를 삭제하지 않음. 남은 책임과 필요한 대체 시정을 COH-C07로 판단 |
| 이미 정상 이행/시정 완료한 뒤 업무 필요가 바뀜 | 그때의 유효한 경험 보존. 이후 변화만으로 과거 완료를 취소하지 않음 |

실제 필요 소멸은 원래 작업을 수행해도 유효한 사용처가 사라진 경우다. 플레이어의 평가 목록에서 삭제한 것만으로 성립하지 않는다. 같은 목적·책임이 이어지고 있다면 종료로 숨길 수 없다. 유효한 종료로 제외된 기록도 남겨 전수 관측과 선택적 누락을 구별한다.

무채점 종료는 확정 경험 표본에 넣지 않는다. 해당 영역에 다른 평가 사례가 없다면 그 기간에 실제 협력 기회가 있었던 사실을 ‘기회 없음’으로 바꾸지 않는다. 기존 충분성 조건에 따라 현재 평가가 대기할 수 있다.

## 7. COH-C07 실제 시정과 대체 시정

필수 결과가 빠졌다면 복구하고, 그 누락 때문에 업무 상태·책임이 불명확해졌다면 정리까지 끝내야 한다. 시정에는 원래 사례와 연결된 실제 결과·완료 시각이 필요하다. 같은 누락의 여러 정정 작업을 새로운 성공 사례로 쪼개지 않는다.

| 영역 | 원래 업무가 계속 유효할 때 필요한 시정 | 원래 목적이 사라졌을 때의 대체 시정 |
|---|---|---|
| 공동업무 | 빠진 역할 결과와 필요한 조율 복구, 잘못 공유된 적용 대상/조건 정정 | 유효한 현재 계획을 관련 담당자에게 전달하고, 기존 누락에서 생긴 잔여 책임을 실제 재배정/종료하여 정리 |
| 인수인계 | 필수 정보·접근·담당 책임 복구, 누락 탓에 생긴 미확정 업무 상태 정리 | 현재 상태와 유효한 담당/잔여 책임을 확인해 실제 담당자에게 제공하고 과거 잘못된 인계의 영향 정리 |
| 상호 지원 | 약속한 결과 복구 또는 같은 필요를 충족하는 유효한 대체 지원의 실제 완료 | 지원 필요 소멸을 확인하고 그때까지 미뤄진 책임·잘못된 기대/업무 상태를 관련 담당자와 실제로 정리 |

대체 시정은 현재 필요도 없는 과거 업무를 억지로 수행시키지 않기 위한 조건이다. 단순 취소·사과로 자동 적용하지 않는다. 현재 계획/상태 확인, 필요한 전달, 잔여 책임의 실제 정리라는 확인 가능한 결과가 모두 있어야 한다. 구체적인 업무에서 이 결과를 확인할 수 없으면 ‘해결됐을 것’이라고 추정하지 않는다.

별도 손실 보상·징계·안전 조치·임금·퇴직·운행 복구의 규칙을 이 표에서 신설하지 않는다. 다른 승인된 시스템이 요구하는 실제 의무는 그 기준대로 처리하고, 협력 시정만으로 해당 의무까지 완료됐다고 선언하지 않는다.

실제 시정은 다음 정상 마감에서 같은 사례 0→5로 반영하며, 원래 기한을 지킨 10으로 바꾸지 않는다. 뒤늦게 발견한 원래 이행 증거로 사실 오류를 정정하는 경우는 실제 시정과 구분한다. 실제로 T에 완료했다는 근거가 확인되면 원래 완료 시각에 따른 사실 정정이지 새 5점 사례나 기억 기간 재시작이 아니다. 과거 보고의 정정 표시는 후속 승계·정보 전달안에서 정한다.

## 8. COH-C08 영역과 원래 사례의 분류

시작 시점의 주된 책임과 실제 필요에 따라 영역을 지정한다.

| 주된 책임 | 지정 영역 | 함께 포함하는 부수 행동 |
|---|---|---|
| 실제 운영 변경에 필요한 여러 역할의 공동 준비 | 공동업무 수행 | 그 준비를 끝내기 위한 부수 인계·자료 교환·지원 |
| 실제 진행 업무의 담당 책임을 넘기는 것 | 정보 공유·인수인계 | 해당 인계를 완성하는 확인·정정·지원 |
| 다른 직원의 특정 업무 일부를 돕는 독립된 지원 | 상호 지원 | 지원 결과 전달과 그 지원을 위한 조율 |

필수 결과 하나의 완료가 세 영역 모두를 충족하는 것처럼 보이더라도 원래 사례 하나다. 플레이어가 결과를 보고 영역을 바꾸지 않는다. 전달 오류·지원 미이행 등의 구체 원인은 설명할 수 있지만 영역별 점수를 추가 생성하지 않는다.

같은 운영 프로젝트라도 별도 실제 필요, 다른 책임·기한·필수 결과가 독립적으로 성립하면 별도 사례가 될 수 있다. 다음 실제 교대의 인계처럼 새로운 책임이 생긴 반복은 인정한다. 원래 누락을 바로잡는 재인계·재요청은 같은 사례이며, 단순 분할·이름 변경·부서 추가는 새 사례가 아니다. 두 해석을 가를 원래 근거가 없으면 임의로 늘리지 않고 판정 불가를 구분한다.

## 9. OWNER가 판단하기 위한 짧은 예시

- **10:00에 필요한 공동 준비:** 역할 두 개 중 하나가 10:00까지 끝나지 않은 사실과 정당한 책임이 확인되면 미해결이다. 10:05에 빠진 결과와 필요한 정정까지 끝내면 실제 시정이다. ‘거의 끝냄’이나 단순 새 마감 등록으로 정상 이행이 되지 않는다.
- **문제 없는 교대:** 실제 운영 책임이 있고 미해결 사항이 없음을 확인해 정확한 현재 상태와 접근 권한을 넘겼다면 정상 인계가 될 수 있다. 빈 문서를 여러 번 보내 사례를 늘릴 수는 없다.
- **지원 거절:** 휴식·자격·기존 업무 때문에 정당하게 성립할 수 없는 요청은 거절해도 결속 실패가 아니다. 이미 정당하게 맡은 지원을 실제로 하지 않은 경우와 구분한다.
- **공동 준비 안의 인계와 지원:** 하나의 준비 책임을 끝내기 위한 행동이면 공동업무 사례 하나다. 이를 세 영역의 3사례로 계산해 최소 표본을 채우지 않는다.

## 10. 다음 기획과 향후 확인

이번 결정 대상은 COH-C01~08, 8개다. COH-E01~08은 이미 채택되어 다시 승인받지 않는다. C안 채택 뒤에는 적용 시작·기존 세이브·과거 실적/진행 책임 승계, 그 다음 플레이어 단계·추세·원인·과거값·자료 부족 표시를 권한다.

실제 직원/업무의 최소 콘텐츠 도입은 계속 별도 범위다. 실제 인원·직무·업무 소요시간·권한·배치 실행을 정하지 않은 채 이 기준표만으로 구현 준비가 끝났다고 하지 않는다. 해당 준비가 안 되면 기존 승인된 관측 준비 조건에 따라 현재 평가를 내지 않는다.

| 향후 확인 대상 | 필요한 정보의 의미 |

| 개발 | 실제 업무의 필요·원래 책임·참여자·역할·주 영역·독립 반복/시정 연결 |
| 개발 | 유효한 운영계획·업무 배정·자격/권한·실제 자원/시간·휴식/다른 의무 조건 |

| 개발 | 인계 다섯 조건의 정확성·접근·책임 이전, 지원 결과의 실제 사용 가능성 |
| 개발 | 유효 변경·종료·교체·미해결·대체 시정·사실 정정과 원래 시각 보존 |
| 디자인 | 기한·필수 결과·누락·정당한 거절·시정 행동을 실제 사실로 설명하는 방법 |
| 디자인 | 점수 비공개, 승인된 현재 문제 병존, 진행 중·판정 불가·무채점 종료의 전달 |

## 12. 작성 상태

기준표는 COH-C01~08 미채택 초안이며 승인 기준선에 정책으로 편입하지 않았다. [작업 티켓](tasks/PLN-018_ORGANIZATIONAL_COHESION.md)과 [결과](tasks/PLN-018_RESULT.md)에 승인/미결과 검증을 구분한다. 개발·디자인 검토 요청, 구현 착수, 원격 게시·PR·main 병합은 수행하지 않는다.
