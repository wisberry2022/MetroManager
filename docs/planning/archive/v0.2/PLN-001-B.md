## 1. 핵심 게임 루프(7단계)

| 단계 | 플레이어가 결정하는 행동 | 게임 상태 변화 | 플레이어가 받는 피드백 | 다음 조건 |
| --- | --- | --- | --- | --- |
| 1. 회사/도시 확인 | 난이도 모드 또는 인피니트 선택, 회사/도시 상황 확인 | 시작 조건·사업 권한·재정 상태 결정 | 초기 임원 보고, 도시 현황 | 사업 탐색 |
| 2. 기회 발굴 | 교통수요 조사 후 자체 제안 또는 허용된 공공입찰 선택 | 후보 노선/공고 선택 | 수요·비용·공고 운임 조건 | 제안서 제출 또는 응찰 |
| 3. 사업 확보 | 시청·정부 심사 대응/보류 설득 또는 경쟁 입찰 | 허가/낙찰·사업비·공사 조건 확정 | 이유/등급/배정 금액/반려 | 승인·낙찰 시 공사, 실패 시 허용 범위 재도전 |
| 4. 노선 시공 | 협력업체 계약, 공기·예산·이벤트 관리 | 공정·공사비·예정 개통일 갱신 | 기성·사고·지연·잔여 현금 | 공사 완료 |
| 5. 개통 검증 | 시험운행·안전 검증 수행 | 공사 중 → 시험 중 → 운영 가능 | 검증 결과·결함 | 검증 통과 시 영업 개시 |
| 6. 운행·시민 평가 | 요금(권한 범위), 영업시간·서비스 결정 | 승객·운임 수익·운영비·만족도 변화 | 시민 이용/민원·일일 재무 | 보고/운영 데이터 누적 |
| 7. 경영 판단·재투자 | 현금·평판·시 지원·다음 노선 사업 결정 | 경영 위기 해소 또는 회사 성장 | 재무·수요·정책 변화 | 사업 탐색으로 재진입, 기존 노선은 계속 운영 |

- 시작 모드: `난이도 모드[쉬움, 중간, 어려움, 극한]` **XOR** `인피니트 모드[운영 파라미터 커스텀]`.
- **쉬움 첫 경험:** 시철 고정으로 자사 시에 소재한 공공입찰 목록과 회사 제안 모두 접근 가능. `다른 시`의 공공입찰은 표시하지 않음. 구체 발주처 자격은 Owner 추가 확인.
- 장기 루프: 운영 중인 기존 노선과 신규 공사/제안을 병행할 수 있는지는 추후 개발·게임 규칙 검토. 상기 7단계는 UI 탭 순서나 모든 행동의 직렬 강제가 아님.
- 종료: 난이도 모드는 정해진 **현금 음수 지속기간** 후 파산/공적 지원 판정. 인피니트는 사용자 설정에 따라 패배 조건 OFF 가능.

### 1-1. 회사 사업 제안 심사 상태 흐름(Owner QD-04·05)

```text
수요 분석 → 사업계획 제출
  ├ 국철: 시청 심사 생략 ───────────────────────────────┐
  └ 시철/사철: 시청 [승인 / 거부]                        │
       ├ 승인 ──────────────────────────────────────────┤
       └ 거부 → 난이도별 시청 재제출 허용                │
                 [쉬움·중간 무제한 / 어려움 5회 / 극한 3회] │
                                                            ▼
                                 국토교통부 최종 심사 [적합 / 보류 / 부적합]
                                 ├ 적합 → 최종 허가·사업비 → 시공
                                 ├ 보류 → 설득 1회
                                 │        ├ 성공 → 허가·최초 적합보다 낮은 사업비 → 시공
                                 │        └ 실패 → 중대한 신규 사실 발생 때만 재접수
                                 └ 부적합 → 중대한 신규 사실 발생 때만 재접수
```

- **시청 판정 2개, 정부 판정 3개를 혼용하지 않는다.** 시청 검토의 확률/조건은 운영 주체와 난이도에 의해 달라지고, 국철은 시청 심사를 받지 않음.
- 정부 적합/보류/부적합 판정 또한 운영 주체와 난이도 영향을 받음; 계산 공식/가중치는 미정.
- 시청의 거부 후 재제출에는 Owner가 **신규 수요 또는 대기기간 조건을 붙이지 않음**. 단, 최대 횟수의 단위·같은 내용 반복 제출의 처리 방식은 미확정.
- 정부 보류에서 설득 1회, 성공 시 예산 축소(축소율 TBD). 설득 실패·부적합 후에는 '중대한 신규 사실'이 있어야 재접수.
- 국토교통부가 **모든 도시철도 신규 사업의 최종 허가권**을 보유한다는 핵심 세계관 규칙 유지.

### 1-2. 공공입찰 흐름(Owner QD-02·07)

```text
정부/시의 공고 목록 → 회사 유형·소속 시·난이도 조건에 따라 노출 및 입찰 자격 확인
→ 공고별 사업 기간·운임·사업비(고정) 확인 → 경쟁업체와 입찰 → 낙찰 또는 탈락
→ (국토교통부 최종 허가 처리 시점 TBD) → 공사 → 검증·개통 → 운영
```

- 쉬움의 시철은 **소속 시 내 공공입찰 목록에 한정**되며 다른 시 목록은 비노출(기존 '시철 입찰 불가' 원칙의 명시적 난이도 예외 필요).
- 입찰은 회사 자체 수요조사 필수 단계가 없고, 운임·예산을 자의적으로 바꾸지 못하며 추가 사업비 청구가 불가함.
- 경쟁업체·낙찰 평가, 공고의 발주 주체, 허가가 이미 공고에 포함됐는지 등은 **별도 기획/Owner 확인 필요**.
- `입찰 경로`와 `제안 경로`는 둘 다 전체 콘셉트에 포함. **MVP MUST 최종 분류는 Gate 2**.

## 5. 초기 플레이 가능성 검증 시나리오

### VP-01 — 시철의 회사 제안 첫 개통

1. 시작: 쉬움 난이도, 시철, 소속 시의 시민 이동 불편, 초기 자본(구체 금액 TBD).
2. 수요 분석 → 노선 사업계획서 → 시청은 해당 난이도 기준으로 승인/거부 판정 → 국토교통부에서 적합/보류/부적합 평가.
3. 적합 또는 보류 설득 성공 시 사업비가 회사 매출·현금에 유입됨. MVP에서는 전액 공사비로 사용할 수 있도록 관리함(예산 금액/현금 타이밍 TBD).
4. 시공·시범운행·안전 검증 → 개통 → 시민 승차 및 만족도 평가.
5. 회사 운임 지분(쉬움 시철 100%)과 유지비 면제 조건을 반영해 손익·현금 변화를 관찰.
6. 성공 기준(관찰 가능): 플레이어가 **어떤 수요를 보고**, **왜 행정 허가가 났고**, **시민이 어떻게 이용하며 재무가 변했는지** 설명할 수 있음.

### VP-02 — 소속 시의 공공입찰 경로 비교

1. 동일한 쉬움 난이도·시철로 시작. 플레이어에게는 **소속 시 내** 공개입찰만 노출.
2. 입찰 노선을 선택해 정해진 운임·예산·시공 기간을 검토하고 낙찰 경쟁에 참가.
