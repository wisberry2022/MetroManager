## 2. 도시·연결·사업 데이터 — PAR-01
ID와 이름은 가칭. P01 도 아래 C01 시, G01~G04 구. G01=D01,D02; G02=D03,D04; G03=D05,D06; G04=D07,D08. 도시 관할 C01.

연결은 위 좌표에서 맨해튼 거리1인 쌍만 허용. 모든 연속 역이 간선으로 연결되고 고유 역 수6~8이면 유효 후보 경로다. 8개 동에 최소1곳씩 배분, D05~D08은2곳씩.
- 슬롯 P-A: C01의 북부·동부 서비스. 정상 예시 S01→S02→S03→S04→S08→S12(6역).
- 슬롯 P-B: C01의 서부·남부 서비스. 정상 예시 S01→S05→S09→S10→S11→S12(6역).
- 8역 예시: S01→S02→S06→S05→S09→S10→S11→S12.
- 슬롯은 제안 시작 때 선택하고 제출 후 변경으로 심사 제한을 우회하지 않는다. 역 집합만 같은 계획은 다른 슬롯에서도 신규 사업으로 인정하지 않는 세칙 제안. 같은 슬롯의 다른 순서·역 교체는 동일 사업. 이 규칙의 자유도/인지 가능성은 Dev/Design 확인 필요.
- 입찰 B01=C01 시청/P-A 6역 예시, B02=C01 소재 정부/P-B 6역 예시. 둘 다 사전 허가. 외부시 B-X는 실제 목록에 비노출.
- 사업성 비교를 위해 두 경로의 수요/기간/노선 순서 결과를 실제 계산한다. 테스트 전용 외부 시·광역시·특별시 위계와 오류 데이터는 별도 제공 대상으로 포함한다.

r 반올림 후 직접 적합액 이상 또는0이 되는 작은 금액은 데이터 검증 오류로 거부하는 방향. 부적합/설득 실패 후 사실 E01은 판정24게임시간 뒤 대상 슬롯의 출발수요25% 증가 사건으로 발생. 사실은 심사 접수 성공 때 1회 소비, 접수 실패는 미소비. 사용 사실/판정 전 사실 재사용 불가. 추가 사실이 없으면 다른 사업/재시작으로 복구.

## 4. OD·운영 계산 — PAR-05, SEM-03
- D01~D08 하루 출발수요 순서대로 2000,1500,1200,800,600,400,300,200 통행. 목적지 비중은 다음 동으로1(D08→D01), 자기 목적지0. 비중합1.
- 출발·목적 동 모두 노선 역이 있어야 접근 가능. 같은 동의 여러 역은 노선 이동시간이 최소인 출발/도착 역 쌍에 전량 배분, 동률은 역 ID 순. 접근비율 a=1 또는0. 수요를 여러 역에 복제하지 않음.
- 속도60km/h, 간선1km=1분, 중간역 정차1분. OD 시간=간선수+중간역수. 단순 역순의 대칭 시간은 동일.
- q(T): T≤5분이면1, 5<T≤10이면0.8, T>10이면0.5. 함수 경계 제안.
- 영업1080분(06~24)에 균등 h=1/1080/분. 수송량 U=10통행/게임분, 노선 전체 공유. 미사용 용량은 다음 분 이월하지 않음.
- 분마다 OD 요청 소수 이월→정수 요청. 각 OD에 남는 소수는 다음 분 및 다음날 유지. 가용량 부족 시 OD ID 순서로 배분하는 최소안이며 편향은 검토 위험. 미탑승 정수는 소멸하되 지표 기록.
- 승차 시 이동 중 증가, 도착 사건에서 완료/매출 증가. 도착 완료 전에는 매출0. 운임100×완료통행×회사100%.
- 만족 초기50, 하루변화=5×충족률−5×미탑승률−2×지연률, 0~100 clamp. 충족률=탑승/요청, 미탑승률=미탑승/요청, 지연률=예정 도착보다 늦은 완료/전체 완료. 요청0이면 전일 유지, 완료0이면 지연률0. 값은 내부 유리수 유지, 화면만 소수1자리.
- 경제는 분마다 고정 경계 처리, 마지막 부분분은 누적 보존. 프레임이나 큰 시간 이동 횟수로 용량을 증식시키지 않음.
- 경계 T 처리 세칙 제안: [이전,T)의 공정·운영비 발생 및 미지급 누적→자정이면 전일 마감/새 날짜→대기 계약/지급→기성/완공→시험/개통→T 도착/운임→미지급 정산→영업/재무 상태 판정→T의 신규 승차. 직전 구간 비용은 마감 전에 발생일 비용으로 인식하고, T의 지급/정산 현금 흐름은 T 날짜에 기록한다. 비용을 정산 시 다시 인식하지 않는다.
- 서로 다른 날짜의 탑승/완료를 같은 지표처럼 비교하지 않는다. 보고에는 기초 이동 중+탑승−완료=기말 이동 중 관계를 표시.

## 5. 미지급·예약·취소 세칙 — SEM-01/02
이 절은 OWNER가 선택한 원칙을 구체화한 **추가 검토 대상 세칙**이다. 포함된 수치의 사용 승인과 세칙 전체 승인을 구분한다.
1. 발생 운영비 E를 비용과 미지급 B에 한 번 기록. 지급 가능액=max(0,F−K). 지급=min(B,지급가능액), C와 B만 감소. 정산 때 비용 재인식 없음.
2. B>0이면 신규 출발·탑승과 신규 사업 계약을 차단하고 보고/계획은 허용. 이미 탑승한 승객은 예정 도착 처리 및 완료 과금. 제한 후 잔여 통행의 추가 운영비는 기존 발생분에 포함하는 최소안으로 제안하며 추가 신용을 만들지 않음.
3. 자유 운임 유입 후 미지급 우선 정산, B=0이며 다음 계산 구간 운영비 충당 가능할 때 신규 운행 재개. 정부 제한자금 유입만으로 미지급을 갚지 않음.
4. 모든 회사부담 공사분 K는 보호. F≥운영비여도 F−K<운영비이면 부족 처리. B>0에서 남는 현금을 신규 공사에 먼저 묶지 않음.
5. 기존 예약의 정상 기성 집행은 자기 K와 실재 자유현금 검사, 이미 지출한 K 감소. 공정중단으로 K를 자동 해제하지 않음.
6. MVP 플레이에 계약 취소/공사 총비용 변경 UI는 제공하지 않는 최소안. 시나리오 재시작은 전체 초기화. 개발 검수용 유효 취소 사건은 미집행 K만 해제, 이미 쓴 비용은 되돌리지 않으며 남은 R은 제한 유지. 제품 취소 기능 도입 시 반환/위약금 별도 승인.
7. C<0인 경계 입력에서도 새 차입/지급을 생성하지 않음. 보고·계획 유지, 운행 제한 및 경고. 총현금 음수의 장기 파산 기준은 유지, 현재 MVP 파산 실행은 NOT_IN_MVP.

## 7. 승인방식 제안 — APP-01 / OWNER_PENDING
1. PAR-01~05의 제안 수치는 OWNER 사용 승인 완료. SEM-01~03 및 APP-01 전체 방식은 검토 의견을 받아 별도 확정한다. 이번 PR 제출·부서 검토 요청은 이미 승인됐다.
2. 기획이 승인 원문·버전·선택범위를 기록. 전체 묶음 승인 전 일부 승인만 별도 표기한다.
3. 새 데이터 버전을 Dev/Design에 동일하게 전달하여 산술·상태·공수·UI 검토. 오류/범위변경은 다시 OWNER에 제시한다.
4. HQ가 미해결·조건 수용·통합 견적·검수계획을 검토한 뒤 OWNER가 Gate 2 최종 승인 여부를 결정한다.
5. 이번 작업 브랜치 commit·업로드·PR 제출은 OWNER 직접 승인 범위다. 실제 구현·main 병합·릴리스는 별도 승인한다. 수치 사용 승인을 구현 완료로 간주하지 않는다.

성능 목표/기기·외부 사용성 표본·예산은 현재 제안 수치조차 고정하지 않고 해당 부서 대안 후 OWNER 승인으로 남긴다.
