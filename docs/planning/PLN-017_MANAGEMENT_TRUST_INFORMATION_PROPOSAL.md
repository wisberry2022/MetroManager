## 2. I01 대표 단계·범위·마감과 오늘의 문제

### 2.1 공통 단계 적용

경영진 신뢰도와 관점값에 기존 평가형 항목의 공통 5단계를 적용하는 표시 계약을 제안한다. 아래 수치는 기획/검증용이며 플레이어에게 공개하지 않는다.

| 내부 유효값 | 플레이어 단계 |
|---|---|
| 0 이상 2 미만 | 취약 |
| 2 이상 4 미만 | 미흡 |
| 4 이상 6 미만 | 보통 |
| 6 이상 8 미만 | 양호 |
| 8 이상 10 이하 | 우수 |

최종 단계는 승인된 최종 중대사건 상한까지 적용한 말단값으로, 관점 단계는 해당 관점의 상한까지 적용한 관점값으로 변환한다. 상한 전의 높은 원값을 단계로 대신 표시하지 않는다.

기본 5·미관측은 보통이 아니다. 유효한 실제 낮은 값은 낮은 단계로 정직하게 표시하고, 자료 부족으로 완화하지 않는다. 단계는 이미 승인된 내부 계산 결과에서 도출하며 표시된 직원/주주 단계 문자들을 평균해 최종 단계를 만들지 않는다.

가장 최근 도래한 정상 마감 R에 실제 유효한 평가가 있고 현재 적용 범위와도 맞을 때 대표 단계로 사용한다. R의 기록이 없거나 무효면 오래된 좋은 기록을 현재값으로 대신하지 않고 마지막 유효 평가를 과거로 분리한다. 단계에 마감 날짜와 ‘직원·주주의 경영 경험 기준’, 해당 회사의 실제 기준표/적용 범위를 붙인다. 급여·복지·주가·투자 매력·직원의 심리 조사 전체를 포괄한 등급으로 설명하지 않는다.

현재 알려진 사건은 다른 시각의 정보다. 어제 마감은 우수이지만 오늘 중대한 권리 침해가 확인될 수 있다. 어제 유효 평가의 근거가 유지되면 해당 마감 단계와 오늘의 필수 경고를 함께 표시하며, 새 점수는 승인된 정상 일일 마감에서만 만든다.

오늘 자료만 부족하고 R의 전체 근거는 유효하면 마감 단계는 유지하고 현재 상태 확인 필요를 병기한다. 과거 평가창의 신뢰성까지 훼손됐다면 R의 현재 유효성을 보류한다. 원래 당시 보고와 정정/재검증 상태는 구분한다.

현재 회사의 적용 관점 자체가 달라져 R의 범위와 비호환이면 옛 단계를 현재 회사 전체 평가처럼 표시하지 않는다. 그때의 단계는 당시 범위가 붙은 과거 참고로 둔다. 실제 전환 시점·관점 편입은 M06 결정에 연결하며 이 표시안이 전환 규칙을 먼저 확정하지 않는다.

### 2.2 공개할 업무 사실과 비공개 평가값

| 제공 가능한 실제 업무 정보 | 플레이어에게 제공하지 않는 평가 정보 |
|---|---|
| 실제 약속 내용·대상·업무 기한·이행/미이행·시정 상태 | 정확한 점수·중간값·소수 변화·단계의 수치 경계 |
| 실제 운영계획·배치·직무 결원·영업 이력·자금/손익·제한 자금 구별 | 요인/관점의 가중·점수 환산식·기여율·등급 상한의 숫자 |
| 실제 보고의 대상 기간·전달/정정 여부와 시각 | 목표 몇 개 충족이 몇 점인지, 평가 요인 몇 개가 종합에 얼마를 기여하는지 |
| 확인된 권리 침해·결함·위기·조치와 남은 의무 | 다음 단계까지 필요한 금액·시간·사례 수와 예상 점수 계산기 |
| 실제 회사 관계·지분·권리 범위와 선택/의무에 필요한 조건 | 평가용 재집계 비율·분모/가중표·정밀 요인 순위·비공개 산식의 역산 전용 표 |

실제 계약/운영/자금 목표와 행동 기한이 업무상 공개되는 경우에는 그 사실을 유지한다. 이를 숨겨 필요한 경영 판단을 막지 않는다. 평가만을 위해 만든 95%/목표 충족 수/내부 상한 등을 별도 ‘신뢰 점수 공략표’로 노출하지 않으며, 기존 업무 화면의 실제 정보를 금지하는 의미도 아니다.

같은 단계 안의 두 유효값은 단계의 막대 길이·좌표·농도·아이콘 세부·접근성 숫자·툴팁·평가 내보내기에서 구별되지 않아야 한다. 실제 업무 사건이나 자료 상태가 다르면 그 사실의 표시는 달라도 된다. 단계 색상 외 텍스트/형태 등으로 의미를 전달하며 구체 시각 설계는 Design의 후속 업무다.

## 3. I02 최종값과 직원·주주 관점

최종 경영진 신뢰도와 다음 두 관점을 구분해 전달한다.

- **직원 관점의 경영진 신뢰:** 약속·설명·운영 능력·대응·공정절차·자원 결정에 대한 실제 직원 경험.
- **주주 관점의 경영진 신뢰:** 같은 여섯 요인의 실제 주주 경험. 상장/주가 평가나 투자 추천이 아니다.

이들은 기존 말단값을 설명하는 계산 관점이며 새 정식 상태값 노드가 아니다. ‘직원 만족도’와 혼동하지 않게 명칭과 범위를 구별한다. 각 관점에는 단계 또는 준비/자료 상태와 기준 마감을 붙인다.

| 실제 상태 | 플레이어에게 전달할 의미 |
|---|---|
| 직원·주주 모두 적용되고 유효 | 최종 단계와 양 관점 단계. 두 경험이 함께 반영됨 |
| 직원 유효, 적용 대상인 주주 자료 부족 | 최종 평가 보류·직원 관점의 유효 단계·주주 기록 확인 필요 |
| 주주가 구조적으로 미적용임을 입증 | ‘주주 관점 미적용’과 실제 적용 범위. 불신/최저나 미확인 주주를 가정하지 않음 |
| 주주 존재/관계 자체가 불명 | ‘주주 적용 대상 확인 필요’. 미적용으로 생략하지 않음 |
| 한쪽 관점이 새로 적용되는 전환 중 | 새 관점의 준비/관측 상태와 최종 보류. 기존 한쪽 단계는 해당 관점 범위에서 제공 |
| 현재 미해소 중대사건이 확인됨 | 해당 관점과 현재 사건을 필수 표시. 유효한 낮은 최종 단계가 다른 좋은 관점과 공존할 수 있음을 설명 |

같은 R의 최종값을 설명할 때 관점별로 다른 마감의 좋은 성적을 가져와 조합하지 않는다. 어떤 관점의 마지막 유효 평가가 더 오래됐다면 날짜가 있는 과거 참고로만 표시한다.

여섯 요인은 이름과 연결된 실제 기록·확인 상태로 탐색할 수 있게 한다. 예를 들어 ‘약속 이행 — 기한을 넘긴 개선 약속 있음’, ‘위기 대응 — 해당 기간 평가 사례 없음’처럼 전달한다. 요인별 점수·세부 등급·달성률 보드나 이해관계자 개인별 신뢰 점수는 새로 제공하지 않는다. 현재 회사 적용 관점/범위를 명시해 “모든 직원 또는 주주가 같은 생각”이라고 단정하지 않는다.

상위 대내적 평판은 기존 세 자식의 현재 유효 조건과 직접 자식 평균을 유지한다. 경영진 신뢰도만 유효하다고 상위 종합 단계/추세를 생성하거나 직원 만족도·조직 결속도에 복사하지 않는다.

## 4. I03 추세

최신 도래 마감 R과 정확히 **7게임일 전 마감 R−7일**의 실제 유효 단계를 비교한다. 높은 단계면 ‘개선’, 같으면 ‘비슷한 수준’, 낮으면 ‘악화’다. ‘최근 마감 기준’과 비교 날짜를 함께 제공한다.

같은 단계 내 점수 움직임을 추가 화살표·변화량·명암으로 표시하지 않는다. 비슷한 수준은 원점수나 모든 경험이 같다는 의미가 아니다. 새로운 순위나 추세 전용 내부 점수를 만들지 않는다.

비교는 다음을 모두 만족해야 한다.

1. 해당 항목의 두 마감에 실제 유효한 평가가 있다. 현재 R이 무효면 오래된 두 점으로 현재 추세를 대신하지 않는다.
2. 같은 회사·저장 분기이며 평가/단계/가중·기간·회사 기준표가 호환된다.
3. 최종값은 적용 관점 구성이 같고, 각 관점은 두 날짜에 실제 집계된 요인 범위도 같아야 한다. 기회 없음 요인이 실제 평가에 새로 들어오면 범위가 달라진 것으로 구분한다.
4. 각 시점의 전수 근거와 충분성이 각각 유효하다.

같은 기준표 안에서 실제 매출·직원 수·지분·정상 운영비·새 기간의 유효 계획이 변한 사실만으로 자동 비호환으로 만들지 않는다. 계산의 의미·목표 규칙·대상 고정 방식은 같아야 한다. 단순한 28일 성과기간 교체는 정상 주기이며 그 자체로 비교를 막지 않는다. 같은 승인 규칙에서 중대사건 상한이 실제 발동/해제된 것은 사건 상태의 변화이며 그 자체로 기준 비호환을 만들지 않는다.

직원·주주·최종값의 비교 가능성은 각각 판단한다. 최종 추세는 범위 변화로 보류여도 직원 관점의 두 기록은 호환될 수 있다. 이를 ‘직원 관점 추세’로 구별하며 회사 전체 추세라고 표시하지 않는다. 두 관점의 화살표를 평균해 최종 화살표를 만들지 않는다.

정확히 7일 전 기록이 없으면 6일/8일 전이나 원천자료의 소급 계산을 대신 사용하지 않는다. 두 비교점이 유효하면 중간 화면 이력의 공백과 두 점의 비교 가능성은 구분한다. 다만 그 공백이 실제 평가 근거의 누락이면 유효성을 다시 확인한다.

28일마다 확정하는 F03과 매일 갱신하는 회사 평가는 다르다. 이미 유효한 F03 사례를 사용해 정상 마감마다 실제 재평가한 기록은 유효하다. 실제 마감 평가가 없던 날에 값을 복사하는 것은 허용하지 않는다. 추세가 일주일마다 새로운 28일 성과를 측정했다는 뜻으로 설명하지 않는다.

오늘의 시정·위반·자료 복구는 현재 사실로 안내하며 마감 추세를 즉시 뒤집지 않는다. 창 이탈로 단계가 올라간 경우에는 그 이유를 구분하고 새 경영 행동의 성과라고 단정하지 않는다.

## 5. I04 이유와 현재 필수 상태

대표 평가의 이유는 **확인된 사유 최대 2개**로 요약한다. 관점별 상세를 따로 펼칠 경우 각 관점에도 최대 2개의 해당 범위 사유를 제공할 수 있다. 회사 요약에 직원/주주 사유를 무조건 합쳐 4개로 늘리지 않는다.

| 사유 종류 | 전달 예시 | 피할 해석 |
|---|---|---|
| 실제 약속/보고/절차 경험 | 기한 내 보고한 사례가 반영됨, 미이행 약속이 남아 있음 | 보고 버튼을 눌렀으므로 전체 신뢰 상승 보장 |
| 실제 시정·위기 회복 | 확인된 시정 결과가 이번 마감에 반영됨 | 사과/계획만으로 과거 실패가 없어짐 |
| 실제 성과기간 결과 | 새 운영 성과기간의 결과가 반영됨 | 재정 점수가 곧 경영진 신뢰 점수임 |
| 기억 범위 변화 | 이전 불리한 사례가 집계 범위에서 벗어남 | 지금 새로 개선했기 때문에 상승함 |
| 자료·범위 상태 | 자료를 확인해 평가를 재개함, 평가 범위가 달라 비교 보류 | 자료 복구 자체가 신뢰 회복 실적임 |

사유는 실제 근거와 해당 마감 평가의 연결을 입증할 수 있을 때만 사용한다. 단순히 최근에 일어난 사건을 전체 변화의 원인으로 추측하지 않는다. 근거는 있지만 순변화의 원인이 불명이면 ‘이번 평가에 반영된 사실’로 표현하고 ‘이 때문에 상승/하락했다’고 단정하지 않는다.

사유 선택은 해당 마감에 반영된 확인된 미해소 책임, 실제 시정/새 결과, 기억 범위 변화의 고정된 의미 순서를 기본으로 하고 같은 종류는 실제 최근 시각을 우선한다. 점수 기여도 순위로 정렬하지 않는다. 자료/범위 문제는 아래 필수 상태로도 전달하며 정확한 영향량·기여율·순위를 노출하지 않는다.

**최대 2개는 설명 요약의 한도**다. 다음은 한도와 별도로 전달한다.

- 현재 확인된 중대한 신뢰 훼손 사안과 미해소 여부, 영향 관점.
- 현재 기한을 넘긴 의무와 아직 필요한 실제 조치.
- 적용 대상/범위·과거 근거·오늘 상태의 확인 필요.
- 최신 마감 평가 없음, 예고/첫 평가 대기 등 현재 유효성을 좌우하는 상태.

복수 사안은 묶어서 요약할 수 있으나 전체 확인 목록에 접근할 수 있어야 한다. 한 사안만 보여 나머지가 없는 것으로 오해하게 하지 않는다. ‘현재 문제 없음’은 관련 현재 범위의 전수 근거가 있을 때만 말한다. 일부 문제를 확인했고 다른 범위는 불명인 상태도 함께 표시한다.

상한이 실제 평가에 적용됐다면 ‘미해소 중대사건이 평가를 제한하고 있음’으로 설명할 수 있다. 상한의 숫자·해제 후 예상 단계·숨은 점수 손실량은 공개하지 않는다. 아직 마감 전이면 ‘현재 미해소 중대사건’으로 표시하고 이미 마감 성적에 반영됐다고 말하지 않는다.

실제 시정 완료 후에도 다른 미해소 사건·새 성과·집계 범위에 따라 결과가 달라진다. ‘시정 완료’와 ‘종합 신뢰 회복 완료’를 같은 의미로 쓰지 않는다. 실제 낮은 평가를 자료 부족인 것처럼 숨기거나, 자료 부족을 불신의 확정 증거로 표시하지 않는다.

## 6. I05 과거 성적과 이력

기본 탐색 범위는 R부터 R−27일까지 **최근 28개 마감일**이다. 실제 생성된 단계·그 날짜의 관점/범위·자료 상태와 공백을 보여준다. 숫자가 같은 28일이라도 현재 집계의 기억 범위, F03 성과기간, 화면의 이력 탐색 범위는 각각의 역할을 유지한다.

- 단계만으로 표시하고 소수값 선그래프·단계 내 연속 위치·빈 날 보간은 제공하지 않는다.
- 실제 두 마감에 같은 단계가 나온 기록과, 평가가 없던 날의 공백을 구분한다.
- 기준표·요인 범위·적용 관점이 바뀐 구간은 변화 사실을 표시하고 자동 추세 연결을 하지 않는다.
- 마지막 유효 평가가 기본 28일 밖에 있어도 날짜·당시 범위가 있는 과거 참고로 보존한다.
- 현재와 옛 기준의 단계 이름이 같아도 호환이라고 가정하지 않는다.
- 28일은 세이브·원천자료·미해소 책임·원래 목표/기간/가중의 삭제 기한이 아니다.

호환 과거 기록의 승계·사실 정정·원본/분기 보존 방법은 M04/M07/M08의 선택에 연결된다. 이번 안은 표시할 실제 이력이 있을 때의 표현을 정하며, 미승인 승계 규칙을 이미 실행된 사실로 설명하지 않는다. 과거 기록이 없는데 화면을 채우기 위해 새 성적을 생성하지 않는 원칙은 기존 A09와 일치한다.

원래 보고가 나중에 재검증 대상이 되면 ‘당시 보고·근거 재확인’처럼 상태를 구분한다. 새 현재값을 과거에 덮어써 원래 보고가 없었던 것처럼 만들지 않는다. 상세 정정 이력의 실제 저장/승계는 M07 결정 대상이다.

## 7. I06 준비·자료 부족·다음 행동

상태 이름은 의미 기획이며 기술 enum이나 최종 UI 문구를 확정한 것은 아니다. 플레이어가 기다릴 상황과 실제 자료/의무를 확인할 상황을 구분한다.

| 상태 | 전달할 내용과 다음 확인 |
|---|---|
| 실제 기능/기준 미준비 | 필요한 직원·주주/직무·권한·기준표가 아직 준비되지 않음. 플레이어의 실패로 표현하지 않음 |
| 관점 구조적 미적용 | 확인된 회사 형태/관계상 해당 관점이 없음. 단순 기록 없음과 구분 |
| 적용 대상 불명 | 실제 관계와 남은 책임을 확인해야 함. 기본 정상값으로 채우지 않음 |
| 예고 중 | 확정된 적용 예정 시각과 그때부터의 업무 범위. M01 채택 후 실제 시각을 사용 |
| 첫 보고/성과 판정 대기 | 실제 기간·종료/업무 기한과 아직 판정 전인 사실. 날짜가 왔다고 종합 평가를 보장하지 않음 |
| 평가 사례 없음 | 준비된 범위에 실제 판단 사례가 없음. 건전/불량이나 자동 만점으로 표현하지 않음 |
| 종합에 충분한 경험 미확보 | 관점별로 어떤 분야의 근거가 더 필요한지 설명. 내부 최소 요인 수·점수 진행률을 노출하지 않음 |
| 과거/현재 평가 근거 부족 | 대상·기한·원래 목표·지분·결과 등 확인이 필요한 근거를 안내 |
| 적용 이력 확인 필요 | 원래 적용/기간을 확인해야 함. 새로 시작하면 해결된다고 안내하지 않음 |
| 자료 확인 완료, 다음 마감 대기 | 다음 정상 마감에서 충분성과 현재 범위를 다시 판단. 평가 재개 확정/단계 상승으로 표현하지 않음 |
| 최신 마감 성적 유효, 오늘 상태만 불명 | 마감 단계와 오늘 정보의 부족을 병기 |
| 회사 단계/관점 전환 중 | 해당 새 범위의 기준/자료/완전한 기간이 필요한 상태. 세부 시작/승계는 M06 결정에 연결 |
| 실제 평가 결과가 낮음 | 유효한 낮은 단계와 확인된 이유/남은 조치. 자료 부족으로 감추지 않음 |
| 핵심 세이브 전환 실패 | 평가 자료 부족과 구분. 실제 원본/복구 결과에 맞춰 안내하며 M08의 판정 규칙 확정 필요 |

복수 상태가 동시에 있으면 함께 전달한다. 하나의 ‘평가 중’ 표시로 현재 중대사건·확인할 기록을 감추지 않는다.

실제 업무 기한까지 남은 게임 시간과 보고/성과기간의 예정 종료일은 업무 정보로 제공할 수 있다. ‘다음 단계까지 며칠/얼마’나 ‘28일 뒤 자동 정상’처럼 바꾸지 않는다. 정해진 목표/의무의 실제 처리 결과를 확인해야 하며 데이터 복구나 기간 종료가 성공 실적을 만들지는 않는다.

기존 승인 업무 기한은 B03/B06/B07/B09를 따른다. 예고·최초 기간 시작·관점 전환·호환 승계 시각은 미승인 M01~08에 의존하므로 현재 초안은 실제 확정된 상태를 받아 표시하는 원칙만 제안한다. M안이 바뀌면 관련 문구/예시를 맞추고 승인된 계산 기준은 임의 변경하지 않는다.

## 9. 미승인 적용·승계안과의 연결

| 표시 결정 | 독립적으로 정할 부분 | M안에 의존하는 부분 |
|---|---|---|
| I01·I02 | 단계·관점 명칭·정확한 점수 비공개·현재 사건 구별 | 현재 적용 범위와 첫 유효 마감의 실제 판정 |

현재 결정 상태는 **F/A/B 승인, M 8개 대기, I 6개 신규 제안**이다. 이번에 문서로 제안된 결정 대기는 합계 14개지만 실제 콘텐츠 입력·다른 회사 단계까지 포함한 프로젝트 전체 잔여 건수를 뜻하지 않는다. 이 목록을 1차 최종 통합 완료로 표시하지 않는다.

## 10. 추후 부서 확인과 검증 준비

개발 확인 준비는 최신 정상 마감/관점 유효성·호환 메타·실제 과거 단계·현재 사건·원인 근거·다중 부족 상태를 공급할 수 있는지, 모든 플레이어 제공 경로에서 비공개 점수가 노출되지 않는지다. Design 확인 준비는 최종/관점/현재 문제의 구분, 색상 외 의미 전달, 좁은 화면·접근성·다중 경고·공백/과거값의 이해 가능성이다. 요청은 보내지 않는다.
