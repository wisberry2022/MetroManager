## 1. 사용 기준

게임 의미는 [Owner 결정][O]·[Gate 2 최종 승인][G2] 및 최신 **[C v0.7][C] / [D v0.9][D] / [DATA v1.4][DATA]**를 따른다. [PLN-005][P5]와 R01~03은 확정 상태로 보존한다. D의 이전 연결 버전과 정본에 남은 과거 DRAFT/제안 표현을 현행 정책 미승인으로 되돌리지 않는다. S3 번호는 [PM-020][PM20] §6의 인수 기준안에 대한 추적 연결이며 새 게임 정책 근거가 아니다.

[Stage 2 최종 결정][S2]은 DONE이고 기존 수용 증거를 재사용한다. [PM-020 Planning 요청][REQ]은 이 표의 범위를 정한다. DEV-026은 Stage 3 공식 필수 범위이나 이번 1~2번 준비에서 기술 계약을 대신 확정하거나 과거 HOLD로 되돌리지 않는다.

아래 **W4B-01~30은 이 문서의 반례 색인**이다. 기존 AC/VP/S3 번호를 바꾸거나 실제 테스트30개·GUI30회를 추가하는 번호가 아니다. 각 행의 기대값은 승인된 전제에서의 정적 결과이며 실제값 칸을 PASS로 대체하지 않는다. 모든 행의 신규 엔진/GUI 실행은 NOT_RUN이다.

표의 A/B는 Design Track A/B다. S3-01의 승인 기준 연결은 이 절·고정 원본 목록으로 준비하며 실제 작업 권한/제품 수용까지 PASS로 처리하지 않는다. S3-10의 F-08 심사는 Track B 별도 범위다. S3-11은 후속 통합 인수 연결이지 이번 정적 준비의 완료 판정이 아니다.

## 3. 공급 확인 항목과 RFC 경계

이 표를 작성한 범위에서 승인 수치/정책의 상충을 확정한 건은 없다. 아래는 **DEV_INPUT_PENDING / NOT_VERIFIED**이며 새 Owner 정책 결정을 일괄 요청하는 목록이 아니다. 아직 확인하지 않은 실제 W04B 공급 계약을 이 문서가 대신 승인하지 않는다.

- **DI-01 — 실제 접수/효력/기간/소비 계보:** command·plan/revision·심사/판정 ID와 유효 접수의 원자적 성공 시점, 계획 잠금 전이, 신규 심사/E01 이벤트의 공통 분 단계, 같은 분 E01 발생과 재접수의 실제 순서를 연결해 달라. UI 요청·대기열 등록을 사실 소비/난수 추출 성공으로 오인하지 않기 위한 대조다. 기존 SEM-03/업무시간/기간을 변경해야 하는 차이가 확인될 때만 해당 행을 RFC로 상정한다.
- **DI-02 — RNG 공급:** 정상 엔진/버전·seed·실제 샘플 도메인·분기 경계·추출 대상/시점/순서, 무효/중복 무추출 증거와 실제 정상 성공 seed를 제공해 달라. 70/20/10·60/40은 확정이고 구체 seed 값이나 엔진 호출 형식은 Planning이 만들어내지 않는다. 확률·유효 시도 의미가 달라지는 경우만 정책 충돌이다.
- **DI-03 — E01 수요 연결:** 대상 슬롯의25% 출발수요 증가를 어떤 실제 동/OD 입력에 연결하는지, 소수 보존·예측 revision/실제 수요의 반영 시점과 사건/사용 이력을 제시해 달라. 현재 정본의 지연1440분·관련/판정 이후/미사용·성공 소비/실패 미소비는 유지한다. 슬롯 예시를 미승인 지리 경계로 고정하거나 도시 전체 증가/추가 반복 보상으로 확대하지 않는다. 실제 공급이 승인 의미로 정해지지 않는 선택을 요구할 때만 영향·대안을 분리한다.

실제 충돌이 확인되면 [RFC 양식][RFC]에 해당 표 ID·정본 절·기대/실제·영향 범위·대안·Owner 판단 필요 여부를 기록한다. 현재 RFC 미발행이며 위 입력 확인은 비의존 정적 준비를 차단하지 않는다. 개발 구조·UI 배치·폰트·성능 최종 규격은 각 소관 판단이다.

## 4. 첫 회신에 사용할 요약

- **재사용 가능:** 시청/정부·설득·동일성·사실·확률·공통 자금/기간 규칙을 기존 승인 기준으로 정리했다. 새 수치·정책 승인 요청 없음.
- **정적 준비 결과:** W4B-01~30 대응표와 정상·경계 산술. 실제 실행 결과는 [결과서](tasks/PLN-013_RESULT.md)의 구분을 따른다.
- **미해결의 종류:** DI-01~03의 실제 공급은 NOT_VERIFIED. 실제 정책 충돌을 확인한 것은 아니며 Owner 결정이 필요한 RFC로 미리 승격하지 않음.
