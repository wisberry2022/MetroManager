## 3. COH-I01 대표 단계와 현재성

### 3.1 공통 단계의 적용

기존 평가형 항목의 공통 5단계를 조직 결속도의 유효한 내부값에 적용한다. 아래 표는 OWNER·제작팀의 검증용이며 플레이어에게 제공하지 않는다.

| 내부 유효값 | 플레이어 단계 |
|---|---|
| 0 이상 2 미만 | 취약 |
| 2 이상 4 미만 | 미흡 |
| 4 이상 6 미만 | 보통 |
| 6 이상 8 미만 | 양호 |
| 8 이상 10 이하 | 우수 |

단계는 승인된 결속도 내부값에서 도출한다. 표시 단계들을 다시 평균하거나 영역의 단계를 만들어 회사 단계를 계산하지 않는다. 단계 변화를 줄이기 위한 새 완충 점수·보정·추가 상한도 도입하지 않는다. 실제 낮은 유효값은 낮은 단계로 표시하며 미관측 기본값 5는 ‘보통’으로 표시하지 않는다.

대표 문구의 범위는 **‘조직 결속도 — 업무 협력 경험 기준’**이다. 공동업무 준비·인수인계·업무 일부 지원의 실제 경험에 한정됨을 설명한다. 직원의 친밀감·감정 전체·회사에 대한 충성심·갈등이나 불만의 부재를 보증하는 표현은 사용하지 않는다.

첫 표시에서는 종합 단계 하나를 제공하고 세 영역은 실제 관련 업무·이행·미해결 사실로 설명한다. 영역별 점수/등급표·가중 순위·추가 정식 상태값 노드를 만들지 않는다. 업무 기한·담당·결과·정정 같은 실제 사실은 점수와 구분해 안내할 수 있다.

### 3.2 마감 평가와 지금의 상태

R은 가장 최근 도래한 정상 일일 마감이다. 마감 시각은 실제 게임 마감 이벤트의 일시를 사용하고, 평가 대상 업무일 이름과 구분한다. R에 실제 유효한 결속도 평가가 있고 현재 적용 범위와도 맞을 때만 현재 대표 단계로 사용한다. R의 평가가 없거나 무효이면 더 오래된 좋은 성적을 현재처럼 대신하지 않고 ‘현재 평가 대기’와 날짜가 있는 마지막 과거 평가를 구분한다.

현재 대표 단계에는 해당 마감 시각과 범위를 붙인다. 오늘 새로 생긴 인계 누락이나 실제 시정은 현재 업무 사실이며, 아직 다음 마감 전이라면 마감 단계·추세가 이미 바뀐 것으로 설명하지 않는다. 예를 들어 R이 양호여도 지금 미해결 지원이 있으면 두 사실을 함께 전달한다.

오늘의 일부 상태만 확인되지 않고 R의 근거는 유효하다면 R 단계와 오늘 상태 확인 필요를 병기한다. R의 평가창·사례·승계 근거 자체가 훼손됐다면 현재 대표 단계의 유효성을 보류하고 당시 보고는 과거로 남긴다. 호환 세이브에서 실제 현재성이 유지되는 보고의 복원은 M05대로 인정하며 로드 시각을 새 마감으로 만들지 않는다.

조직 결속도만 유효하다고 대내적 평판 전체의 현재 단계·추세를 생성하지 않는다. 직원 만족도·경영진 신뢰도·조직 결속도 모두 현재 유효해야 한다는 기존 상위 조건과 직접 자식 보유값 평균을 유지한다.

## 4. COH-I02 추세 비교

최신 마감 R과 정확히 **7게임일 전 마감 R−7일**의 실제 유효 단계를 비교한다. 단계가 높아지면 ‘개선’, 같으면 ‘비슷한 수준’, 낮아지면 ‘악화’다. 비교 날짜와 ‘7게임일 전 마감 대비’라는 의미를 함께 전달한다.

같은 단계 안의 소수점 변화는 추가 화살표·퍼센트·강도·속도로 드러내지 않는다. ‘비슷한 수준’은 내부값이나 모든 사건이 같다는 뜻이 아니다. 새로운 추세 점수나 서열을 계산하지 않는다.

비교 조건은 다음과 같다.

1. R과 R−7일에 실제 발행된 유효 평가가 각각 있다. 현재 R이 무효하면 오래된 두 점으로 현재 추세를 만들지 않는다.
2. 같은 회사·저장 분기이고 평가·단계·가중·기억 기간·실제 기준의 의미가 호환된다.
3. 두 시점에 실제 평균에 포함된 영역 구성이 같다. 기회 없음으로 제외됐던 지원 영역이 새로 포함되면 범위 변화로 비교를 보류한다.
4. 각 시점의 전수 근거와 충분성이 유효하며, 판정/승계/정정 문제로 비교 신뢰성이 훼손되지 않았다.

같은 기준 안에서 직원·사례 수가 달라지거나 실제 이행·시정·28일 창의 구성원이 바뀌는 것은 정상 변화다. 이 사실만으로 비교를 막지 않는다. 다만 실제 포함 영역이나 평가 의미가 달라졌다면 같은 조건의 비교가 아니다. 정확히 7일 전 기록이 없으면 6일·8일 전 기록이나 소급 계산값으로 대체하지 않는다.

중간 날짜의 화면 이력 공백과 두 비교점의 유효성은 구분한다. 두 시점의 전수 근거가 충분하고 같은 범위임이 입증되면 두 마감 비교는 가능하지만, 중간 공백을 채우거나 7일 내내 연속 개선했다고 설명하지 않는다. 공백이 실제 평가 근거 누락이라면 유효성을 다시 확인한다.

예를 들어 내부 6.1→7.9는 양호→양호이므로 ‘비슷한 수준’, 5.9→6.0은 보통→양호이므로 ‘개선’이다. 이 숫자는 내부 검증용이다. 오래된 낮은 완료 경험이 기억 창 밖으로 나가 단계가 올랐다면 기간 구성 변화임을 설명하고 새로운 협력 행동의 성과로 단정하지 않는다. 현재 미해결이 시간이 지나 사라졌다는 설명은 승인 규칙과 다르므로 사용하지 않는다.

## 5. COH-I03 평가 사유와 현재 남은 문제

대표 평가의 사유는 **확인된 사실 최대 2개**로 요약한다. 해당 마감의 실제 평가와 연결되는 근거가 있어야 하며 단지 최근 일어났다는 이유로 원인에 넣지 않는다.

| 사유 종류 | 플레이어에게 전달할 예시 | 구분할 의미 |
|---|---|---|
| 확인된 미해결 책임 | ‘기한을 넘긴 인수인계가 이번 평가에 반영되었습니다.’ | 원래 책임·기한·미이행이 확인된 사례만 해당 |
| 실제 시정 | ‘누락된 지원 업무를 바로잡은 결과가 반영되었습니다.’ | 사과/계획만으로 해결된 것이 아님 |
| 정상 이행 | ‘공동 준비를 정해진 시각까지 마친 경험이 반영되었습니다.’ | 최종 매출/운행 성과를 그대로 협력 성적으로 바꾼 것이 아님 |
| 기억 범위 변화 | ‘일부 완료 경험이 최근 집계 기간에서 제외되었습니다.’ | 새 협력의 성공/실패나 미해결 자동 소멸과 구분 |
| 사실 정정·자료 복구 | ‘확인된 기록 정정이 이번 마감 평가에 반영되었습니다.’ | 새 시정 행동·과거 정상 이행의 소급 창작과 구분 |

순변화의 원인까지 입증할 수 없으면 ‘이번 평가에 반영된 사실’로 표현한다. ‘이 일 때문에 단계가 올랐다’고 추정하지 않는다. 정확한 기여량·감점·영역 가중·등급까지 남은 사례 수는 공개하지 않는다.

선택 순서는 해당 마감에 반영된 확인된 미해결, 실제 시정/정상 이행, 기억 범위 변화/사실 정정을 기본으로 한다. 같은 종류는 실제 관련 사건 시각이 최근인 것을 우선하고, 동률은 고정된 원래 사례 순서로 안정되게 선택한다. 점수 기여도나 숨은 중요도 순위로 정렬하지 않는다. 같은 원래 사례를 두 사유로 중복 강조하지 않는다.

### 5.1 요약 한도와 별개로 전달할 사실

- 지금 확인된 미해결 협력 문제와 실제 남은 의무·기한·담당.
- 실제 시정됐으나 다음 마감 평가에는 아직 반영되지 않은 상태.
- 필요한 자료나 적용/승계 범위를 확인 중인 상태.

이 사실들은 요약 사유 2개에 들지 않았다는 이유로 숨기지 않는다. 현재 문제의 존재를 알리고 각 확인된 문제와 필요한 업무를 확인할 수 있게 한다. 구체적인 펼침 방식·배치는 디자인 후속 범위다. 실제 문제 수·업무 기한 같은 사실은 제공할 수 있지만 ‘등급을 올리기 위해 몇 건을 처리하라’는 점수 목표로 바꾸지 않는다.

현재 문제가 있더라도 종합 단계가 양호일 수 있다. 승인된 별도 중대 상한 없음은 유지하며 표시를 이유로 새 상한을 추가하지 않는다. 반대로 전체 평가 자료가 부족하더라도 확인된 현재 문제는 보존한다. 승계 판정이 불명한 실제 문제는 ‘평가 포함 여부 확인 중’처럼 구분하고 이미 점수에 반영됐다고 말하지 않는다.

문제 해결 안내는 실제 누락된 정보·접근·역할·잔여 책임을 가리킨다. ‘인계 내용을 복구하고 남은 담당을 정리하세요’는 가능하지만 ‘이 조치를 하면 다음 단계가 됩니다’라는 결과를 보장하지 않는다. 정당한 휴식·자격 제한에 따른 거절을 불성실로 표현하지 않고 의견 차이·불만·단체행동을 결속 실패의 자동 원인으로 삼지 않는다.

## 6. COH-I04 과거 단계와 공백

기본 이력 탐색 범위는 R부터 R−27일까지 **최근 28개 마감일**이다. 실제 발행된 각 마감의 단계·범위·자료 상태를 보여주고, 보고가 없는 날은 공백으로 남긴다. 28일 기억 기간, 7일 추세 간격, 28개 마감일 이력 보기는 서로 다른 역할이다.

- 단계 이름/구간으로 표현하고 소수값 선그래프·단계 안 연속 위치·빈 날 보간을 제공하지 않는다.
- 실제로 같은 단계가 평가된 날과 평가 자체가 없던 날을 구분한다. 이전 날짜의 값을 복사해 새 보고를 만들지 않는다.
- 미도입·평가 대기·이력 없음·기록 확인 필요를 실제 근거에 따라 구분한다. 보고가 유실됐는지 발행되지 않았는지 모르면 한쪽으로 단정하지 않는다.
- 기준이나 실제 포함 영역이 달라진 구간은 표시하고, 비교 조건이 충족되지 않으면 추세를 연결하지 않는다.
- 마지막 유효 평가가 28일 밖에 있어도 원래 날짜·당시 범위가 있는 과거 참고로 보존한다. 기본 보기 밖이라는 이유로 실제 과거 보고를 삭제하지 않는다.
- 현재 R의 평가가 없으면 오래된 좋은 단계를 현재 대표값처럼 배치하지 않는다. 현재는 대기, 옛 단계는 ‘마지막 유효 평가’다.

과거 보고의 사실 오류는 M07에 따라 원본과 연결된 정정 기록을 구분한다. 당시 실제 보고가 있었고 수정 근거가 검증된 경우에는 그 보고의 정정된 단계와 정정 사실을 과거 정보로 설명할 수 있다. 이를 그 날짜에 새 보고가 발행됐거나 정정일에 새 협력 경험이 생긴 것으로 표현하지 않는다. 원래 보고가 없는 날에 정정 자료만으로 가상 보고를 만들지 않는다.

정정으로 최신 R의 근거가 훼손되었다면 R을 현재 유효 단계로 유지하지 않는다. 정정 결과는 구분 보존하고 다음 정상 마감에서 현재 평가를 다시 판단한다. 과거 비교점은 실제 원래 보고에 연결된 검증된 정정 결과를 사용할 수 있지만, 현재 R의 유효성과 두 시점의 호환 조건을 별도로 충족해야 한다. 실제 시정은 원래 낮은 과거를 지우지 않고 이후 시정 시각의 경험으로 남는다.

## 7. COH-I05 자료 상태와 비공개 경계

### 7.1 자료 부족의 의미

| 상태 | 플레이어에게 전달할 의미 |
|---|---|
| 평가 준비 전 | ‘업무 협력 평가를 위한 준비가 아직 끝나지 않았습니다.’ |
| 최초 예고 중 | 예정 적용 시각·대상 업무·이어받을 책임과 원래 기한을 안내 |
| 첫 평가 자료 수집 중 | ‘현재 평가를 내기 위한 실제 협력 경험을 모으고 있습니다.’ |
| 사례/영역 범위 부족 | ‘다양한 협력 경험이 충분히 확인되지 않았습니다.’ 실제 필요한 자료 범위를 설명 |
| 평가 대상 기회 없음 | 전수 관측 결과 해당 평가 범위의 실제 기회가 없음을 설명. 실제 높은/보통 성적으로 표시하지 않음 |
| 진행 중인 책임의 결과 대기 | 아직 원래 기한 전인 실제 업무의 결과를 기다리는 상태. 미해결 실패와 구분 |
| 무채점 종료만 있어 실적 부족 | 업무 필요가 정당하게 끝났지만 평가할 완료 경험은 부족한 상태. 성공 또는 기회 없음으로 바꾸지 않음 |
| 판정 자료 부족 | 원래 책임·기한·실제 결과 등 확인할 자료가 부족함을 설명 |
| 적용/승계 확인 필요 | 이전 적용 경계·원래 의무·현재 남은 책임의 연결을 확인해야 함을 설명 |
| 정정/재검증 중 | 당시 보고와 그 근거를 다시 확인하고 있음을 구분 |
| 자료 확인 후 다음 마감 대기 | 다음 정상 마감에서 충분성과 현재 평가를 다시 판단. 높은 단계나 평가 재개를 미리 보장하지 않음 |
| 핵심 세이브 전환 실패 | M08의 전환 실패와 원본 보존을 안내. 평가 자료만 부족한 정상 플레이 상태와 구분 |

자료 상태는 여러 개가 함께 있을 수 있다. 예를 들어 인수인계 자료 부족과 상호 지원의 결과 대기를 함께 표시한다. 현재 확인된 문제도 같이 알리며 하나의 포괄적인 ‘자료 부족’으로 모두 덮지 않는다. 부분 자료가 있다는 이유로 결속도 현재값을 임의 생성하지 않는다.

기회 없음은 오늘 일이 없거나 현재 직원이 0명이라는 사실만으로 판단하지 않는다. 승인된 기억 범위의 과거 경험과 현재 미해결을 확인한다. 퇴사·부서 이동·현재 인원 변화만으로 유효한 최근 경험이나 남은 책임을 삭제하지 않는다.

최신 마감 근거가 유효한 상태에서 오늘의 정보만 부족하면 마감 단계와 오늘 상태를 병기한다. 평가창의 근거 자체가 불명해지면 현재 평가는 보류하고 마지막 유효 보고를 과거로 분리한다. 유효한 실제 낮은 평가를 자료 부족으로 완화하지 않는다.

안내는 실제 업무를 이어가거나 필요한 원래 자료·승계 근거를 확인한 뒤 정상 마감에서 재판단한다는 수준으로 제공한다. ‘평가 표본 2/3’, ‘지원 한 번만 더 하면 상승’, ‘28일 뒤 자동 정상’ 같은 점수용 진행률·보장은 제공하지 않는다. 일부러 불필요한 협력 업무를 만들도록 유도하지 않는다.

### 7.2 모든 플레이어 제공 경로

| 제공할 수 있는 실제 정보 | 제공하지 않는 평가 내부 정보 |
|---|---|
| 단계·마감/비교 날짜·평가 범위·자료 상태 | 정확한 값·소수 변화·단계 수치 경계·산식/가중 |
| 실제 업무·역할·기한·정상 이행/미해결/시정 사실 | 사례의 10/5/0 점수표·영역 값·정밀 기여율/순위 |
| 확인된 현재 문제 수·누락 내용·남은 업무·실제 시정 결과 | 등급까지 남은 점수·금액·시간·표본 수와 예상 단계 계산기 |
| 실제 보고·공백·정정·비교 불가 사유 | 추정 과거 점수·빈 날 보간값·미관측 기본 5의 정상 단계화 |

같은 단계의 서로 다른 내부값은 단계 막대 길이·위치·색 농도·아이콘 세부·애니메이션 강도·툴팁·접근성 숫자·평가 내보내기 등으로 구별되지 않아야 한다. 실제 업무 사실이나 자료 상태가 다르면 그 사실의 표시는 달라도 된다. 플레이어에게 제공하는 숨은 속성·진단/로그에도 정확한 평가값을 노출하지 않는다.

색상만으로 단계를 전달하지 않고 텍스트 등으로 같은 의미를 제공한다. 자료 부족 문구에 내부 클래스·필드·DB 오류 같은 구현 용어를 넣지 않는다. 구체적인 시각·입력·접근성 구현은 디자인/개발 후속 확인 대상이다.

## 11. 작성 상태

COH-I01~05는 아직 미채택이며 승인 기준선에 정책으로 편입하지 않았다. [작업 티켓](tasks/PLN-018_ORGANIZATIONAL_COHESION.md)과 [결과](tasks/PLN-018_RESULT.md)에 승인/미결·검증을 구분한다. 개발·디자인 검토 요청, 구현 착수, 원격 게시·PR·main 병합은 수행하지 않는다.
