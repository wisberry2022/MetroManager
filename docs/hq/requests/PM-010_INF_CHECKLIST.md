# PM-010-INF — AI Infra / Gate 3-1 업무 연속성 위험 확인

- **대상:** AI Infrastructure Manager (INF). **참조:** [INF 운영](../../infra/README.md), [인계 정책](../../infra/AGENT_HANDOFF_TEMPLATE.md), [PM-008](../PM-008.md).
- **문서 상태:** REQUEST_FOR_INPUT / HQ 제안. Gate 3-1 진입은 Owner 승인, 최초 Stage의 실행 범위·티켓별 Git 쓰기·main Merge/릴리스는 **미승인**.
- **공통 기준:** `main` `5a24ddb375b5859a033055566353e932754a525e` (실제 회신 시 최신 SHA 재확인); [Gate 2 승인](../../planning/PLN-001_GATE2_FINAL_APPROVAL.md), [PM-008 운영](../PM-008.md), [Gate 3-1 요청 개요](../PM-010_GATE3_1_REQUESTS.md).
- **요청 목적:** Stage 계획을 확정하기 위한 **확인·선택·부서 소관 제안**. 이번 문서만으로 실제 코드/씬/아트 제작, 새 기능·기획 수치 승인, Commit/Push/PR 권한이 발생하지 않음.
- **응답 방식:** 각 항목에 `READY / PENDING / BLOCKED / NOT_APPLICABLE`와 **한 줄 근거·관련 Issue/파일·해소 담당·필요 시점**을 기재. 원칙적으로 기존 해당 Issue 댓글이나 본 HQ PR의 댓글로 회신하며 별도 장문 문서 작성 불필요. `PENDING`만으로 전체 착수를 봉쇄하지 말고 **어느 작업부터 차단되는지** 분리.

## 간단 확인 체크리스트 — 게임 설계 검토 아님

- [ ] Stage 계획을 확정·공유할 시점에 **실제 진행 중인 에이전트 교체/인수인계**가 있는지, 해당 티켓·Owner 승인·담당 전환 시점이 명확한가?
- [ ] 부서별 세션이 새로운 Stage 계획의 **기준 SHA/Owner 승인 범위/다음 안전 행동**을 읽고 인수할 수 있는가? 자동 세션 동기화를 전제로 하지 않는가?
- [ ] 작업 연속성을 막을 **확인된 위험**(중복 담당·미공유 로컬 작업·승계되지 않은 권한 등)이 있는가? 없다면 `NO_KNOWN_BLOCKER`로 회신할 수 있는가?
- [ ] 예방적 세션 점검을 하더라도 기존 건강 진단을 전면 반복하거나 **게임 개발/Stage 계획의 필수 선행 게이트로 추가하지 않는가**?

## 회신 요건

Stage 계획에 **직접 영향을 미치는 위험만** 2~5문장으로 회신 가능합니다. 게임 WBS·아키텍처·디자인 품질·기획 규칙을 판단하지 않습니다. 비공개 세션 평가 원문·점수/대화 전문을 공개 Issue·PR에 올리지 않습니다. 현재 새 진단·세션 교체나 Git 쓰기를 이번 요청만으로 지시하지 않습니다.
