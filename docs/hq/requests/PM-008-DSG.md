## 목적
승인된 MVP 8영역·MUST 11개·AC·두 VP를 위해 필요한 **화면·상태·공통 UI·픽셀 아트·에셋 재사용** 작업을 자체 분해하고 실제 플레이어가 느낄 혼란·가독성·접근성 위험을 점검한다.

## 분석 요청
1. 4구·8동·후보역 12개 및 노선당 서로 다른 6~8역의 지도, 관할, 선택/오류 표시를 분해한다.
2. 공공입찰·자체 제안, 공정·안전, 운행, 자금 C/R/F/K/A/B, 당일/과거 보고의 표시 상태와 공통 컴포넌트를 매핑한다.
3. 기존 에셋/스타일/아이콘 재사용 우선순위를 검토하고 신규 컴포넌트와 중복 제작 후보를 구분한다.
4. Development와 필요한 `의미 필드/기준 시각/원인·허용 행동/데이터 없음 vs 0` 계약 질문을 정리한다.
5. 목표 PC·뷰포트·동시 표현/FPS 등 Owner 선택이 필요한 조건은 Design/Development 공동 대안으로 남긴다. 근거 없는 '사용자 거부감 없음'이나 실제 UX PASS를 주장하지 않는다.
6. 실제 디자인 제작은 정식 작업별 권한 승인 후 진행한다.

## 제출 형식
`화면/컴포넌트 ID, 연결 기능·AC, 신규·재사용 여부, 최소 산출물, 사용자 위험/검수, 입력 계약, 선행 조건, 병렬화, L1/L2/L3 의견`을 표로 제시한다.

## 완료 기준
부서 전문 영역에서 독립 제작 가능한 작업과 교차 입력이 필요한 작업이 구분되고, 공통 스타일·재사용·가독성 판단 근거가 기록됨. 게임 경제 규칙/개발 아키텍처를 임의 결정하지 않음.
