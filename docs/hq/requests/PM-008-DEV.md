## 목적
Godot에서 **실제 동작·검증 가능한 MVP 구현 작업 단위**를 분해하고 기술 선행관계·첫 Vertical Slice 후보·QA 계획을 제안한다. 기획팀 전체 분석 완료 대기 금지.

## 분석 요청
1. 현 추적 소스/엔진 환경·주요 Scene/Script/입출력 파일의 존재·부재를 직접 점검한다. 이전 DEV-005 시점의 분석을 현재 구현 상태로 단정하지 않는다.
2. MUST 11개, AC-01~10, VP-01/02를 데이터·Godot 구현·테스트 작업에 매핑한다.
3. 행정·관할/역 후보→시간/거래/미지급→사업 취득/심사→시공/시험→OD/운임/일일 보고→UI 통합의 의존성을 독립적으로 검토하되, 단계 순서는 기술 분석 후 확정한다.
4. 사업별 보호 R, 예약 K, 미지급 B, 자정/동시각 사건, 잔여 승객 추가운영비0, 재현 시드·명령 로그를 구현/검수 경계로 명시한다.
5. Design에 전달할 상태·시간·이유/허용 행동 및 재무 UI 의미 필드 계약을 별도 작업으로 제안한다.
6. Godot 프로젝트 로드, 자동/회귀, 실제 게임 플레이, Windows 빌드/성능의 각 검증 시점을 구분하고 미실행은 NOT_RUN으로 표시한다.
7. 첫 플레이 가능한 Vertical Slice 후보와 리스크를 하나 이상 제시한다. 적정 확장성에 집중하되 미승인 미래 기능·과도한 추상화는 제외한다.

## 제출 형식
`작업 ID, 승인 기능/AC/VP, 종속 작업/담당, 구현 범위/비범위, 산출물, 독립 검증법, 실제 실행 필요 환경, 병렬 가능 여부, 예상 통합 리스크, 등급(L1/L2/L3)`.
