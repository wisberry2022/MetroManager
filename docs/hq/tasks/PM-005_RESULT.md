## 7. HQ 소관 결정 및 추가 질의

다음은 이번 Owner 요청 범위 안의 **HQ 관리 결정**이며 게임 규칙·전문 설계의 승인이 아니다.

1. **게이트:** 이번 수정본을 조건부 접수한다. 개별 정책 선택 준비와 재검토는 진행 가능하지만 최종 Gate 2 승인 상정은 §3~4의 해소 증거 확보까지 보류한다.
2. **우선순위:** Q06 → Q01/Q04/Q05 시간 기준을 P0 묶음으로 먼저 처리한다. Q02/Q03/Q05 수요/Q07/Q08은 P1이며 Gate 2 범위 고정 전에 결론 필요. Q03/Q07을 P1로 분류해도 최종 승인 이후로 미루는 뜻은 아니다.
3. **인수인계:** 같은 승인 규칙/검수 데이터 버전과 SHA를 Dev/Design에 전달한다. 회신은 기존 ID별 수용/조건/미해결, 기능·AC 영향, 변경 공수, 입력 의존성, 미실행 항목을 포함해야 한다. 기존 회신을 최신 재검토로 재사용하지 않는다.
4. **재현 인수:** 저장 MUST 여부와 별개로, 각 VP를 독립 초기 상태에서 같은 버전·시드·입력/시각으로 반복하고 거래/상태/보고 결과의 동일성을 판정할 계획을 필수 인수 입력으로 한다. 제공 방식은 Dev 결정, 저장 범위는 Owner 결정. 실제 실행 증거는 구현 검수 때 요구한다.
5. **범위/일정:** 8영역·두 경로를 유지한다. 재작업을 줄이기 위해 결정 전 작업량은 선택지별 영향 비교까지만 접수하고 확정 날짜를 약속하지 않는다. 고충실도 재무/상태 화면 확정은 해당 규칙 결정 이후로 순서를 조정한다.
6. **사용성 인수:** 내부 두 VP 검수에는 “수요가 큰 동 / 사업 통과·실패 이유 / 개통의 회사 재무 효과”를 관찰 기록 항목으로 고정한다(C §1-2). 외부 사용자 표본 수·통과율·모집 예산은 이번 HQ가 임의 확정하지 않는다. Design이 테스트 목적·표본/비용 대안을 제시하고 Owner가 예산/품질 목표를 결정한 뒤 HQ가 별도 계획으로 고정한다. 이는 게임 규칙이 아닌 인수 계획의 미결정이며 BLOCK-07에 포함한다.
