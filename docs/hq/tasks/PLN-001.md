# PLN-001 — 게임 콘셉트 구체화 및 HQ 인수인계 지시서 (초안)

- 발주: HQ (PM)
- 대상: Planning Agent (별도 ChatGPT 세션)
- 상태: DRAFT / Owner 업무 배정 승인 대기
- 선행사항: Owner가 직접 구상한 게임 콘셉트 설명 제공
- 기준 저장소: `https://github.com/wisberry2022/MetroManager.git`
- 근거: PM-001 운영체계 승인, AGENDA 1 Owner 제안

## 1. 업무 목표

Owner의 원안을 보존하면서 기획 전문가로서 콘셉트를 구체화하고, HQ가 MVP 범위와 프로젝트 수행 계획을 수립하는 데 필요한 정보를 전달합니다. **HQ는 게임 시스템을 대신 기획하거나 세부 디자인·기술 결정을 승인하지 않습니다.**

## 2. 수행 지침

1. Owner가 전달한 원안과 기획팀의 추가 해석을 문서에서 명확히 구분하십시오.
2. Owner와 콘셉트의 핵심 의도·경험·차별성을 검토하십시오.
3. 우선 `PLN-001-A` 및 `PLN-001-B`를 작성하고 `PLN-001-D`로 Gate 1 제출하십시오.
4. HQ 검토 및 Owner의 콘셉트 승인 전에는 해당 문서를 공식 확정본으로 표기하지 마십시오.
5. Gate 1 승인 이후 `PLN-001-C` MVP 범위 초안을 작성하십시오.
6. MVP 범위에 기술적·디자인적 판단이 필요한 부분은 질문으로 분리하여 HQ로 전달하십시오. 기획팀이 임의 확정하지 마십시오.
7. 디자인팀과 개발팀의 검토가 접수된 이후 `PLN-001-D`로 Gate 2 승인 자료를 제출하십시오.

## 3. 산출물

- 필수 / Gate 1: `PLN-001-A` 콘셉트 정의서, `PLN-001-B` 핵심 플레이 루프 및 시스템 관계서, `PLN-001-D` HQ 통합 인수인계서
- 필수 / Gate 2: `PLN-001-C` MVP 범위 정의서 및 갱신된 `PLN-001-D`
- 필요 시: Owner 결정 요청서 또는 기존 `RFC_AND_DECISION` 양식을 활용한 RFC

## 4. 업무 경계

- 기획팀: 플레이 목적, 핵심 규칙, 게임 콘셉트와 범위 제안
- 디자인팀: 비주얼·UX 제작 규모 및 화면·에셋 관련 판단
- 개발팀: 구현 가능성, 기술적 위험, 예상 작업 단위 및 개발 견적
- HQ: 검수·의존성·리스크 통합, 승인 상정, 일정 수립
- Owner: 콘셉트, MVP 범위, 주요 변경, 계획 최종 승인

## 5. 완료 조건

- [ ] Owner 원안이 정확하게 보존되고 추가 기획과 구분됨
- [ ] 플레이 경험과 핵심 루프를 이해할 수 있음
- [ ] Gate 1에서 검토할 Owner 선택사항이 명료함
- [ ] MVP에서 검증할 기능과 비범위가 구분됨 (Gate 2)
- [ ] 디자인·개발 측 검토 요청이 명확하고 결과가 접수됨 (Gate 2)
- [ ] 최종 인수인계 문서에 버전·상태·근거 경로·미결정 사안이 기록됨

## 6. 일정 관련 주의

PLN-001 산출물은 개발 일정 산정의 입력 자료입니다. 기획팀은 작업량을 임의 추정하거나 출시 일정을 확정하지 않습니다. HQ는 Gate 2 승인 이후 디자인팀·개발팀의 작업량/리스크 추정과 Owner의 개발 가능 시간을 취합해 별도 일정안(Gate 3)을 제시합니다.

2026-10-31 GitHub 플러그인으로 원격 저장소 파일 목록과 주요 문서 본문을 확인했습니다. 이번 확인은 DEV-001 전체 검수를 의미하지 않습니다. 개발팀은 기존 파일명을 조사한 뒤 중복·충돌 없는 경로로 배치합니다. Git Push는 문서 승인과 다르며, 공식 승인 표시는 별도 결정 기록이 있어야 합니다.
