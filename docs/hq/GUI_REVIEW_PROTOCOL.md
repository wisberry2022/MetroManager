# 부서 공통 GUI 검수·증거 재사용 지침

- 작업: PM-015 / HQ / AGT-PM-0002 / 2026-11-14 / v1.0.
- 상태: REVIEW — Owner가 Design 제안과 HQ 보완 의견의 문서화·작업 브랜치 게시·PR 제출을 지시했다. 공통 배포본은 Owner의 별도 병합 승인 후 main의 이 경로로 안내한다.
- 적용 대상: HQ, Development, Design Track A/B, Planning, INF, Convention. 기존 승인 명세·PM-014 수용 기준·티켓별 실행/Git 권한을 유지한다.
- 작성 기준 main: `49590f3f1b870fac2af7c77bb4cf179933699b8d`. 문서의 현황 표는 이 시점의 스냅샷이며 이후 판정은 연결된 Issue/PR에서 확인한다.

## 1. 업무 시작 시 읽을 핵심

1. 승인된 필수 조건과 이번 변경의 영향 범위를 확인한다. 검수 시작 전에 시험본·필수 행·기대 결과·차단 대상·종료 조건을 정한다.
2. 이미 수용된 증거는 관련 코드·입력/표시 계약·데이터·엔진/환경의 영향을 확인해 재사용한다. main SHA 변경만으로 GUI를 반복 실행하지 않는다.
3. DEV는 준비된 검수 패킷을 한 번 전달하고, Design은 수정 요청을 묶어서 회신한다. 기능 결함·증거 누락·기록 정정을 구분한다.
4. 독립 GUI 실행과 Design의 결과 심사는 구분한다. 충분한 독립 실행 증거가 있으면 같은 GUI의 재실행을 기본 의무로 두지 않는다.
5. 실제 관측한 증거는 여러 인수 항목에 함께 연결한다. 관측하지 않은 필수 예외를 PASS로 확대하지 않는다.
6. NOT_RUN·NOT_VERIFIED·PARTIAL은 정확한 범위와 함께 기록한다. 그 표시만으로 관련 없는 작업 전체를 중단하지 않는다.

새 세션 또는 관련 작업 시작 시 본 지침의 승인/병합 상태와 자기 담당 행을 확인한다. 이미 읽은 뒤에는 관련 변경분과 최신 판정만 확인하되 저장소 공통 지침의 필수 확인은 유지한다. PR 게시만으로 다른 채팅에 지시가 전달되거나 자동 숙지됐다고 가정하지 않는다.

## 2. 재검수 판단

| 변화 또는 발견 | 처리 |
| --- | --- |
| 관련 코드·계약·지원 환경에 영향이 없는 변경 | 기존 수용 SHA·증거와 영향 없음의 근거를 연결한다. GUI 재실행 없음. |
| 문구·ERROR 집계·링크·증거 색인 정정 | 원본 보존 후 문서·로그·해시 대조로 정정한다. 기능 재검수로 전환하지 않는다. |
| main 진전·병합 SHA 변경·무관한 문서 변경 | 관련 diff와 시험본의 동등성을 확인한다. SHA 차이 자체는 재실행 사유가 아니다. |
| 화면·포커스·스크롤·허용 행동·상태 소비 변경 | 변경된 행과 직접 영향을 받는 정상/실패 조건을 재검수한다. |
| 공통 시간·원장·명령 처리 변경 | 영향 자동 회귀와 사용자에게 보이는 상태 전이·조작을 확인한다. 영향이 넓거나 불명확하면 검수 범위를 확대한다. |
| 새 결함 또는 증거 신뢰성 훼손 | 영향을 받는 판정과 재개방 이유를 명시한다. 공유 증거가 훼손됐다면 그 증거에 의존한 항목도 확인한다. |
| 엔진·렌더러·대상 환경 변경 | 변경된 지원 조건을 검증한다. 이전 환경의 수용을 일괄 취소하거나 새 환경에 자동 승계하지 않는다. |

전체 경로 재실행은 실제 통합 동작이 달라졌거나 기존 완주 증거를 사용할 수 없다는 근거가 있을 때 판단한다. 실패·불명확한 영향은 숨기지 않으며, 기존 자동 회귀·필수 CI를 이 표로 면제하지 않는다.

## 3. 한 패킷·한 피드백으로 진행

DEV는 고정 시험 SHA, 재현 입력/fixture 버전, 엔진·환경, 자체 검증, 알려진 결함·미실행, 독립 실행에 필요한 조작·관측 방법을 함께 제공한다. 사유 렌더링용 소비 fixture와 실제 제품/모델 결과를 구분하고 가짜 성공을 제품 증거로 사용하지 않는다.

조건별 증거는 기존 보고서/로그를 가리키는 짧은 색인으로 연결한다. 최소 내용은 조건 ID, 기대/실제 결과, 실제 입력과 상태 전이, 화면·로그·필요한 원장, 실행/종료 정보다. 환경·공통 입력은 패킷에 한 번만 기록해도 된다. 실행별 고유 식별자를 사용해 캡처 덮어쓰기를 방지하고 원본 해시와 접근 위치를 보존한다. Owner 제한 원본의 접근이 불가능하면 검증 수준을 명시한다.

독립 실행자는 개발 구현·자체 검증과 구별되는 실행 주체와 시험본을 기록한다. Design은 독립 실행의 실제 입력→상태→화면 원본을 심사하고 수용 범위를 책임진다. DEV 캡처만을 심사한 것을 독립 GUI 실행으로 바꾸지 않는다. 최초 실제 조작 인수를 정적 캡처만으로 대체하지 않으며, 증거가 부족한 행만 직접 실행 또는 보완한다. 별도의 상설 검수 조직을 신설하는 규정은 아니다.

Design은 대표 Issue/PR 한 곳에 수정 요청을 묶고 DEV는 각 행에 결과·근거를 연결한다. 다른 Issue에는 상태 요약과 링크만 둔다. 기능 결함은 영향 행 재검수, 로그 누락은 필요한 증거 보완, 집계·설명 오류는 기록 정정으로 처리한다. 단순 수신 확인 때문에 전체 검수 회차를 재시작하지 않는다.

도구로 확인 가능한 파일 무결성·누락·집계는 자동 요약을 우선 활용하되 실제 가독성·조작 판정과 구분한다. 새로운 도구/runner 변경은 담당 부서의 승인된 작업 범위에서 수행한다. 새 검수 시스템 구축을 선행조건으로 만들지 않는다.

## 4. 통합 증거와 필수 범위

- PM-014의 실제 제품 완주 기준은 B01→계약→표준 공사→시험/안전→운행→첫 유효 실적 보고→다음 사업 조회다. 다음 사업의 실제 수주까지 요구하지 않는다.
- 한 실제 실행을 S2-08·09·10 등 여러 항목에 공동 사용하되 실제 관측한 조건만 연결한다. 정상 완주에서 발생하지 않은 오류·0·자료 없음·버전 구분 등 필수 예외는 기존 유효 증거 또는 해당 조건의 추가 검증으로 확보한다.
- 빠른 공사의 결함·수리·재시험은 자동 회귀와 필요한 상태 UI 검증으로 확보한다. 빠른 공사의 독립 전체 사업 E2E 반복을 Stage 2 추가 의무로 만들지 않는다.
- S2-11은 DEV·Design·필요한 Planning 회신·CI·미해결/이월·HQ 통합·Owner 결정을 연결한다. 번호가 다르다는 이유만으로 게임을 다시 완주하지 않는다.
- DEV-019 Q05의 4개 경계×1/2/4배속 12조합 및 정지/재개 증거는 기존 합의를 유지한다. 단일 시간 점프는 실제 배속 증거를 대체하지 않는다. 범위 축소는 변경 근거와 필요한 부서 협의·Owner 결정 후 별도로 반영한다.

자동검사 PASS, 실제 GUI 관측, Design 독립 수용, Owner Stage DONE은 서로 다른 판정이다. 승인된 필수 조건의 생략·게임 규칙 변경·인수 기준 완화는 본 지침에 포함하지 않는다.

HQ는 기존 추적 기록 한 곳에 다음 열을 유지한다. 모든 부서가 별도 장문 문서를 만들거나 매 PR마다 같은 집계표를 수정할 의무는 없다. 실제 판정 원본은 담당 티켓/Issue/PR이며 표는 링크 중심의 스냅샷이다.

| 항목 | 수용 범위·SHA | 증거 링크 | 미충족 필수 조건 | 차단 대상·시점 | 다음 담당·재개방 사유 |
| --- | --- | --- | --- | --- | --- |
| 작성 예시 — 판정 아님 | 관측 조건 한정 | 기존 원본 | 없으면 없음, 모르면 NOT_VERIFIED | 실제 차단만 | 책임과 변경 영향 |

새 판정을 기록할 때 그 판정에 영향 없는 승인 이력·원본을 다시 읽거나 재작성하지 않는다. 충돌이 있으면 Owner 승인 기록→승인 명세→승인 티켓 순으로 복구하고, 범위/의미가 모호하면 기존 RFC 절차를 따른다.

Q03의 최초 차단은 S2-02/03, Q04는 S2-03/08, Q05는 S2-08 해당 인수 전이다. 이를 최종 Stage까지 자동 이연하거나, DEV-021 및 독립적인 W06 모델 준비 전체의 선행조건으로 확대하지 않는다. 실제 W06의 개통 상태 통합에는 기존 W05 의존성을 유지한다.

유효 DPI·과거 창 동등성·초기 환경 원인은 NOT_VERIFIED, R02 종료코드는 NOT_CAPTURED를 보존한다. R30 exit0은 별도 보완 증거다. 실제 실행·판정 신뢰성을 막는 경우 해당 범위를 조치한다. F-08·성능·빌드/export·모든 문맥×키 조합의 미실행을 PASS로 바꾸거나 Q12의 추가 차단으로 자동 편입하지 않는다.

다음 검수 배치는 Q03~Q05 일괄 패킷과 제품 통합 준비 후 표준 VS-01 완주를 중심으로 한다. 이는 업무별 제작/Git 권한 발급 또는 현재 실행 가능 선언이 아니다. 총 토큰·작업시간·절감률은 NOT_MEASURED이며, 시범 적용 시 기존 결과 기록에 작업/대기시간·왕복 횟수·검증 누락 또는 재작업만 간단히 남긴다. 확인할 수 없는 토큰 수는 추정하지 않는다.
