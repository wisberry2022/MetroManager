## 1. 실행 조건·독립성

DEV-018 실제 제품 공급 필드·타입·revision과 정상/실패 fixture, DEV-019 개별 실행 승인·제품 UI/검증 경로·명령 로그를 수신하고 같은 제품 head에서 Design이 직접 조작한다. DEV 자동검사 성공만으로 GUI PASS로 올리지 않는다. fixture/디버그 사건은 제품 사용자 기능과 분리하고 증거에 검증 전용임을 표시한다.

제품 정상 경로는 B01/P-A·C01·자유현금1,000,000·이행80·초기 재무100·R/K/B0, 경쟁자80/80과 공개 동점순위 경쟁자 우선에서 시작한다. B02는 별도 독립 초기 상태로 재실행한다. 요청 ID·대상 회차·입력분을 명시하고 이전 케이스의 계약/자금을 무단 승계하지 않는다.

DEV는 모델/명령/원장 실제값, Design은 화면·포커스·오류복구·공급 소비를 검증한다. Planning은 승인 의미 차이만 검토한다. 실제 GUI가 없거나 권위 fixture를 재현할 수 없으면 해당 행은 NOT_RUN/차단 원인으로 기록하며 다른 독립 문서 검토를 막지 않는다.

## 3. 실행 기록 양식

각 케이스/하위 입력별로 다음 행을 채운다. 미공급 API의 필드명은 구현 후 실제 명칭으로 대응표를 붙인다.

```text
case_id / subcase:
run_state: NOT_RUN | PASS | FAIL | BLOCKED
product_head / base / engine_version:
rules_version / data_version / ui_contract_revision:
fixture_ref / sha256 / initial_values:
command_id / tender_id / round_id / plan_revision:
actual_input_sequence / keyboard_focus:
requested_at / receipt_at / decision_at / effective_at / observation_phase:
snapshot_revision / decision_snapshot_revision / result_revision:
expected_values / reasons / allowed_actions:
actual_values / reasons / allowed_actions:
screenshots / logs / raw_hashes / process_exit_code:
reviewer / observed_at_with_timezone:
defect_or_dependency / owner / unblock_condition / retest_head:
```

게임분·게임일은 권위 snapshot에 대응시킨다. 실제 조작 시간은 시간대가 있는 별도 관측시각으로 기록한다. 공개 증거에는 토큰/불필요한 개인 화면·대화·개인 절대경로를 포함하지 않는다. 원본과 해시를 보존하며 캡처와 제품 head가 다르면 재검수 범위를 기록한다.
