## 1. 화면 목적·Stage 범위

**목표:** 플레이어가 S01 지도에서 소속 도시 C01의 12개 후보역을 읽고, 노선 후보 6~8개 역을 **순서가 있는 목록으로 구성**하며, 개발측 유효성 결과·사유·수정 경로와 최소 수요 예측의 유효성/기준을 오해 없이 관찰하도록 하는 저충실도 UI 설계다.

- 이번 DSG-004에서 **작성:** S01-B 중앙 4×3 후보역 텍스트 목업, S01-F 역 목록·선택/순서·오류 메시지·예측 상세의 상태/전환 명세, 지도↔목록 동등 조작 표, 정적 사례·가독성 검수 계획.
- **재사용:** DSG-003의 S01-A 게임시간/속도 HUD, S01-C 현금·자금 및 S01-D 마감 보고의 **위치·읽기 전용 의미**, S01-E 공통 오류/명령 결과; DD-01 한 레이어 강조, DD-03 사유+허용행동, DD-04 역 목록 대체 조작, DD-08 미계산/0/이전값 구분.

## 2. S01 통합 화면 구조 (상대 배치만, px 미확정)

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ S01-A [회사/C01] [게임일·시각] [일시정지/재개] [1× 2× 4×] [현재 snapshot rev]       │
├────────────────────────────────────────────────────┬───────────────────────────────────┤
│ S01-B | 지도/행정                                   │ S01-F | 역 목록·선택 계획          │
│ [행정] / [수요] / [사업] — 1개 레이어만 강한 강조   │ 도시 C01 / 구·동 경로·역 ID      │
│ [후보/선택/오류/연결 범례 + 필터 상태]              │ ① S01 [↑ ↓ 제거]                 │
│                                                    │ ② S02 [↑ ↓ 제거]                 │
│  S01 ─ S02 ─ S03 ─ S04                            │ ... 선택 순서 / 고유 역 개수     │
│   │     │     │     │                              │ [되돌리기] [유효성 확인]          │
│  S05 ─ S06 ─ S07 ─ S08                            │ [오류 위치/사유/다음 행동]        │
│   │     │     │     │                              ├───────────────────────────────────┤
│  S09 ─ S10 ─ S11 ─ S12                            │ S01-F | 예측 최소 표시           │
│                                                    │ 계획 rev / 입력 rev / 기간·단위  │
│ 선택 역: [역 ID/D ID/G ID/C01], 연결 상태          │ [미계산/계산 중/유효0/실패]      │
│                                                    │ 구 예측: 이전 버전 비교용만      │
├────────────────────────────────────────────────────┴───────────────────────────────────┤
│ S01-C 현재 C/R/F/K/A/B (읽기 전용)  | S01-D 전일 확정 보고 (날짜·보고 ID 별도)           │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ S01-E 상태/오류·명령 결과: [요청 대기] [당시 결과] [최신 허용 행동/사유]              │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

- 그림의 `─/│`는 **계획 가능한 후보 간선의 추상 배치**이지 실제 선택 노선을 모두 연결한 상태가 아니다. 선택 노선은 순서 번호·별도 선 스타일로 표시한다. 승인 좌표의 상하/좌우 인접만 허용되며 **대각 연결은 시안에서 사용하지 않는다**.
- 구/동 색면의 선·점선은 시각적 설명 도구이고 실제 관할의 point-in-polygon 판정 기준이 아니다.
- S01-C/D/E의 내용과 위계는 **DSG-003 승인 설계가 우선**이다. 본 시안이 레이아웃의 최종 px·역 아트 크기·타깃 PC 사양을 새로 정하지 않는다.
- S01 지도/목록을 이용한 `노선 유효성 확인`은 **계획 후보의 검사/편집 단계**다. `시청 제출`, `정부 재접수`, `계약`과 혼동되는 버튼/문구를 Stage 1에 만들지 않는다.

## 3. 공식 좌표·행정 소속·구획 표현

DATA v1.3 `2의 좌표(검수용 km)를 4열×3행 **후보 위치**로 사용한다. `G01=D01·D02`, `G02=D03·D04`, `G03=D05·D06`, `G04=D07·D08`이고 전체 C01/P01 소속이다. **같은 동에 여러 역**이 속할 수 있으므로 동 이름만으로 역을 식별하지 않는다.

| 지도 행(y, km) | x=0 | x=1 | x=2 | x=3 |
|---|---|---|---|---|
| **0** | S01 · D01/G01 | S02 · D02/G01 | S03 · D03/G02 | S04 · D04/G02 |
| **1** | S05 · D05/G03 | S06 · D06/G03 | S07 · D07/G04 | S08 · D08/G04 |
| **2** | S09 · D05/G03 | S10 · D06/G03 | S11 · D07/G04 | S12 · D08/G04 |

### 3.1 지도·범례·접근 원칙

| 시각 요소 | 저충실도 표현 | 색상 외 대체·확인 방식 |
|---|---|---|
| 선택 전 후보 | `S01` 같은 고유 ID + 외곽 1중 선 | 옆 목록에서 동일 ID 선택, 관할 경로 표시 |
| 선택된 역 | `① S01` 형태 **노선 순서 번호** + 선택 테두리 | 목록의 같은 순서/ID, 포커스/선택 상태 읽기 |
| 노선 연결 | 순서가 있는 구간에 선/실선 + 양 끝 번호 | 목록 `①→②` 등 순서 텍스트, 불연속 구간 설명 |
| 유효성 실패 | 역/연결 대상에 오류 기호·점선 강조 | **해당 역·순서·연결ID**와 reason 문구를 같은 목록 행에도 노출 |
| 행정 경계(추상) | G01~G04 **굵은 점선 + 라벨** | 역 선택 상세에 `P01 > C01 > Gxx > Dxx > Sxx` 경로 |
| 한 레이어 강조 | 행정·수요·사업 중 하나만 강한 강조 | 활성 레이어 이름+범례/텍스트; 여러 레이어의 강한 동시 강조 금지 |
| 역 밀집/마커 중첩 | 리스트의 ID 검색·선택 이동으로 복구 | 지도 마커만 사용해야 하는 필수 행동 **0개** |

**중요:** 좌표로 동 소속·시 관할·행정 부모를 생성하거나 덮어쓰지 않는다. 시 외 역은 승인된 12 후보 중 하나가 아니라 **별도 부정 입력 fixture**로만 다룬다. 좁은 화면/마커 클릭 충돌은 확정 px 크기 이전에 실제 화면에서 검증할 문제이고, 목록 대체 조작을 없애서는 안 된다.

## 4. 역 선택·순서·되돌리기 UI 상태 계약

### 4.1 명령의 사용자 의도 ↔ 지도/목록 동등성

| 사용자 의도 | 지도에서 접근 | 역 목록에서 접근 | 공급자 판정·표시 |
|---|---|---|---|
| 후보역 정보 보기 | 역 마커 선택/포커스 | ID 행 선택/검색 | 동일 `entity_id`·동/G/관할 경로와 현재 plan_revision |
| 역을 계획에 추가 | 후보 마커의 `노선에 추가` 컨텍스트 | 후보 목록의 `추가` | DEV가 허용한 동작만. 선택 순서는 공급된 계획 리스트를 표시 |
| 선택/해제·제거 | 선택 마커 컨텍스트 `제거` | 선택 목록 행 `제거` | 공급된 대상 ID/삭제 결과, 검증 사유·최신 순서 |
| 순서 위·아래 | 선택 마커 컨텍스트에서 해당 역 `위/아래` | 동일 역 행의 `↑/↓` | 상단/하단·잠금 상태의 비허용 이유 공급. 드래그만 요구하지 않음 |
| 직전 편집 되돌리기 | 지도 하단 `되돌리기` 공용 조작 | 목록 위 `되돌리기` 공용 조작 | 되돌릴 대상/허용 여부는 DEV 실제 공급·명령 결과 기준. UI가 자체 역사/경제 상태 복원 금지 |
| 유효성 검사 | 지도 아래 `노선 검사` | 목록 아래 `노선 검사` | 검사 결과/사유·문제 순서 및 다음 허용 행동. **신규 사업 계약 버튼 아님** |
| 키보드·마커 겹침 복구 | 포커스 역 ID와 선택 상태 표시 | 목록·방향·버튼의 동일 목적 조작 | 구체 단축키 지정은 런타임 검수 전 가설; 포커스/텍스트/읽기 순서 검증 필요 |

하나의 계획 ID/개정 버전에 대한 **권위 있는 명령·검증 결과를 지도와 목록이 함께 반영**한다. 두 영역이 각각 별도 노선의 로컬 유효성이나 제출 결과를 계산하지 않는다. 검증이 불가하면 공급된 사유를 표시하고, 임의 수정·자동 재제출하지 않는다.

### 4.2 상태 전이와 오래된 결과

1. **초기·선택 전:** “현재 선택 0역 / 고유 6~8역 필요”는 **규칙 설명용 도움 문구**다. 실제 검사·활성 여부는 DEV 공급 필드가 결정.
2. **편집 중:** 요청 ⇒ `접수/대기` ⇒ `효력 시각 수락 또는 거부` ⇒ 공급된 최신 `plan_revision + snapshot_revision`으로 지도/목록·검사 상태 동시 갱신. 대기 중 중복 클릭은 새 계약/새 경제 효과를 만들지 않음.
3. **오류가 생긴 노선:** `노선 검사 실패: [사유]`와 **문제가 된 역 ID·순서/간선**을 지도·목록 양쪽에서 강조한다. `수정/제거/정렬` 등의 다음 동작은 실제 allowed_actions에 한정.
4. **잠금·권한 없음:** 편집 컨트롤 비활성/불가 사유·다음 허용 행동 표시. 잠금 원인을 “이미 계약/영업 중” 등 Stage 밖 기능의 허구 상태로 단정하지 않음.
5. **늦은 요청 결과:** 이전 command_id/revision의 거부는 명령 결과 이력에 표시하되 **새 계획의 허용 버튼·지도 선택 상태를 역행시켜 덮어쓰지 않는다**. 계획의 확인된 의미가 바뀐 `STATE_CHANGED`는 갱신·재확인 안내; 단순 시간 tick으로 revision이 달라졌다고 무조건 일괄 거부하지 않음.
6. **지도/목록 동등성:** 마커에서 작업한 결과를 목록에서, 목록에서 작업한 결과를 마커에서 같은 revision·같은 역 ID/순서로 비교해 불일치 발견 시 DSG-005/DEV 통합 결함으로 기록.

**미확정:** DEV-012의 구체 command enum, 되돌리기 히스토리 표현/에러 키·Godot API는 실행 공급자가 결정한다. UI는 `undo 가능`을 임의로 예단하거나 비허용 명령을 실행하지 않는다.

## 6. 예측 최소 표시 — UI-DC-02 소비 및 revision 설계

예측은 **선택 계획에 대한 예상 결과**다. 실제 영업/완료 승객·운임/당일 보고가 아니다. S01-F 작은 상세 영역에서 **계획 ID + plan_revision / prediction_input_revision / 기간·통행·거리·시간 등 단위 / 결과 생성 게임시각**을 결과와 함께 표시한다.

| 공급 상태/사례 | UI 문구·강조 | 값 표시·허용 |
|---|---|---|
| `NOT_CALCULATED` | “예측 계산 전” | `자료 없음`. `0`으로 대체 금지 |
| `CALCULATING` | “예측 갱신 중 — 입력 rev N” | 현재 결과 미유효이면 비워두고 처리중 표시. 동기 계산에서 실제 미노출이면 애니메이션용 대기 만들지 않음 |
| `READY` + current input 일치 + `available=true/value=0` | “유효한 예측: 0 [단위]” | **실제0** 표시. 계산 오류/미수신과 다름 |
| `READY` + current input 일치 + `available=true/value>0` | “현재 예측 [값/단위] · 기간” | 권위값만 표시·반올림 규칙의 해석을 역계산에 사용하지 않음 |
| `FAILED` | “예측 계산 실패: [공급된 사유]” | 0 대체 금지. 사유·다음 허용행동 안내 |
| 이전 입력 revision의 `READY` | “이전 예측 / 입력 rev N / 당시 기간·생성 게임시각” | 비교 정보로만, **현재 유효 예측·노선 판정/제출 계산에 재사용 금지** |
| 자료 미수신/`available=false` | “예측 자료 없음” + 공급 사유 | 실제0/실패/로딩과 구별 |
| 오래된 응답 도착 | “현재 입력 rev 8”은 유지, rev7 결과는 이전값 공간으로만 | 느린 이전 계산 결과가 최신 현재값을 덮지 않음 |

**FX-PRED-01 (정적 화면 경계):** 입력 rev7에서 READY/유효0 → 계획 변경 후 rev8에서 미계산 또는 계산 중 → rev8 실패/사유 또는 완료. 뒤늦은 rev7 READY는 “이전값” 표제로만 표시한다. 실제 예측 계산·게임 시각·난수 진행은 DEV에서 권위 있게 처리하며 UI 조회만으로 실행하지 않는다. `prediction_status` 등의 명칭은 계약의 의미 식별이며 최종 Godot enum/API 강제 지정이 아니다.
