## 1. 표현과 현재 구현의 경계

20개 EX는 **독립된 정적 표시 사례**다. 클릭 순서로 게임 사건·계산/복구/입력을 진행하지 않는다. JSON은 Session에 주입할 부분 snapshot이 아니며 원래15상태·DEV025 입력과 별도로 둔다.

현행 present는 clock/current/plan 등 필수 Dictionary가 존재한다고 전제한다. 전체/지도 미수신·허용 필드 누락을 제품에 주입하는 실험은 수행하지 않는다. 향후 guard/자료 준비 상태는 L2 확인 후 적용한다.

## 3. 소비·복구 흐름 제안

1. 실행/대상/판·DATA 버전과 필요한 구조를 확인할 수 없으면 현재값처럼 합치지 않는다. 자료 준비/구조 검증 책임은 DEV와 확인한다.
2. 같은 실행의 view_revision 역행 거부 의미를 유지한다. 오래된 snapshot 전체는 반영하지 않는다. 별도 실제 명령 결과가 요청ID/효력시각에 연결됐을 때만 당시 이력으로 표현한다.
3. 예측은 status·available·현재 입력 일치를 확인한다. READY0은0, 미계산/계산중/실패는 각각 다른 안내와 현재 자료 없음이다. 동기 요청이 READY/FAILED로 끝나면 대기 문구를 노출하지 않는다.
4. 보고는 available·조회 상태·실행 범위/마감일을 함께 확인한다. UNAVAILABLE만으로 모든 경우를 미마감으로 단정하지 않는다. 그 원인이 확인될 때만 부연한다.
5. 재무·당일 누계는 완료 시점/관측판을 따로 확인하고 고정 보고는 원래 출처를 유지한다. 불일치 표시가 시계·원장 자동 정정의 계기가 되지 않는다.
6. 현재 행동은 최신 관련 allowed_actions·대상 조건을 따른다. 과거 결과·예측/보고 오류로 일괄 덮지 않는다.

새 봉투/필드·fallback 알고리즘·시간제한·네트워크 재시도 정책을 확정하는 문서가 아니다.

| 미확인 자료 | 확인 전 제안하지 않을 것 | 독립 유지 |
| --- | --- | --- |
| 전체 snapshot | 신뢰된 현재 대상/허용값이 필요한 모델 요청 | 실제 있는 과거/마지막 확인본. 현재값으로 승격 금지 |
| 지도/관할/간선 | 해당 자료 의존 후보·계획 입력 | 독립 확인된 시계/자금/보고. 독립 목록 공급 때만 대체 |
| 현재 예측 | 이전값을 이용한 현재 제출판정 | 실제 현재 계획 편집/시간 등 별도 행동 |
| 자금/당일 누계 | 불일치 값의 금액·자격 단정 | 독립 지도/과거보고. 의존 행동 허용은 공급 확인 |
| 보고 | 오류/없음을0으로 채우기·다른 보고 합치기 | 현재 자금·계획·시간 |
| 특정 allowed_actions | 그 행동군의 과거 허용값으로 입력 제안 | 신뢰된 다른 행동군·비모델 정보 열람(자료 유효 시) |

확인중은 표시 가설이며 전역 LOCKED나 시뮬레이션 정지를 새로 발생시키지 않는다. 실제 PLAN_LOCKED 공급과 구별한다.

복구는 정상 공급으로 확인한다. 카드 선택을 복구로 보지 않는다. 같은 ID가 유효하게 남아 있으면 정보 선택/포커스 보존을 목표로 하고, 대상이 없으면 실제 선택 없음으로 전환한다. 첫 후보 자동 추가는 하지 않는다.

같은 실행 최신 응답과 새 실행/reset의 판 재사용을 구별해야 한다. 현행 reset_observation은 표시 revision/선택/목록을 초기화한다. 새 세션 감지·자료 준비의 정확한 경계는 아래 질의로 확인하고 임의 영구ID·복구 버튼을 만들지 않는다. 실제 읽기/탭 순서·가림·포커스·안내 반복은 후속 GUI 검증이다. 새 live-region·토스트·음향·타임아웃을 자동 구현하지 않는다.

## 4. RFC-DSG-008-EX-01 — 적용 전 L2 확인 초안

- 상태: OPEN / LOCAL_DRAFT / NOT_SENT / RESPONSE_PENDING
- 요청: Design / 응답 책임: DEV / 연관: DSG008·UI-DC-01/02/05/07
- 현황: 의미 일부는 코드에 있지만 아래 예외 입력의 실제 처리 증거는 이번에 실행하지 않았다. 기존 UI-DC 전체 수용을 재개방하지 않는다.

| ID | 확인 질문·정적 관찰 | 차단 시점 |
| --- | --- | --- |
| EX-Q01 | present는 완전한 Dictionary 전제. 전체/지도/allowed 준비 상태·구조/버전·같은 실행/새reset 구별을 누가 어떻게 공급/guard하는가 | 미수신/누락 guard 제품 적용·인수 전 |
| EX-Q02 | 계획 dispatch/예측은 동기. 실제 pending이 있는 경로의 접수/요청ID/효력·허용 행동/중복 입력 공급은 무엇인가 | CP-S13 대기 표시 제품 적용 전 |
| EX-Q03 | UNAVAILABLE 실제 원인과 run-scope/day-key·조회 실패/미식별의 경계, 계산중/당시 결과 문구를 연결할 분기는 어디인가 | 해당 문구·복구 분기 적용 전 |

현행 _render_prediction은 available=false 비실패 상태에 공통 “예측 계산을 선택하세요”를 붙이고, _render_finance는 UNAVAILABLE에 미마감 문구를 사용한다. 조건별 제안과 다른 부분은 영향 행만 DEV와 대조한다. 정적 차이 관찰이며 실제 제품 결함·수정 승인 판정이 아니다.

- 일정: 회신/적용 범위 확인 전 산정하지 않음.
- 기획·세이브: 규칙·원장·시각·저장 기능 변경 제안 없음.
- 디자인/개발: 문구·영역 구분과 해당 공급/guard만 대조. 제품 코드 수정/DEV 실험 실행은 별도 승인.
- DEV 의견/HQ 조정: PENDING / 미발송.
- Owner 결정: 새로운 규칙/범위가 실제 필요할 경우 해당 영향에 한정. 최종 제품 규격/배치는 계속 미확정.
- 반영 대상: 이번 문구/예외 설계, 필요한 DEV 적용 티켓. 외부 전달·Git 제출은 이번에 수행하지 않음.
