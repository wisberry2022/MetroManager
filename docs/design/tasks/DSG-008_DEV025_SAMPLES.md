## 2. 공통 데이터와 비교 절차

JSON은 **DESIGN_DISPLAY_FIXTURE_NOT_GAME_SNAPSHOT**이다. 기존 DSG-008 1단계 HTML의 15개 상태를 기본값까지 해석해 그대로 복제했다. JSON 필드는 게임 Session payload·enum·새 규칙이 아니다. DEV는 실제 공급 형태에 대응시키고 차이를 기록한다. UI가 숫자·판정을 재계산하지 않는다.

1. `common_samples.json`의 버전·base·원본 해시를 확인한다.
2. 같은 state ID·표시 profile·정보 선택 ID·포커스 대상·시간·환경을 고정한 A/B 쌍을 비교한다.
3. 먼저 baseline을 비교하고 같은 상태에 long profile을 추가한다. 전체 조합을 제품 수용 필수로 강제하지 않는다.
4. 기존 보드는 배치·상태·표본을 선택하면 같은 정보를 재배치한다. 버튼은 명령 의도만 기록하며 모델·시간·계획·돈을 바꾸지 않는다.
5. DEV 실험은 실제 명령/공급·격리 fixture·배치 대안을 구분해 기록한다. 가독성 보드 성공을 Godot 입력·성능 성공으로 바꾸지 않는다.

| 상태 ID | 공통 확인 내용 |
| --- | --- |
| pa / eight | 공식 P-A6역·공식8역, 순서·소속·현재 재무·미계산 |
| initial / five / nine | 0/5/9역, 값0과 자료 없음·유효성 미충족·편집 가능의 구분 |
| duplicate / gap | S02 순서2/4 오류, S01→S03 단절 양 끝점·지도/목록·지역 사유 |
| locked | 미포함 후보 추가/편집 불가, 포함역 정보 열람 유지 |
| failure / zero | 실패≠유효0≠미계산. 0통행도 운영비108000·거리5km·종단9게임분 보존 |
| stale | 현재v8 미계산과 이전v7 결과/기간·당시 거부 분리 |

0예측의 대상 기간은 [1일06:00, 2일06:00)이며 생성시각은 1일06:00이다. 실행 검증이 아닌 기존 정적 표시 예시다. 서로 다른 상태 예시를 하나의 사건 진행으로 연결하지 않는다.

JSON의 PAIR-01~12는 우선 비교할 12쌍이다. 나머지 상태도 보드에서 선택 가능하다. PAIR-11/12는 long profile이며 항상 A/B 같은 문자열·정보량을 사용한다. 제품 게임 필드로 주입하지 않는다.

정확한 Unicode 문자열은 JSON이 정본이다. 사전 잘라낸 문자열·전각 숫자·지수표기로 교체하지 않는다. 공백 없는 STR-05는 줄바꿈 위치보다 전체 값에 도달 가능한지를 본다.

보드 long profile은 지도/재무/안내 옆에 **표시 부하·게임 값 아님** 블록으로 넣고 기존 상태값을 보존한다. 실제 마커 버튼에 긴 이름을 주입한 가림 실험은 보드에서 수행하지 않는다. DEV T01/T03에서 같은 문자열을 시험용 라벨/마커/정보 패널에 대응시켜 실제 clipping·폰트 fallback·입력 영역을 확인해야 한다. 지도 표시에 생략이 필요하면 안정 ID와 정보/목록의 전체 이름 경로를 유지하는 대안을 비교한다. 보이지 않는 tooltip만으로 키보드 경로를 입증하지 않는다.

## 4. 정확한 픽셀 원본·비교

PNG는 본 작업이 수학적으로 작성한 **128×64 RGB8 불투명·무문자** 원본이다. 외부 이미지/폰트·최종 게임 아트가 아니다. 색은 DSG-007 잠정 토큰 6개를 재사용한다. 좌표 원점은 왼쪽 위, 사각형 범위는 x/y 포함·x+w/y+h 제외다.

| 표본 | 원본 텍셀 범위 x,y,w,h | 비교 의도 |
| --- | --- | --- |
| PX-01 | 0,0,32,32 | 1텍셀 체크: 손실·모아레·비정수 위상 |
| PX-02 / 03 | 32,0,32,32 / 64,0,32,32 | 1/2텍셀 세로줄의 폭·병합·번짐 |
| PX-04 | 96,0,32,32 | 1텍셀 대각 교차의 계단·대칭·위상 |
| PX-05 | 0,32,64,32 | y36의1, y40~41의2, y46~49의4텍셀 가로선 |
| PX-06 | 72,36,24,24 | 계단 테두리·내부면·빈 모서리 구분 |
| PX-07 | 104,36,20,24 | 4×4 면의 경계와 주변 대비 |

정확한 레시피·팔레트·SHA-256은 JSON에 있다. PNG 크기 변경/재인코딩 시 해시와 원본 텍셀 보존을 확인한다. 브라우저 보드는 같은 PNG를 CSS pixelated/auto로 나란히 제시할 뿐 Godot nearest/linear와 동일 결과라고 주장하지 않는다. 후보1/1.25/1.5/2배는 실험 조건이며 제품 배율이 아니다. 좁은 브라우저에서는 max-width로 미리보기가 축소될 수 있으므로 원본/실제 표시 크기를 함께 기록한다.

DEV T02는 텍스트를 PNG에 굽지 않고 같은 별도 텍스트/선과 비교한다. 원본→텍스처 import→필터→노드 변환/위상→뷰포트→클라이언트/OS DPI 단계의 실제 값을 기록한다. 두 후보의 원본·장면·위상·배율은 같게 하고 필터만 바꾼다. nearest 정수 후보는 텍셀 반복·선 끊김을, linear/비정수 후보는 경계·글자 판독·소실/간섭을 관찰한다. 비정수에서 동일 텍셀 폭을 요구하거나 어느 필터를 자동 합격으로 정하지 않는다.

판정은 `NO_ISSUE_OBSERVED`(관찰한 조건 한정), `ISSUE_OBSERVED`, `INCONCLUSIVE`, `NOT_RUN`으로 기록한다. 취향/선명도 선호는 별도 `PREFERENCE`와 이유로 남긴다. 미실행·판정 불가를 합격으로 처리하지 않는다. 예컨대 RD-01의 전체 금액 손실은 조건별 문제이며, 특정 필터의 단순 선호는 제품 결함으로 승격하지 않는다.

기록 필드: case/pair·A/B·state/profile·stableID/포커스·문자열/PX ID·코드 SHA/샘플 해시·환경/실측 좌표/배율·입력→기대→실제·증거 경로/해시·RD별 판정/원인·권고/남은검증·검토자/역할. 실제 glyph 확인 불가·GPU 계측 불가 등은 해당 범위만 명시한다.

기존 DSG-007 대비 검토 목표4.5/3.0은 잠정 참조이며 실제 Godot anti-alias·표시/접근성 수용 증거가 아니다. 새 색·글꼴·목표 수치를 확정하지 않는다.
