CP-S11의 “확정 보고 자료 없음”은 중립 표현으로 유지한다. 첫 마감 전 설명은 실제 첫날·조회 생략 문맥이 확인될 때만 붙인다. FAILED의 key 잔존을 READY로 승격하지 않으며 유효0·없음·실패를 구분한다. 현재 자금 오류라도 보고 대상이 독립 확인되면 보고를 유지하고, clock 미확인으로 대상일을 확인할 수 없으면 보고를 현재 정상으로 승격하지 않는다.

run_scope는 실행 중 귀속 확인용이며 영구ID·세이브·인증 설계로 확대하지 않는다. 전체 재생성이라는 기술 선택의 성능·자원 해제 검증은 DEV 책임으로 남긴다.

## 4. L2-C — 문구·선택·포커스 복귀

대상: EX-03/13/15 및 공통 복귀, CP-S03/14/16·CP-R01/08 / 계약 §4~5 / 검증 X-05·06 및 직접 영향 X-07.

- 실제 빈 계획은 “계획에 포함된 역이 없습니다” 의미를 유지한다. CP-R01은 실제 계획 유효성 사유 문맥에서 사용하며 빈 계획을 자료 오류로 바꾸지 않는다. 첫 후보에 포커스를 주는 것과 자동 계획 추가를 구별한다.
- 미상 사유는 CP-S14의 중립 안내와 개발 진단을 분리한다. 확인된 수락/거부 사실을 유지하고, accepted=true의 빈 reason을 오류로 표시하지 않는다. 미공급 ID·효력시각·원인을 창작하지 않는다.
- 당시 STATE_CHANGED/거부는 CP-S16·CP-R08 문맥으로 남기며 현재 edit/undo/predict 허용을 덮지 않는다. 과거 거부 후 현재 허용된 새 요청은 표시한 계획판으로 기존 Session 검사를 거친다.
- 같은 Session의 유효 안정 ID 선택 보존에 이견 없음. 미수신 중 잠재 보관 ID는 현재 유효 표시·모델 요청에 쓰지 않는다. 정상 복귀 후 대상이 없으면 선택 없음으로 전환한다.
- 사용자가 이동한 포커스를 복구가 빼앗지 않는 조건에 동의한다. 살아 있고 현재 유효한 이전 Control로 복귀하고, 불가능하면 **기존 계획 목록 → 유효 후보 Control → 기존 제목 Label**의 제안 순서를 실제 화면에서 확인한다. 이 순서는 잠정안이며 제목의 focus_mode·탭 순서·시각 표시·스크롤/가림을 제품 증거로 확인하기 전 확정하지 않는다.

확인할 전이는 같은 Session의 정상→미수신→복귀, 복귀 중 사용자 포커스 이동, 대상 소멸/행동 제한, 자식 화면 진입·복귀의 직접 영향이다. stale 관측으로 현재 포커스를 변경하지 않으며 새 Session은 이전 포커스를 복구하지 않는다. 새 버튼·live-region·토스트·음향·자동 재시도·취소 기능은 이번 의견에 포함하지 않는다.

재개 시 DEV가 최신 통합 full SHA·승인 범위·실제 계약/경로·변경 행·적용/제외·검증 패킷을 묶어 공급하면, Design은 차이가 있는 의미와 직접 영향 행을 한 번에 회신한다. 계약안의 helper/API/필드·View 재생성·fallback 순서를 그대로 구현된 사실로 승계하지 않는다. 정확한 일정은 NOT_ESTIMATED이다.

기존 20사례/copy_ids는 정적 연결이 일치한다. EX-05 CALCULATING은 소비 fixture, 동기 제품 중간 대기는 EXCLUDED_FROM_PATH이다. EX-16 CP-S13은 일반 S01 적용 제외이며 다른 실제 pending의 정상 전달만 영향 회귀한다. EX-18 외부역은 격리 입력으로 실제12후보를 바꾸지 않는다. 재개 시 이 구분이 실제 경로와 여전히 맞는지만 확인한다.

[PM-015 지침](../../hq/GUI_REVIEW_PROTOCOL.md)에 따라 기존 수용 Q03~05·Q12 28조건·QA-001/002·OBS-01·A02-11은 원래 범위로 보존한다. A01-Q12 상위 PARTIAL도 유지한다. 새 SHA만으로 재실행하거나 같은12/28조건·모든 문맥×키를 새 필수 행렬로 만들지 않는다. 관련 변경/결함/증거 공백이 있는 행만 보완하고 자동 회귀·필수 CI는 면제하지 않는다. 독립 GUI 실행과 Design 증거 심사를 구분한다.

## 6. RFC 회신 초안·미해결 기술 협의

이 절은 [RFC 양식](../../templates/RFC_AND_DECISION.md)에 따른 RFC-DEV-026-01의 **로컬 Design 회신 초안**이다. 외부 전달 전이므로 원격 DEV 문서의 Design 의견 PENDING을 이번에 수정하거나 RFC를 CLOSED 처리하지 않는다.

- 요청/응답: DEV → Design Track B / 연관 DSG-008·DEV-026·RFC-DSG-008-EX-01.
- 현황: 계약안은 수신했고 위 L2-A/B/C의 의미상 이견은 없음. 최신 구현 계약·실제 복구/입력 증거는 아직 미수신이다.
- 담당 의견: 위 조건으로 후속 대조 진행 제안. 지금 20사례 전체 재승인이나 새 게임 규칙 질문은 없음.
- 남은 확인: DEV의 최신 지역 의존/자식 호스트 범위, 새 View/binding/옛 callback 처리, L2-C fallback 구현·가시성·사용자 이동 보존. 선행 결과 후 RECOMPARE_REQUIRED / 제품 수용 PENDING.
