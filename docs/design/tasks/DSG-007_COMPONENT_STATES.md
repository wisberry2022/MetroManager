## 2. 공통 데이터·업무 상태

| 조건 | 표현·다음 행동 | 금지·경계 |
| --- | --- | --- |
| 값 공급됨·실제0 | `0` + 단위·해당 시점 | 자료 없음·긴 대시로 대체 금지 |
| 미수신·미계산 | `자료 없음` / `미계산` + 공급 사유 | 0·정상 빈 목록과 합치지 않음 |
| 조회 실패 | `불러오기 실패` + 사유 + 공급된 다음 행동 | 기존 정상값을 현재 확정처럼 유지하지 않음 |
| 명령 처리 대기 | `요청 접수 / 처리 중` + 해당 요청 문맥 | 실제 공급이 동기 완료면 대기 연출을 추가하지 않음 |
| 당시 수락/거부 | 당시 효력 시점·대상·결과·사유 | 늦은 과거 결과로 현재 버튼·금액·계획 덮기 금지 |
| 현재 허용 행동 | 최신 상태의 사유·허용값을 소비 | 과거 거부를 현재 금액으로 소급 성공시키거나 자동 재실행 금지 |
| 과거 확정 보고 | 마감일·공급 식별·고정값. 실제0 표시 | 실제 공급에 없는 전역 report ID를 만들지 않음. 현재값과 혼합 금지 |
| 예측 | 입력·대상기간·단위·예상 라벨. 현재 유효 결과만 현재값 | 이전 계획 결과·실제 실적과 혼합 금지 |
| 편집 불가 | 비활성 조작·인접 이유, 열람 가능성은 별도 | 임의로 계약중·개통 등 원인을 창작하지 않음 |
| 게임 일시정지 | 게임 시각 정지와 속도 정보를 각각 표시 | 업무 잠금·공사중단·영업중단과 하나의 상태로 합치지 않음 |

## 3. 재배치·좁은 폭·키보드

재배치해도 요소 ID·필수 정보·대상·행동 의미를 유지한다. 반응형에서 지도·업무 패널을 쌓고 금액 열 수를 줄인다. 같은 DOM 요소를 사용해 이벤트 바인딩·현재 정보 선택을 유지한다. 보드의 시각 순서와 DOM 읽기 순서는 HUD→지도→업무→현재 재무→과거 보고→안내다. 완성 게임 화면의 읽기 순서는 DSG-008/DEV에서 별도 검토한다.

긴 한국어 사유·소속 경로는 줄바꿈하고, 금액 숫자는 값 자체를 축약하거나 화폐 기호를 새로 부여하지 않는다. 작은 폭에서 6계열을 잘라 숨기지 않는다. 개별 시민·열차 수와 통행수의 1:1 표현은 요구하지 않는다.

보드의 조작 요소는 native button/select/checkbox다. Tab/Enter 접근과 포커스는 브라우저에서 확인하며 이것을 게임 단축키·Godot 입력 정책으로 확정하지 않는다. 실제 게임의 지도↔목록 편집·제거·정렬·되돌리기 동등성은 DEV 연결 후 Track A/후속 Design이 검수한다.

## 4. 표현·검증 수준

개별 역/간선 오류, 대기·수락·과거 확정 보고의 전체 데이터 연결은 **명세/정적 예시**다. 모든 컴포넌트의 실제 제품 상태를 구현했다고 주장하지 않는다. 브라우저 샘플은 탭 구획, 정상/잠금·조회실패, 실제0/없음, 정보 선택·배치 이동을 다룬다. DEV 기술 회신·실제 게임 가독성·성능·외부 사용자 접근성 검증은 결과서의 NOT_RUN/PENDING을 따른다.
