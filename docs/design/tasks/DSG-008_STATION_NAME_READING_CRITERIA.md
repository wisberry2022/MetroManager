## 1. 효력과 공급 전제

O01~07·S1/E1/F1/N1/A1/P1은 승인/선택 완료이며 재선택 대상이 아니다. 이 문서는 **N1의 Track B 표현 기준 제안**이다. 실제12개 이름·콘텐츠 작성/승인 담당은 NOT_SUPPLIED다. 제품의 이름 데이터·코드/namespace·새 Control을 구현하거나 최종 폰트/치수·접근성 전체 수용을 결정하지 않는다.

현재 제품은 `id/neighborhood_id/x_km/y_km`과 ID 중심 map/목록을 사용한다. DEV025의 긴 이름/겹침 샘플은 실제 콘텐츠가 아니다. DEV의 `station_names_ui`·표시명 JSON/loader·schema/content version 제안은 **표시 자료를 모델 ID와 분리하는 방향으로 대조 가능**하나 실제 봉투·타입·지역 의존표·L2 수용은 DEV/Track A/B 협의 후다. DEV 미게시 로컬6문서의 제출을 선행조건으로 추가하지 않는다.

## 2. 동명이름 구별 — NR01~03

| ID | 제안 기준 | 예시·금지하는 혼동 |
| --- | --- | --- |
| NR01 식별 | 명령·정보 선택·지도/목록·계획 순서는 기존 안정 station ID로 연결. display_name은 표시 자료이고 식별 키/그룹 병합 기준이 아님 | 이름이 같아도 S01과 S02는 다른 대상. 이름 변경으로 역/계획·계보·좌표/ID를 새로 만들지 않음 |
| NR02 동명 표시 | 목록의 이름 가까이에 **항상 같은 ID를 함께 읽을 수 있게** 제시. 선택 정보에서 승인 전체 이름과 ID를 함께 제공. 유효한 기존 소속도 보조로 제공 가능 | 표기 예시 `[승인 표시명] · S01` / `[동일 표시명] · S02`. 대괄호는 변수이며 실제 이름표 아님. 소속/순서 번호만으로 ID를 대체하지 않음 |
| NR03 지도 | 현재 마커의 ID·계획 포함 순서·선택/포커스 의미를 우선 보존. 이름을 모두 지도 마커에 넣는 방식은 필수 아님. 겹침 시 같은ID 목록/정보 열람으로 도달 | 긴 이름 때문에 마커 좌표·클릭 영역·연결/오류/운행 의미를 임의 변경하지 않음. tooltip은 보조이며 전체 열람의 유일한 경로가 아님 |

표시명이 중복되는 것은 **허용된 서로 다른 ID의 콘텐츠 사례**이며 중복ID 오류와 구분한다. 별칭·축약명·구역명/역 접미어를 임의로 만들어 공식 표시명으로 쓰지 않는다. 대소문자/공백·정규화로 서로 다른 ID를 합치지 않는다. 실제 승인 표기의 공백/개행 정책이 필요하면 콘텐츠 공급자·DEV와 협의한다.

## 3. 읽기순서·키보드 — NR04~06

| ID | 제안 기준 | 확인할 실제 의미 |
| --- | --- | --- |
| NR04 후보/정보 목록 | 유효한 현재 공급의 역 순서를 유지하며 이름 가나다순 재정렬을 기본으로 도입하지 않음. 순서 계약을 바꾸려면 DEV가 현재 배열과 변화 이유를 L2에 제시 | 정적 비교용은 S01~S12 공급 순서. 실제 payload 순서·정렬/Tab 구현의 최종 계약은 미확정. 이름 갱신만으로 행 순서가 바뀌지 않음 |
| NR05 계획 목록 | 계획 포함역은 **실제 계획 순서 1..n**로 읽음. 후보 ID/가나다순·장식의 공간 순서로 정렬하지 않음 | 같은ID 지도/후보/계획에서 같은 이름/소속을 참조하되 계획 번호는 계획 자료만 따름 |
| NR06 키보드 | 선택한 유효 영역 안에서 실제 표시 순서와 키보드 순서가 일치하도록 DEV가 제안. 현재 선택/키보드 포커스/계획 포함을 구분. 포커스한 대상은 화면 안에 보이거나 즉시 접근 가능한 읽기 위치를 제공 | 다른 영역 왕복은 같은ID 연결 유지. 제거된 대상/옛 scope Control로 복원하지 않음. 신규 단축키·Tab 전역 순서·방향키 재매핑을 이 문서로 확정하지 않음 |

자동 갱신으로 사용자 포커스·스크롤을 첫 행으로 빼앗지 않는다. 이름 버전 변경은 현행 행 텍스트를 갱신하되 같은ID의 유효 선택·포커스/읽기 위치를 유지한다. 글자 높이 변화로 필요한 가시성 보정은 사용자 이동을 존중하며 실제 전후 조건에서 검증한다. 새 Session에는 옛 선택/읽기 이력을 이관하지 않는다. 대상 소멸·지역 무효 때의 유효 fallback은 공급/화면별 계약으로 확인한다.

## 4. 전체 이름 열람 — NR07~10

| ID | 제안 기준 | 입력·권위 경계 |
| --- | --- | --- |
| NR07 기본 접근 | 후보/계획 목록 또는 읽기 전용 정보 영역 중 실제 유효한 경로에서 **승인된 전체 이름·ID**를 확인 가능. 마우스와 키보드 양쪽의 경로를 제시 | hover tooltip에만 전체 이름을 두지 않음. 미포함역을 읽기 위해 편집 명령을 실행해야 하는 구조를 요구하지 않음 |
| NR08 긴 문자열 | 목록의 줄바꿈/줄 수·실제 배치는 환경/폰트 검증 후 결정. 축약 표시가 필요하면 별도 전체 열람에서 원문 끝까지 도달. ID는 동명 구별에 사용할 수 있어야 함 | 전체 열람은 이름 전체를 보존. 고정 글자수 잘라내기·임의 줄임말/교정·가로폭 증가로 다른 필수 행동을 가리는 처리를 최종 규격으로 채택하지 않음 |
| NR09 열람과 편집 | **정보 열람/포커스/이름 갱신은 plan revision·원장·시간·RNG/명령 효과0**. 기존 미포함역 선택 등 명시적 편집은 실제 허용 행동에 따른 정상 효과 | 현재 `_select_station`은 미포함역 편집일 수 있으므로 이를 단순 읽기 트리거로 호출하지 않음. 읽기 전용 경로의 구체 Control/신호는 DEV 제안·L2 후 결정 |
| NR10 잠금/실패 | 편집 잠금과 정보 열람 가능 여부를 별개로 표시. 유효 정보와 허용된 읽기 경로가 있을 때 잠금 중에도 이름/ID 열람 가능 | invalid map/관측 무효로 제거된 대상은 안전 대안이라고 강제하지 않음. 이름 읽기를 위해 편집 잠금을 우회하지 않음 |

효과 비교는 읽기 자체가 추가로 만든 명령·변경에 한정한다. 자연 시간 진행이나 동시에 수행한 명시적 편집의 정상 효과는 별도 기록하며 화면 열람 중 게임 시간이 항상 정지해야 한다고 요구하지 않는다.

표현 제안: 별도 읽기 영역의 주 정보는 `[승인 전체 이름]`, 보조 정보는 `역 ID Sxx`와 공급된 소속/현재 상태로 구성할 수 있다. ID는 기존 제품에서 쓰는 역 식별이며 내부 revision/hash·namespace 오류 코드를 플레이어 문구로 노출할 필요는 없다. 창/폰트/치수·열람을 여는 정확한 버튼/키는 아직 미확정이다.

## 5. 이름 오류·버전 변경 — NR11~13

- **NR11 이름 미확인:** namespace 검증 실패/누락/타입·중복ID/외부ID 오류 시 승인되지 않은 이름이나 이전 버전의 이름을 현재 이름처럼 표시하지 않는다. 유효한 기본 map/ID 공급은 독립적으로 유지한다. 표시명 계약 전체가 거부된 경우 이름 전체를 미확인으로 처리하며, 행별 부분 수용은 별도 계약 없이 가정하지 않는다.
- **NR12 fallback:** 제품 문구 제안은 `역 이름을 확인하지 못했습니다`와 유효 station ID의 조합이다. ID fallback을 이름 공급 성공/전체 이름 열람 PASS로 집계하지 않는다. 실제 오류 문구는 승인 카탈로그·새 공급 계약과 대조 후 확정한다. 이름 없음과 정상 이름/동명·맵 전체 오류를 구분한다.
- **NR13 갱신:** 같은ID 집합/plan revision이라도 content_version·locale 등 유효 표시 자료 버전이 바뀌면 실제 행·정보 영역·보조 tooltip을 일관되게 갱신한다. 잘못된 옛 scope/오래된 이름 자료는 현재 표시에 적용하지 않는다. 이름 검증 실패만으로 계획/원장·독립 유효 지역을 초기화하지 않는다.

독립 name 관측과 root/지도 관측의 우선순위·같은판/캐시 key·보조 문구의 정확한 필드/거부 단위는 DEV 공급 계약·지역 의존표로 대조해야 한다. 이 문서가 새 수신 프로토콜이나 기존 guard 수정 권한을 부여하지 않는다.

## 6. 공급/검증 인계

콘텐츠 담당은 id/display_name 12행과 승인/버전/출처·locale을 공급하고 HQ/Owner가 작성·승인 담당을 지정한다. Track B는 위 NR 기준, DEV는 실제 schema·namespace·경로/권한·거부 단위/캐시·입력 경로를, Track A는 실제 기능/명령 영향을 같은 패킷에 연결한다. 실제 공급·해당 L2 후 UI를 연결한다.

| 최소 사례 | 기대·증거 |
| --- | --- |
| 같은 이름인 서로 다른ID·긴 이름 | 모두 동일ID로 지도/목록/정보 연결, ID로 구별, 원문 끝까지 마우스/키보드로 읽기. 실제 승인 이름이 없으면 fixture로만 확인하고 콘텐츠 수용 대기 |
| 계획 순서와 후보 순서가 다름 | 계획 번호/순서 보존, 후보 읽기 순서 계약 유지, 이름 변경으로 재정렬/계획 수정0 |
| 잠금·미포함역 읽기·명시적 편집 | 읽기 경로는 권위 효과0, 편집은 승인 효과. 포커스/이름 열람을 모델 명령 우회로로 쓰지 않음 |
| 같은ID·이름 버전 변경 | 실제 텍스트 갱신·유효 선택/포커스·사용자 스크롤 보존, 오래된 응답 무시의 자동/실제 GUI 근거 구분 |
| 이름 봉투 오류와 유효 지도·무효 지도 | 이름 미확인/ID fallback은 실패로 구분, 유효 지도/독립 지역 유지. root/map 무효 때 낡은 클릭/대상/이름을 유지하지 않음 |

관련 자동·로드 및 변경 영향 GUI만 수행하도록 이후 실행안을 좁힌다. 전체 F08 재실험·이전 수용 반복 없음. 위 사례의 **실제 실행은 이번 NOT_RUN**이며 NR13의 source audit를 구현/렌더 PASS로 바꾸지 않는다. 최종 규격·제품 L2·Stage 최종 인수는 별도다.
