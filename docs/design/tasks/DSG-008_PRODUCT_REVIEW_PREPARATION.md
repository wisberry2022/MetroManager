## 1. 지금 진행한 업무와 경계

Owner의 “원격 저장소를 확인하여 현재 단계에서 진행할 수 있는 업무를 계속해주세요” 지시에 따라 DEV 구현·실험 전에도 준비 가능한 **Design 제품 검수의 기대 표시/행동·증거 확인표**를 작성했다.

[v0.2 수신 회신](https://github.com/wisberry2022/MetroManager/issues/104#issuecomment-6868246151)의 DEV 판정은 DEV_DESIGN_INPUT_RECEIVED / NO_NEW_DESIGN_BLOCKER_IDENTIFIED / IMPLEMENTATION_APPROVAL_PENDING / FINAL_SPEC_PENDING이다. v0.2 인계 누락이나 새 문구 쟁점을 다시 요청하지 않는다. 다음 L2 대조 시점은 DEV가 구체 공급/소비 계약과 사례별 동작을 제안할 때다.

이 문서는 DEV 실행 패킷·정확한 수정 파일·새 작업ID·입력 API를 대신 확정하지 않는다. 제품 코드/테스트·UI 시안/배치·카탈로그/열람기·기존 승인/검증은 수정하지 않았다. 정적 문구 승인과 제품 구현/인수, Track A 실제 GUI 수용과 Track B 표현 검토를 구분한다. 이번에는 로컬 산출물만 작성하며 Commit·Push·PR·외부 메시지/이슈 댓글·병합은 수행하지 않는다.

## 2. 20사례를 제품 검수에 연결하는 방법

JSON은 실행 가능한 테스트나 Session payload가 아닌 Design 확인표다. case_id/copy_ids는 v0.2와 같고 의미를 재정의하지 않는다. 각 행은 전제 설명, 기대 표시, 행동/독립 정보, 복귀/포커스, 실제 적용·미구현 경계, 필요한 증거를 가진다. actual_result=null, evidence_refs=[], execution_status=NOT_RUN으로 시작한다. 증거가 없는 상태를 PASS로 채우지 않는다.

## 3. 후속 DEV 계약을 받은 뒤의 대조 순서

1. 실행 SHA·실제 경로·계약/자료 책임과 전제조건을 고정한다. 명세 의견/코드 관찰/격리 fixture/실제 제품 실행을 구분한다.
2. DEV가 각 case_id에 대응하는 실제 필드/조건·적용 또는 제외 이유를 제안한다. Design은 JSON의 의미와 차이가 있는 행만 L2 대조한다. 포괄적인 새 envelope/영구ID·재조회 버튼을 선행조건으로 만들지 않는다.
3. 정상 전→이상 중→정상 복귀의 표시와 독립 행동을 확인한다. 변화 없는 조회/정보 열람에 계획·원장·시계 효과가 없다는 주장은 DEV 모델/로그 증거로 확인하며 화면만으로 단정하지 않는다.
4. 같은 Session의 view_revision 역행과 새 Session 판 재사용/이전 응답을 별도 행으로 재현한다. Pipeline 관측판·계획판·예측 입력판을 같은 숫자 체계로 비교하지 않는다.
5. 복귀 후 같은 안정 ID가 유효하면 정보 선택/키보드 포커스 보존을 확인한다. 대상이 없어졌으면 선택 없음과 합리적인 기존 포커스 경로를 확인하되 새 자동 후보 추가·임의 기능을 만들지 않는다. 정확한 포커스 목적지는 해당 제품 흐름/DEV 계약과 대조한다.
6. 보고 첫날 확인/원인 미확인·key가 남은 FAILED·다른 Session/day, 예측 유효0/입력 변경/이전값을 구분한다. 기본 문구 “확정 보고 자료 없음”과 현재/과거 출처를 확인한다.
7. 실제 키보드·마우스로 읽기 순서·행동 사유 가시성·스크롤 도달·복귀를 확인한다. fixture 선택만으로 실제 편집/복구를 실행했다고 기록하지 않는다.

## 4. 증거 기록과 판정 제안

최소 기록: case_id·copy_ids, 기준 full SHA·계약/환경, 실제 경로와 fixture/제품 구분, 입력 순서, 관측 전/후의 표시/대상/같은 종류의 판/게임시각, 기대/실제, 허용/차단 행동과 독립 정보, 선택/포커스, 로그·캡처/자동 증거 참조, 한계·다음 담당.

- 실행하지 않았으면 NOT_RUN, 실제 결과/증거는 비워 둔다.
- 계약/적용 경로가 미확정이면 CONTRACT_PENDING, 증거로 판정할 수 없으면 INCONCLUSIVE로 별도 기록한다. 이 둘을 제품 PASS로 처리하지 않는다.
- 실행 후 원래 의미와 다르면 ISSUE_OBSERVED, 해당 조건에서 문제가 관찰되지 않았으면 NO_ISSUE_OBSERVED로 제안한다. 전체 MVP/가독성/성능 인수 판정과 구분한다.
- 제외 경로는 EXCLUDED_FROM_PATH와 해당 동기/다른 화면 근거를 기록할 수 있다. 현재 모든 행의 실행 상태는 NOT_RUN이며 이 용어들은 추후 결과 기록 지침이다.

브라우저 CSS px를 Godot 최소창·DPI·실제 픽셀로 바꾸지 않는다. 글꼴·배율·필터·FPS 등 수치 합격선을 이 확인표에서 새로 정하지 않는다. 계약 확정 후 표본·필드·필요 증거가 달라지면 해당 영향만 개정한다.
