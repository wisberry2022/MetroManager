## 4. MVP 이후 개편 가능성 반영

1. **의미 역할과 외관:** `선택`, `오류`, `현재 자금` 등의 역할과 팔레트·표면 장식을 분리한다. 특정 색이나 테마 이름을 업무 의미의 식별자로 삼지 않는다.
2. **요소와 배치:** HUD·재무·역 목록·업무 안내가 이동해도 필수 필드·상태·출처·조작 의미를 유지하도록 명세한다. 공통 요소 문서에 화면 절대 위치를 고정하지 않는다.
3. **도시 아트와 정보 UI:** 건물 그림에 버튼·숫자·문구를 합성하지 않는다. 정보 레이어와 배경 장식을 구별하고 밀집 시 목록 대체를 유지한다.
4. **최소 제작:** 필요한 요소와 대표 상태부터 작성한다. 미래 다중 테마·모든 화면 변형·범용 UI 편집기를 선제 제작하지 않는다.
5. **변경 영향:** 역할·상태 의미 변경과 색·장식 변경을 구분하고 영향 화면/에셋·재검수 범위를 기록한다. 향후 대규모 개편 자체는 별도 범위·비용·승인 대상이다.

이 요구는 디자인 인계 수준이다. 구체 Godot 아키텍처·클래스·리소스 구조와 성능 보장은 DEV의 기술 판단·검증으로 남긴다.
