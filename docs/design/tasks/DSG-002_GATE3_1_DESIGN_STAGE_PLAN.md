## 1. 최종 분석 결론·추가 요청 점검

**DESIGN_STAGE_PLAN_READY / DEV_STAGE_UI_BOUNDARY_CONFIRMED / OWNER_MINIMAL_UI_SCOPE_AGREED.**

- [디자인 PM-010 최초 회신](https://github.com/wisberry2022/MetroManager/issues/24#issuecomment-6555464641)에서 W01~W03 + Stage 최소 UI의 화면·표현·검수 범위 제안.
- [DEV의 직접 상세 회신](https://github.com/wisberry2022/MetroManager/issues/24#issuecomment-6555812161)에서 W01 전용 메뉴 불필요, W02 원장 읽기 전용/시간 조작 유효, W03 지도·목록 안정 ID와 예측의 최소 표시 연결 가능을 확인. 실제 데이터/명령/fixture 공급은 **해당 통합 전** 책임.
- [Design의 개발 계획 수용](https://github.com/wisberry2022/MetroManager/issues/25#issuecomment-6555800425)과 [Owner의 포함 범위·검수 조건 동의](https://github.com/wisberry2022/MetroManager/issues/24#issuecomment-6555874135)를 유지한다.
- 최신 개발 [PR #33](https://github.com/wisberry2022/MetroManager/pull/33)은 `main`에 병합되었으며, UI 계약 v0.2.1의 의미 그룹 표/Planning 확인 상태는 **L1 문서 정정**이다. UI-DC-01~07의 기존 정적 디자인 의미 수용을 무효화하거나 새 수용 절차를 요구하지 않는다.
- **새로운 미해결 의미 질문, 부서 간 계약 충돌, 기획 수치 변경, 추가 L3 검토 사유 없음.** 다만 실제 실행·목업·제품 목표/사용성 검증은 아래 차단 시점을 가진 **후속 의무**이지 완료가 아니다.
- 본 문서는 **첫 Stage 디자인 계획의 인수 입력**이며 실제 게임/UI 제작 완료, Stage 전체 승인, 독립 AC/VP PASS를 주장하지 않는다.

## 3. 검수 시나리오 및 완료 증거

아래는 **앞으로 수행할 검수 계획**이다. 수행된 테스트나 PASS 결과가 아니다. 디자인팀은 구체적인 레이아웃·문구·가독성과 동등 조작을 판단하며, 수치/관할/경제 계산의 정답 및 실제 명령 판정은 DEV의 권위 공급값을 소비한다.

| 검사 묶음 / 연결 AC | 검수 입력·화면 상태 | 관찰해야 할 증거 |
|---|---|---|
| **W01 / 기반** | 정상/잘못된 버전·ID, 회사 초기 상태, 실패 종료코드 | 실제 제품 GUI 진입/초기화와 headless 실행의 구분; 사용자용 추가 메뉴 없이도 상태 이해 |
| **W02 / AC-08·10 일부** | 정지·재개·1/2/4배속, 현재/마감 일자, 같은 revision/없음·0 | 시간조작 실제 클릭→상태/게임분 변화·정지 중 불변, 전일 보고 스냅샷 불변, 현재·과거 혼동 방지 |
| **W02 / SEM·CLOSE 정적 설명** | 같은 T 계약/도착/정산, R/K 보호·B 상환, 명령효력/현재 잔액 | **테스트용 사건 fixture**임을 명시하고 제품 계약/탑승 기능처럼 보이지 않음. 후순위 운임으로 과거 계약 거부를 바꾸지 않음 |
| **W03 / AC-01·02·04 일부** | 후보12/정상6역·8역·5역·9역, 중복/단절/관할 외 별도 fixture | 지도/목록이 동일 역 ID와 선택·순서·허용/거부를 보여주며 오류 대상·사유·다음 행동이 일치 |
| **W03-B / AC-04 일부** | rev7 READY=0→rev8 계산 중/실패/완료, 늦은 rev7 응답 | 실제 0/미계산/실패의 라벨 분리, 계획 버전·기간·단위·유효성 유지, 낡은 예측이 현재값을 덮지 않음 |
| **공통 UX** | 상태 잠금·자료 없음·오류/복구·여러 역 밀집, 스냅샷 갱신·명령 거부 | 화면/마커/목록의 가독성, 클릭 대체 경로, 허용 행동·거부사유 일관성, 실제 입력/화면 기록 |

Stage 전체 인수에는 **실제 자동 규칙·회귀 결과**, **Godot 프로젝트 로드**, **제품 GUI 진입**, **최소 UI 실제 조작**의 개별 증거가 필요하다. **스크린샷만으로 실제 조작 PASS를 주장하지 않는다.** 최초 Stage 종료는 AC-01~10 일부의 실증 단계이고 독립 VP-01/02, Windows export/대상 PC FPS/외부 사용성 합격은 이 Stage의 완료를 자동 뜻하지 않는다.
