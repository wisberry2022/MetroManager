## 현황과 문제

[PR #90](https://github.com/wisberry2022/MetroManager/pull/90)은 2026-11-08 병합됐다. 이는 기술 회신 전 정보 구조·상태 매핑·잠정 A/B 비교의 1단계 제출이며 최종 제품 규격·배치 또는 전체 DSG-008의 인수를 뜻하지 않는다. A 우선 권고와 B 대안을 유지한다.

[INF-004](../../infra/tasks/INF-004_TRACK_B_AGENT_REGISTRATION.md#owner-activation)·[PR #91](https://github.com/wisberry2022/MetroManager/pull/91)로 기존 독립 Track B 담당 세션의 AGT-DSG-0003이 ACTIVE 등록됐다. 효력은 2026-11-08T16:25:00+09:00이며 과거 산출물 작성 당시 등록 여부·QA·승인 기록을 소급 변경하지 않는다.

기준 main의 DEV/HQ 문서와 관련 Issue #24·#25 댓글을 읽었으나, 이 RFC의 네 항목에 대한 최종 기술 회신·제품 규격 결정은 확인되지 않았다. 기존 UI-DC-01~07 정적 의미 수용을 다시 요구하지 않는다. F-08은 규격 종속 제작에 적용하며 Track A 최소 기능 UI를 일괄 차단하지 않는다.

## 질문 또는 변경 제안

아래는 기술 검토 질문과 Design의 비교 후보다. 구현 경로·필터·폰트 선택을 DEV에 강제하거나 신규 DEV 실행/Git 권한을 부여하지 않는다. DEV는 기존 증거로 답할 수 있는 항목과 별도 승인된 실험이 필요한 항목을 구분해 주면 된다.

| ID | 확인 요청·비교 후보 | 필요한 회신·증거 | 차단 시점 |
| --- | --- | --- | --- |
| F08-01 | 대상 PC/OS·DPI·지원 창 범위 후보, 리플로/스크롤 대안, 시스템 한글 폰트 vs 배포 가능한 폰트와 대체 경로 | 실제 측정 환경·Godot 버전/renderer·창/표시배율·글꼴명/파일 출처·배포 검토 주체, 긴 한국어/큰 금액/누락 글리프의 재현 화면·한계 | 정밀 치수·글꼴·최소창 확정 전 |
| F08-02 | 픽셀 배경과 가독성 우선 텍스트를 분리하는 대안, 정수/비정수 배율의 선·텍스트 필터 비교 | 후보별 설정·원본 크기·배율·캡처와 계단/번짐/위상 차이, 변경 영향. 설정만 제시한 경우 실행 미검증 표시 | 최종 아트 원본·필터·표시 방식 확정 전 |
| F08-03 | 실제 12역/6·8역, 중복·단절·잠금·포커스, 지도 폭 축소와 긴 라벨에서 가림·대상 일치 | 같은 안정 ID의 지도/목록 실제 클릭·키보드 경로, 겹침·포커스·정보 열람/후보 추가·경계 편집 판정, 실패 조건과 대안 | 최종 지도 조작·마커 규격·제품 인수 전 |
| F08-04 | Theme/Control·패널 분리와 텍스처 인계/필터·재사용 대안, 측정 장면·부하 범위 | 권장 인계 형식·기존 구조 영향·측정 PC/renderer/창/장면·객체 수/입력 패턴·측정 방법·원시 기록. FPS/동시 표현 상한은 후보와 미측정 상태 구분 | 실제 적용·재사용 설계·성능 인수 전 |

숫자가 필요하면 후보값과 선택 근거·미검증을 함께 제시한다. 1280×720·40px 또는 현재 캡처1200px를 승인 제품 규격으로 채택하지 않는다. UI 크기·필터·목표 FPS를 RFC에서 임의 확정하지 않는다. 폰트 라이선스·renderer 호환성은 해당 실제 파일/버전/환경을 특정한 후 담당 부서가 검토한다.

## 회신 형식과 반영 규칙

각 F08-ID별로 다음을 기록한다.

| 필드 | 작성 내용 |
| --- | --- |
| 상태 | 미검토 / 문서 의견 / 실험 필요 / 실측 완료 / 대안 권고. 미회신을 동의로 처리하지 않음 |
| 기준 | 코드 full SHA·Godot 버전·환경·설정·사용한 상태/입력 |
| 대안 | 후보·장단점·위험·권고 이유·적용 범위 |
| 증거 | 명령·기대/실제·종료 결과·스크린샷/로그 경로. 정적 의견과 실행 분리 |
| 남은 일 | 미실행·실패·필요 승인/다른 담당·차단 시점 |

Design은 [후속 준비 기록의 검증표](DSG-008_F08_REVIEW_PREPARATION.md#4-회신-후-검증과-확정-게이트)에 따라 정보 보존과 상태별 소비를 대조한다. DEV 기술 의견 수신→Design 대안 반영→HQ 통합→Owner 규격/배치 결정 순으로 진행한다. 기술 회신 일부만으로 F-08 전체를 CLOSED 처리하지 않는다. Windows export·대상 PC 최종 FPS 합격은 별도 W09 인수다.

## 영향도

- 일정: 회신·실험 범위 확인 전 기간을 추정하지 않는다. 규격 종속 상세 설계만 대기하며 독립 IA·상태 보완은 계속 가능하다.
- 기획: 승인 게임 규칙·경제·시간·관할·세이브 변경 제안 없음.
- 디자인: 회신에 따라 DSG-008 상세 배치·토큰 적용과 DSG-009 인계 범위의 수정 가능성. 의미 역할과 장식·배치를 분리한다.
- 개발: 이 문서는 실험·구현 실행 승인서가 아니다. 소스·씬·테마·설정 변경이 필요하면 DEV 담당 티켓/승인 범위에서 진행한다.
- 테스트·세이브 호환: 표시 대안만으로 세이브 변경을 요구하지 않는다. 실제 영향 발견 시 해당 범위만 RFC 보완한다.
- 부서 경계: Track A AGT-DSG-0002의 UI 수용·실GUI 검수와 Track B 기술 자문/시안 검토를 구분한다.
