## 4. 잠정 배치 비교

| 구분 | A: 지도 중심·우측 작업 | B: 작업대·하단 작업 |
| --- | --- | --- |
| 구성 | HUD/입찰 진입→재무 띠→지도+우측 편집→예측+과거보고→피드백 | HUD/입찰 진입→넓은 지도→하단 편집/예측/재무→과거보고→피드백 |
| 장점 | 계획과 편집을 나란히 읽고 현재 자금을 상단에서 먼저 확인 | 지도 폭 확보, 후보·계획 목록과 긴 상태 설명을 하단으로 확장 |
| 위험 | 상세 패널이 좁으면 후보 목록·긴 사유·큰 금액의 높이가 늘어남 | 화면 높이·스크롤·지도와 편집 사이 시선 이동 증가, 재무가 아래로 내려감 |
| 좁은 폭 | 지도→편집, 예측→보고 순으로 쌓고 재무 계열을 행으로 전환 | 하단 업무 구획을 같은 순서로 쌓음. 필수 요소를 숨기지 않음 |
| 가설적 적합성 | 현재 S01 노선 편집과 경영 수치 확인의 기본안 후보 | 지도 우선 검토·넓은 지도 또는 하단 작업 선호의 비교 대안 |

**현재 Design 잠정 우선안은 A**다. 지도·편집과 현재 재무를 동시에 확인하기 쉽다는 정보 구조상의 판단이며 사용자 조사·Godot 검증·Owner 최종 선택이 아니다. B는 같은 상태·정보량을 유지한 대안으로 보존한다. 두 배치는 동일 DOM 요소를 이동하고 데이터·이벤트·정보 선택을 유지한다. DOM 순서는 실제 시각 순서에 맞춰 변경하며 이동 중 활성 조작의 포커스를 복원한다.

MVP 이후 UI 재배치·콘셉트 변경 가능성을 유지한다. 현재 토큰·모형 배경과 정보 영역을 분리하고, 배치 변경이 게임 의미·필드·허용 행동을 바꾸지 않도록 한다. 완성 화면·영구 배치로 확정하지 않는다.

## 5. 목업의 동작 수준과 정적 자료

HTML은 DSG-007 v0.1 토큰의 내부 사본을 포함하며 외부 의존성 없이 열린다. 15개 고정 상태 예시를 A/B에서 같은 데이터로 표시한다. 숫자·판정·편집 허용값은 예시에 미리 지정되어 있고 UI가 경제·유효성을 계산하지 않는다. 데이터·소속과 공급 의미는 상태표에 연결한다.

- 이미 포함된 역 클릭·목록 행 선택은 정보 열람을 바꾸며 계획 순서는 유지한다.
- 미포함 후보 클릭은 실제 제품의 `select` 의도, 위/아래/제거·되돌리기·예측·시간·입찰 버튼은 해당 명령 의도만 목업 바깥 검토 영역에 기록한다. 게임 전송·처리 대기·성공·계획 변경을 가장하지 않는다.
- 잠금 예시는 실제 현행과 같이 미포함 후보 추가를 막고 기존 포함역 정보 선택을 유지한다. 모든 후보에 대한 새로운 잠금 후 정보 열람 기능을 확정하지 않는다.
- 상태 예시 선택은 실제 사건 진행이 아니며 독립된 시점으로 전환한다. 제한금·예약금·보고 예시를 한 실행의 연속 사건으로 합치지 않는다.
- 유효0 예측은 DEV의 수요0 검증용 사례와 공급 형태를 정적으로 참고한 기대 표시다. 운행비까지0이라고 가정하지 않으며 코드 실행 결과는 아니다.
- 입찰 진입·복귀는 상태 매핑·의도만 기록한다. P01 실제 화면 전환이나 복귀 시점·최신값 갱신은 NOT_RUN이다.

기본 PNG는 A/P-A의 S03 정보 선택, 경고 PNG는 B/단절 사례다. 목업을 통해 나머지 장면과 두 배치를 검토할 수 있다. PNG·검증 폭·44px 가설은 제품 최소 지원 규격이 아니다.
