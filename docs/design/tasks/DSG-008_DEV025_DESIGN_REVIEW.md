## 1. 검토 범위와 이력

Owner는 DEV-025 결과에 따른 F-08 디자인 검토와 선택안 정리를 로컬로 요청했다. 새 실험·제품 적용·최종 규격 확정·Commit/Push/PR·외부 게시를 수행하지 않는다. 기존 문서/원본/승인/실패 이력은 수정하지 않고 이 후속을 추가한다.

[PR143](https://github.com/wisberry2022/MetroManager/pull/143)의 실험 공급은 완료됐으며 [#97 기술 종료](https://github.com/wisberry2022/MetroManager/issues/97#issuecomment-7052796254)를 유지한다. 원 [보고](../../engineering/evidence/DEV-025_F08_REPORT.md)와 JSON의 당시 미실행/승인 대기·DEV026 HOLD는 당시 기록이다. DEV-025 실험 base는 `d673435ce51f8f10604a93a54aa9ba3060d84ebf`, 제출 head는 `8bd236957f5adcf50aeb418cbaa617779eb8241a`, merge는 `dc3c049134fb45764560e47116b3332bc2f5624d`다. 원실행 바이트와 제출 LF 정규화는 [실행 JSON](../../engineering/evidence/DEV-025_F08_VALIDATION.json)의 source_identity를 따른다. 최신 main의 동일 실험 재실행으로 소급하지 않는다. 특히 DEV026이 바꾼 전환기와 구 실험 원본을 혼합해 새 실행이라고 하지 않는다.

## 4. F-08별 검토 결론

### F08-01 / T01 — 폰트·창·배율

기본은 세 font family 혼합, 시스템 후보는 단일 Malgun Gothic family로 관측됐다. 설치된 시스템 글꼴 표시 성공은 복사·재배포 권한 확인이 아니다. 기본의 굵은 숫자/라틴·한글 혼합과 시스템 후보의 균일한 획은 서로 다른 줄바꿈·정보 밀도를 만든다. 어느 후보도 전 지원 환경 수용 아님.

**권고:** 현행 표시를 임시 유지하고, 배포 시 필요한 한글 폰트의 권리/기본·fallback 구성을 별도 확인한다. OS 시스템 폰트를 무조건 번들하는 안은 선택지로 권고하지 않는다. 시험 클라이언트1280×720·1600×900·1920×1080, root변환1/1.25/1.5/2는 실험 조건이다. 최소창/지원 배율로 확정하지 않는다. 1280×720·1배를 다음 검토의 재현 기준으로만 쓸 수 있다. 논리640×360을 지원 해상도로 선언하지 않는다.

### F08-02 / T02 — 픽셀·동적 텍스트

1배 nearest/linear 모두6색·원본일치.2배 nearest는6색/차이0, linear는49색·정수반복 대비14308픽셀 차이.1.25배 linear는74색·원본 밖6156픽셀,1.5배는56색·8909픽셀이다. 이는 보간 특성으로 제품 버그 수치가 아니다.

**PREFERENCE:** 픽셀 도형은 정수·nearest를 비교 기준으로, 한국어/숫자는 동적 Control/Label로 분리한다. 비정수 확대·선형은 Owner가 유연 배율과 픽셀 선명도 사이의 방향을 선택한 뒤 적용 조건을 확인한다. 디오라마의 모든 그림을 저해상도 픽셀로 강제하지 않는다.

### F08-03 / T03 — 배치·지도·긴 문자열·입력

A는 넓은 창에서 지도와 목록/행동의 병렬 비교에 유리하다는 Design 선호다. 작은 논리폭은 A도 세로화/스크롤이 필요하다. B는 정보·권위 동등성이 있지만 전환 직후 포커스 가시성이 부족하다. 겹침 fixture에서 후보S12→전체 이름, 목록키→S08 정보 접근은 가능했다. 겹친 마커 모두의 직접 도달·읽기 순서 최종 검증은 아니다.

**권고:** A 잠정 우선/B 비교 유지. 최소 보완 M-01은 현재 유효 포커스를 전환 직후 화면에 보이게 하되 사용자 이동·선택/명령을 만들지 않는 것. M-02는 겹침 시 안정ID/순서·전체이름·정보/편집을 구분하는 후보/목록 대체 접근을 유지하는 것이다. 클러스터/팬/자동배치/지도좌표 변경은 이번에 도입하지 않는다.

### F08-04 / T04 — 재사용·인계·계측

Theme/텍스처·문자·지도·입력→Session의 역할 분리가 실험상 가능하고 A/B 정보 보존도 확인됐다. 제품 통합용 구조/컴포넌트 전면 수용과는 다르다.

22조건/2639프레임의 p95는 약16.925~17.229ms, 전체 최대32.980ms가 포함된다. 워밍업1초·관측2초·고정 순서·전체 프로세스 메모리·숨은 패널 동시 존재·Debug/VSync의 한계로 A/B 승자나 FPS 합격선을 결정하지 않는다. **권고:** 역할 분리 원칙과 원시 측정 보존을 다음 인계 기준으로 검토하고, 최종 목표/표현 상한은 실제 목표환경·제품 적용 범위가 정해질 때 결정한다. 새 벤치마크 시스템을 먼저 만들 필요는 없다.
