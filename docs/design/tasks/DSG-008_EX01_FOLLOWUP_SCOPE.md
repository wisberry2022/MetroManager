## 1. 이번 반영과 후속 단계

이번에는 아래 영향표·의존표와 미해결 상태만 새 문서에 반영했다. 기존 가이드/예외 설계/JSON/HTML·원래 승인/검증 기록은 그대로다. 따라서 아래의 문구/표본 변경은 **후속 반영 제안**이며 기존 카탈로그나 제품에 이미 적용됐다고 보지 않는다.

1. 로컬 검수: 회신 사실·조건부 표본/현행 구현 경계·후속 범위 대조 (이번3개 문서).
2. 후속 Design 문서/표본 반영: 검토 의견에 따라 영향 행만 보완. 원본을 개정한다면 원래 기준·변경 이력과 과거 검증을 보존하고 변경된 JSON/HTML은 새 검증 필요. 별도 시안/배치 개편·F-08 규격 확정은 포함하지 않는다.
3. DEV 실행 준비: 정확한 변경 파일·공급/소비 책임·행동군·자동/실제 GUI 증거·승인 범위를 별도 티켓으로 제안. 후보 stage1_session/view/map 및 W07 관련 테스트/증거는 DEV 권고이며 승인 경로 목록이 아니다.
4. 승인된 적용·검증 후 Design 대조→필요한 HQ 조정→Owner 결정. 부분 답변·정적 문서 승인만으로 제품 규격/전체 DSG-008 인수하지 않는다.

## 5. 후속 검증 제안 — 실행하지 않은 인수 항목

DEV의 별도 승인된 패킷에서 누락/잘못된 타입·버전, 유효한 독립 패널 유지, 누락 행동군만 제한, 새 Session 판 재사용/이전 응답 배제/자식 초기화, 보고 없음/실패/유효0/식별 불일치, 동기 예측 대기 미노출을 자동 회귀로 확인할 필요가 있다. 정확한 입력 스키마/기대값·파일/명령은 DEV가 계약과 함께 제안한다.

적용 후 GUI에서는 실제 복구 시 선택/포커스·독립 조작·읽기 순서와 원인/다음 행동을 확인한다. 정적 표본의 선택 전환이나 기존 489브라우저 검사로 대체하지 않는다. 글꼴/치수·배율/필터·성능 합격선은 F-08 후속과 Owner 판단 전 미확정이다.

게임 자동 테스트·Godot 로드·실제 GUI/플레이·부분 입력/새 실행 실험·Windows 빌드·성능/폰트·접근성 인수는 이번 모두 NOT_RUN이다. 기술 협의 OPEN/적용 승인 대기와 테스트 미실행을 구분한다. 신규 게임 규칙/세이브 명세 변경 필요는 현재 NONE이며 필요한 기술 계약 보완 범위는 DEV와 후속 확정한다.
