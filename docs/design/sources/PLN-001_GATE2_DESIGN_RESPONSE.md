## 2. 질문별 세부 의견

### DSG-R01 — 단일 지도 및 시·구·동 위계

- **화면 목적:** 현재 회사의 소속 시, 구·동의 상위 관계, 역 후보·사업 위치를 오인 없이 파악한다.
- **레이아웃 제안:** 영속 지도(중앙) + 좌측 `도시/구역` 패널 + 우측 선택 지역 상세 + 상단 회사/시간 정보. 지도 위에는 현재 선택한 행정 깊이의 경계만 강하게 표시한다. 위치 맥락에 따라 시 경계는 항상 우선 식별하고, 구·동 경계는 확대 단계/필터에서 강화한다.
- **필수 상태:** 미선택 / 시 선택 / 구 선택 / 동 선택 / 후보역 선택 / 노선 확인 / 관할 필터 적용. `도→시→구→동` 및 `광역시·특별시→구→동`은 **같은 임의의 4단계 트리로 오해되지 않도록** 소속 경로에 별도 표시한다.
- **위험/근거:** `PLN-001-C.md` §2-1과 AC-01~02가 행정 위계·관할·입찰 필터를 요구한다. 행정 경계·수요색·역마커·노선색을 동등한 강도로 중첩하면 선택 대상이 모호하다.
- **조건/대안:** 행정 표시 선택(`관할`/`수요`/`사업`)으로 강조할 레이어를 한 번에 하나씩 바꾼다. 현재 시를 헤더 및 브레드크럼에 텍스트로 반복 표기한다. 소속 시 바깥 공고는 기획 요구대로 **목록에 보이지 않아야 하므로** UI에서 비활성 공고로 노출하지 않는다. `소속 시 공고만 표시`라는 필터 설명은 가능하다.
- **필요 에셋:** 지도 타일 아틀라스, 3단계 테두리/패턴 규칙(개별 PNG로 제작하지 않는 UI 표현), 역 마커, 노선 선분, 범례 아이콘.
- **판정:** CONDITIONAL / HIGH — 토글·계층 표시를 전제로 가능. 지도 실제 클릭 성공률은 미측정.

### DSG-R02 — 동별 수요와 노선안의 차이

- **화면 목적:** 수요가 높은 동과 낮은 동을 비교하고 노선 선택이 예상 수요·사업성에 어떤 변화를 주는지 파악한다.
- **레이아웃 제안:** 중앙 지도에 동별 수요 레이어, 우측에 `현재 선택한 노선안` 패널, 하단에 노선안 A/B 비교 카드. `예상` 레이블을 실제 성과보다 시각적으로 명확히 구분한다.
- **최소 표현:** 3~5단계 수요 등급을 *숫자·명도·패턴*으로 중복 부호화, 항상 범례 제공. 두 노선안 비교 시 예상 이용/사업비/소요기간을 한 표에 나란히 표시하며 계산식에 없는 인과설명은 꾸며내지 않는다.
- **위험/근거:** §2-2, AC-04는 위치·순서 변경에 따른 설명 가능한 비교를 요구한다. 색상 한 가지로만 표현하면 색각 다양성이나 모니터 명도 차이에 취약하다.
- **조건/대안:** 개발팀에서 제공 가능한 비교 결과 값과 확정/예상 구분이 필요. 예측 불확실성 범위가 없는 경우 `확정된 수요`인 듯한 UI(정밀 히트맵)는 피하고 `예상 수요 지표`로 표시한다.
- **필요 에셋:** 범례 1세트, 오버레이 패턴 최대 5종, 비교 화살표·아이콘 3~5종(공용 재사용).
- **판정:** CONDITIONAL / HIGH — 비교 대상 데이터가 공급되어야 한다.

### DSG-R03 — 공공입찰과 회사 주도 제안

- **화면 목적:** 플레이어가 두 사업 경로의 **결정권 범위와 심사 절차**를 혼동하지 않는다.
- **레이아웃 제안:** `새 사업 시작` 진입에서 **공공입찰** / **자체 제안**을 독립된 카드로 선택. 같은 지도 셸을 재사용하되 오른쪽의 작업 패널과 진행 단계는 분리한다.
- **공공입찰 흐름:** 내 시의 공고 목록 → 사업구간·발주처·**고정** 운임/사업비·공기/자격 확인 → 응찰 → 경쟁/낙찰 근거 표시 → 계약·시공. `정부 사전 승인 사업` 배지와 `낙찰 후 재심사 없음` 안내를 유지한다. 고정 필드는 입력창처럼 보이지 않도록 처리한다.
- **자체 제안 흐름:** 동별 수요 조사 → 후보역·순서 설정 → 예상치 확인 → 시청 심사 → 국토교통부 심사(적합/보류/부적합) → 결과·사유 확인 → 사업비/시공. `쉬움 시철 시청 자동 통과(수익 0 포함)`를 UI가 임의의 실질적 경쟁 심사인 것처럼 연출하지 않는다.
- **실패/보류:** 결과 화면은 결과명·판정 기관·근거·허용된 다음 행동을 명시. 정부 보류의 1회 설득 기회와 감액 사업비는 수치·상태 명세가 제공된 범위에서만 표시한다. 부적합/실패 후 **항상 재신청 가능** 버튼을 임의로 추가하지 않는다.
- **위험/근거:** §2-2~2-3, AC-02~05, VP-01/02. 경로 간 동작 차이가 게임의 H-02 검증 핵심이다.
- **필요 에셋:** 사업 경로 카드 2개, 공통 결과 다이얼로그 1개, 기관·단계 배지 4~6종.
- **판정:** CONDITIONAL / HIGH — 판정 이유·허용된 후속 동작을 Planning이 정의할 필요.

### DSG-R04 — 역 후보 4~6개 / 2~4역 선택·순서 지정

- **화면 목적:** 후보역의 위치를 보고 소수의 클릭으로 유효한 노선안을 만들고, 잘못된 순서·역 선택을 수정한다.
- **레이아웃 제안:** 지도 위 후보역 마커, 선택 시 우측 `노선 순서` 목록에 순서번호를 자동 부여. 목록의 `위/아래 이동`, `제거`, `모두 취소`를 제공하고 지도에 연결선 프리뷰를 즉시 반영한다.
- **권장 동작:** 1회 클릭 선택, 선택된 마커 재클릭/패널 버튼 해제, `제출 전 확인`에서 역 순서·예상치 요약. 최소 40×40px(화면 표시 기준)의 클릭 타깃 또는 그와 동일한 클릭 영역을 확보한다.
- **필수 상태:** 미선택/호버/선택/목록 순서 변경/제출 불가(2개 미만 등)/제출 가능. 최대 역 개수와 중복 선택 처리는 **Planning의 상세 규칙을 따름**.
- **위험/근거:** §5-1의 4~6개·2~4개는 미확정 제안 수치이므로 마커 UI가 후보 수 증가에 취약할 수 있다. 밀집 시 확대·우측 목록을 제공한다.
- **대안:** 드래그 재정렬은 보조 수단으로만 채택; 확실한 버튼 기반 정렬을 우선한다. `지도를 자유롭게 선 그리기` 기능은 이번 검토의 전제가 아니다.
- **필요 에셋:** 후보/선택/비활성 역 마커 3상태, 번호 배지, 선분·조작 아이콘.
- **판정:** CONDITIONAL / MEDIUM — 준비된 역 후보 기준 가능; 후보 숫자 변동 시 재평가.

### DSG-R05 — 시공·시험운행·안전검증·개통

- **화면 목적:** `공사 100%`가 곧 `영업 가능`을 의미하지 않는다는 것을 이해하고, 개통 전에 부족한 절차가 무엇인지 알 수 있다.
- **레이아웃 제안:** 동일한 노선 상세 패널에 ① 계약/시공 ② 시범운행 ③ 안전검증 ④ 개통/운영의 단계 인디케이터와 상태별 액션을 표시한다.
- **필수 상태:** 사업 확보 전/계약 가능/시공 중(진행률·비용·잔여 기간)/공사 완료·검증 대기/시범운행 미완료·진행·완료/안전검증 미완료·진행·통과·실패/개통 가능/운영 중. 세부 상태전이의 **정확한 정의는 Planning/Development와 조율 필요**.
- **시간 표현:** 일시정지 중 공정바가 움직이는 애니메이션으로 진행을 암시하지 않는다. 공정률·시간 경과·일일 보고의 맥락은 F-TIME-001을 따르며, 시간 속도와 기간값은 미확정이다.
- **차단 피드백:** 개통 버튼 비활성 시 `안전검증 미통과`, `시범운행 미완료` 등 실제 충족되지 않은 요건을 텍스트로 기재한다. 시험 실패 후 재시험 가능 여부는 임의 결정 금지.
- **필요 에셋:** 공사·시험·안전·개통 단계 아이콘 4종, 진행바, 성공·실패·대기 상태(공용 배지), 선택적 공사 오버레이 1종.
- **판정:** CONDITIONAL / HIGH — 절차를 분리하는 UX는 가능, 실패 시 회복 경로 규칙 필요.

### DSG-R06 — 승객 이용과 경영 성취 피드백

- **화면 목적:** 개통 이후 도시에 실제 변화가 발생했음을 즉시 보여주되, 데이터 분석과 경량 연출을 함께 제공한다.
- **최소안(권고):** 개통 노선 위 **열차 1종(간단한 이동/정차 상태)**, 역에서 **소수의 승객 픽셀 애니메이션(반복·재사용)**, 노선 패널의 `운영 중/비운영` 및 실제 이용량·만족도 변화. 이 연출은 집계 데이터에 기반한 시각적 피드백이지 실제 개별 시민 모델을 뜻하지 않는다.
- **구별 원칙:** 영업시간 외에는 동일한 운행 연출을 계속 보여주지 않는다. 낮은 이용과 높은 이용의 차이는 *표시 인원·빈도·정보 수치* 중 구현 가능한 두 가지 이상으로 식별한다. 이용 수치를 렌더링된 캐릭터 수와 1:1 대응시키지 않는다.
- **스프라이트 최소안:** 열차 원본 스프라이트 1세트(기본/정차 또는 2~4프레임), 시민 2실루엣×이동 4프레임, 역 1종. **원본 픽셀 규격은 §4의 시안 기준이며 기술 승인 전**.
- **성능/제작 위험:** 도시 전역 개별 승객 AI·경로탐색·대량 오브젝트 생성은 요구하지 않는다. 화면상 가시 연출 개수·업데이트 빈도는 Development 측정과 연동하여 결정한다.
- **축소 대안:** 성능이 곤란하다면 `열차 이동 + 정차 효과 + 승하차 아이콘 + 수치`의 조합으로 유지하고 시민 걷기 프레임을 축소. **열차/승하차의 식별 가능한 변화까지 없애고 집계 숫자만 남기는 안은 H-01 성취감 검증 관점에서 비권장**.
- **판정:** CONDITIONAL / HIGH — G2-Q08에 관해 상기 최소안을 권고하며 기술 검증 필요.

### DSG-R07 — 일별 정산·손익·현금

- **화면 목적:** 금전 항목의 경제적 의미를 혼동하지 않고 `첫 사업이 회사에 무엇을 남겼는가`를 파악해 다음 행동으로 이동한다.
- **레이아웃 제안:** `일일 운영 보고`를 날짜 헤더+핵심 요약 카드+상세 거래 표로 구성. 핵심 영역은 **정부 사업비 수입 / 공사비 지출 / 운임 수익 / 영업·기타 비용 / 순손익 / 보유 현금**을 분리 표시(해당 지표가 정의된 시점에 한함). 회사·노선 필터가 필요한지는 대상 데이터 확정 후 검토.
- **언어 제안:** `정부 사업비(회사 매출·현금 유입)`과 `운임 수익`, `공사비`, `순이익`, `현재 현금`을 서로 다른 항목으로 표현. 지급/인식 시점이 미확정인 경우 회계적으로 확정되지 않은 세부 표제는 잠정으로 유지한다. `매출=현금=순이익`처럼 보이는 단일 합산 카드 사용 금지.
- **피드백:** 날짜 변경 시 `일일 보고 생성됨` 알림과 읽기 접근점을 제공하고, 다음 사업 후보 화면으로 이동할 수 있는 버튼을 하단에 배치한다. 급격한 증감·큰 값은 단위(원/천원 등)를 통일하며 색뿐 아니라 `+/-`, 텍스트로 제공한다.
- **위험/근거:** §2-5, §2-6, AC-08~10. 사업비의 수익 인식·잔액 처리 시점(`G2-Q06`)이 미정이므로 수치가 있는 고충실도 대시보드는 최종 설계할 수 없다.
- **대안:** 1차 프로토타입은 날짜 선택·6개 자리표시자·상세표 구조만 정의하고 실제 항목 라벨/수치는 Planning의 재무 명세 확정 후 연결한다.
- **판정:** CONDITIONAL / HIGH — 정보 구조 가능, 구체 항목은 G2-Q06 선행 결정 필수.

### DSG-R08 — 화면·에셋 제작 규모 및 프로토타입 우선순위

- **화면 원칙:** 서로 다른 8개 게임 장면을 제작하기보다 `공통 지도 게임 셸 1`에서 **기능 패널 7종과 공용 대화상자 3종**을 재사용한다. 이 개수는 작업량 추정용 가정이며 최종 화면 수는 변경 가능.
- **필수 화면·패널(제안):** [S01] 도시 지도/행정/시간, [P01] 사업 경로 선택, [P02] 공공입찰 목록·상세, [P03] 회사 제안·노선 편집·수요 비교, [P04] 심사 단계·판정 내용, [P05] 시공·시험운행·안전검증·개통, [P06] 영업·시민 평가, [P07] 일일 재무·다음 사업. [D01] 결과·근거, [D02] 제출 전 확인, [D03] 경고·차단 사유는 공용 대화상자로 재사용.
- **제작 병목:** `지도/행정/수요/노선 오버레이 복합성`, `한글 픽셀 폰트 가독성`, `열차·시민 움직임`, `경로별 상태 문구`가 리스크. 지도·건물 그래픽을 대량으로 확장하지 말고 의사결정을 보조하는 최소 도시 풍경으로 시작한다.
- **제작량 견적(한 명의 디자이너 기준, 미실측):** 소스 PNG/아틀라스 등 **약 24~36개**, UI/와이어프레임/스프라이트/검수 합계 **약 15~25 디자이너 작업일**의 초기 범위 추정(1일=8시간, 컨셉 재작업·엔진 통합·후속 변경 제외). 이는 **계약 일정 또는 확정 공수 아님**, HQ가 개발 의존성과 함께 재산정해야 한다.
- **프로토타입 순서:** ① P0 와이어프레임으로 VP-01/02 동선 및 문구 검토 → ② P1 지도 셸·범례·노선 에디터·사업 분기 → ③ P2 시공/검증/재무 패널 → ④ P3 최소 픽셀 에셋·승객/열차 연출 → ⑤ P4 사용자 테스트·시각 QA.
- **판정:** CONDITIONAL / HIGH — 반복 사용을 전제로 제작 가능, 주어진 일정/인력 및 개발 제약 확인 필요.

## 3. MVP 화면 구조 및 E2E UX 검증

### 3-1. 공통 화면 구성안

**화면 목적:** 게임 진행 중 현재 상황/시간/자금·지도와 선택한 작업을 한 화면에서 지속적으로 파악하게 한다.

```text
┌────────────────────────────────────────────┐
│ 상단 HUD: 회사/소속 시 | 게임 날짜·시각 | 일시정지 | 현금 │
├──────────┬───────────────────────┬─────────────┤
│ 좌측 패널 │                       │ 우측 패널    │
│ 지도 계층 │    도시/노선 지도      │ 선택 지역·  │
│ 필터·범례 │    역/노선/열차         │ 사업/노선 상세│
│ 사업 진입 │                       │ 행동 버튼    │
├──────────┴───────────────────────┴─────────────┤
│ 하단: 상황·알림·단계·새 보고서·다음 행동                    │
└────────────────────────────────────────────┘
```

**설계 기준 시안값(TBD):** 1280×720 px의 참조 캔버스, 상단 56px, 좌측 224px, 우측 312px, 패널 사이 16px 여백, 하단 정보바 80px. 마우스 입력 영역 최소 40×40px(화면 크기 기준). 한국어 본문 글꼴은 화면 기준 **16px 이상부터 검토**하며 눈금·보조 라벨도 접근성 평가 후 조정한다. 이는 *UI/아트 설계 수치*이지 엔진 해상도·스케일링 구현 확정값이 아니다.

### 3-2. VP-01 — 회사 자체 제안

`[현재 시·동 확인] → [동 수요 비교] → [역 선택/순서] → [예상 수요·사업비·기간 확인] → [시청 심사 결과] → [정부 적합/보류/부적합 및 이유] → [사업비/시공] → [시범운행] → [안전검증] → [개통] → [열차·승하차/운영 수치] → [일일 보고] → [다음 사업]`

**사용성 확인 질문:** 비설명 사용자가 `왜 이 역을 선택했는가`, `어느 기관이 무엇을 판단했는가`, `왜 아직 개통할 수 없는가`를 답할 수 있는가? 정부 보류·설득 분기는 기획팀 결정 범위 밖으로 확장하지 않는다.

### 3-3. VP-02 — 공공입찰

`[내 시 공고만 보기] → [발주처·고정 운임/사업비/공기 확인] → [응찰] → [낙찰/실패 이유] → [계약/시공] → [시범운행] → [안전검증] → [개통] → [운영·일일 보고]`

**사용성 확인 질문:** 입찰에서 노선안을 자유 편집하거나 정부 재심사하도록 오해하지 않는가? `국토교통부 발주라도 소속 시 사업이면 노출` 규칙을 UI가 충족하는가?

### 3-4. 가독성·접근성

- 행정 계층의 의미는 색상 외에 **브레드크럼·선 굵기·레이블**로 전달한다.
- 수요 고저는 색상 외에 **숫자·패턴·범례**로 제공한다.
- 모든 핵심 결과(`승인/보류/부적합`, `낙찰/탈락`, `공사/검증`)는 **상태명 + 이유 + 다음 행동**의 3요소를 표시한다.
- 최소 버튼 클릭 영역 40×40px을 목표로 하고 겹치는 역 마커에는 확대·목록 대체 조작을 제공한다.
- 텍스트·배경 명도 대비 **WCAG 2.2 AA 일반 텍스트 4.5:1**을 목표로 시안 단계에서 검사한다. 실제 접근성 검사는 아직 **NOT_RUN**.
- 마우스 중심 입력을 유지하되 보조 `Esc`/뒤로 가기와 `확인/취소` 표시를 권고한다(키보드 대응 구현은 Development 협의).

- 사용 폰트는 한글 자모 결합/완성형 글립 가용성, 라이선스, UI 크기에서의 판독성을 확인해야 한다. 폰트의 최종 선정은 미완료.
- 디렉터리/파일명은 **디자인 시안용 예시**다. 프로젝트 Git 및 개발팀 에셋 경로 규칙과 충돌하면 HQ 조정 뒤 확정한다.
